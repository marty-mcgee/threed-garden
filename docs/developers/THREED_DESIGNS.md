The preceding local candidate diverged from the requirement: Design mode hid the Project Scene, rendered an independent DesignPreview Canvas and saved records through /api/threed/designs. Its optional Project association did not include those meshes in the Project Scene or Project Save. That flow is superseded.

Inspection found an existing JSONB project.config column and an owner-scoped Project snapshot transaction. ## Lifecycle, units and geometry

### Exact persistence mapping

The Dashboard does **not** hold a whole `project.config` object in client state. That notation names server storage. The editable client source is the active Project's entry in `architectureDrafts.current`, with `history.present`, a saved baseline and selection. Pointer previews are transient. Client edits and a success toast alone do not establish database persistence.

| Boundary | Exact implementation | Representation / responsibility |
| --- | --- | --- |
| Client edit / dirty state | `src/app/dashboard/scene/page.tsx`: `architectureDrafts`, `changeArchitecture`; `src/libraries/services/threed/design/project-architecture.ts`: `architectureIsDirty` | Project ID keys each draft; source changes differ from its acknowledged saved baseline. No browser-storage authority. |
| Backing schema | `src/libraries/schema/project/index.ts`: `project = pgTable('project', ...)`, `project.config = jsonb('config')` | PostgreSQL table **project**, column **config**, type **JSONB**. `threeDArchitecture` is a JSON key containing `{version:1, document}`, not a separate column. Other modules' `config` columns are unrelated. |
| Save dispatch | `src/app/dashboard/scene/page.tsx`: `handleSaveThreeDProject` | Existing Project Toolbar/menu Save captures the architecture/marker/view snapshot and PUTs `/api/project/threed-markers`. There is no additional Design Save button. |

Update `project.config` with `coalesce(config, '{}'::jsonb) || {threeDViewState, threeDArchitecture}` under Project/owner predicates, alongside marker writes. Keep architecture in the existing Project JSONB column. It is bounded editable Project content already covered by the snapshot transaction and owner lifecycle. Using the legacy table would introduce a second identity, save and concurrency boundary without solving this workspace requirement. No schema migration or SQL Editor activation is needed. This is confirmed source behavior and mocked-test evidence; live database state and authenticated save/reopen remain manual acceptance.

Selected walls expose center X/Z, length, height, thickness, level-relative base, first-edge rotation, mirrored geometry and endpoint coordinates. Floors expose center X/Z, world-axis width/depth, area, rotation, mirrors, thickness, top offset and vertices. A JSONB merge updates threeDArchitecture and threeDViewState within the existing transaction while retaining unrelated config. Older callers omitting architecture preserve existing architectural content.

Owner/provider readiness, duplicate-click locking and stale-Project replies are guarded. Save/edit actions wait for Project hydration. Save validates returned Project identity and acknowledged architecture; newer edits stay dirty. Failures retain source and show an error. Dirty status appears in Design and normal Scene, with navigation/unload guards. Per-Project history survives page-session mode/Project changes; Project Save or JSON export is needed before leaving/reloading. Reopening reads parameters and reconstructs matching geometry. Corrupt saved architecture blocks session loading rather than silently overwriting it. Existing Project snapshots retain their last-committed-write concurrency semantics; no independent design revision/conflict system is claimed.

The `Unsaved Project architecture` message in Dashboard `scene/page.tsx` means `architectureIsDirty(architectureDraft)` is true: current source JSON differs from the acknowledged baseline. It does not establish a database failure. The October 10 reload bug occurred before hydration: `projectArchitectureDraft()` serialized raw `newDesign()` defaults for the baseline, but `designHistory()` normalized them (for example, 96 inches was `2.4383999999999997` versus `2.4384` metres). The empty placeholder therefore appeared dirty and `loadData` refused to replace it with loaded source. The baseline now uses normalized `history.present`; `hydrateArchitectureDraft` replaces clean placeholders while preserving genuine unsaved edits. Project transitions immediately invalidate/abort old loads, and session parsing rejects mismatched response Project IDs. ## JSON portability

Export includes supported architectural source: name/defaults, levels, nodes, walls, floors, roofs and hosted openings. It excludes Project ownership, database identity, Models and general Scene settings. The portable threed-home-design identifier and versions 1-5 remain compatible.

Import validates/migrates the whole file before mutation. The user chooses **Merge architectural content** (default) or **Replace architectural content only** (explicitly confirmed with the dialog Import action). Both allocate fresh IDs and remap references; imported IDs cannot overwrite existing entities or determine access. Unknown ownership/record fields are rejected. Merge appends topology with unique level names, retaining imported coordinates. Replace changes architecture only and preserves unrelated Models/resources/settings. Import is undoable and remains dirty until Project Save.

Local October 14 legacy adapter: `design/design-import.ts` recognizes old Paper.js plan maps separately from native versions 1–5. Supported constant-height walls, floor polygons, independent roof slopes and levels convert centimetres to metres, retaining X/Z positions and same-level shared corners. `DesignImportDialog` shows converted counts and requires explicit acknowledgement of every reported omission before applying supported content. Catalog objects and their cutout masks, tapered walls, joined roof miters, annotations/guides and legacy appearance/history are not silently approximated. The native document and persistence validators remain strict. See [mapping, supplied-file results and verification](../plans/legacy-design-json-import.md).

The separate operator command `npm run threed:design:recover` prepares/verifies OBJ/MTL/texture bundles and placements offline. Its explicitly invoked `apply` creates a new private Project through the existing tables/config contracts and public Vercel Blob storage, with fresh architecture IDs and a durable recovery journal. It never updates an existing Project or Model primary. The session advisory lock requires a direct connection; a supplied `DATABASE_URL_UNPOOLED` must match the App endpoint, port, database and username. Default report mode retains catalog objects but leaves boolean apertures unresolved; optional native mode replaces only proven compatible openings with generic editable frames. This does not expand the ordinary Import JSON payload to include Models. The Developer-authorized October 14 run created Project #17; committed-data and remote-file hash verification passed. Authenticated App appearance and subsequent Save/reopen remain manual. See the same plan for commands, limits and exact evidence.

After native or legacy merge, the editor activates the first incoming level so its imported plan is immediately discoverable. OBJ/MTL catalog import is a separate future placement concern: registering Models does not automatically map legacy names, recreate hosted openings or restore plan instances. Original reference files remain unchanged; the architecture importer performs no asset upload or database operation.
