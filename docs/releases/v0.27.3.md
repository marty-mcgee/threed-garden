## Model thumbnail File attachments

Problem: Details displays threed_models.thumbnail_url, while Files lists threed_model_files. Earlier thumbnail uploads/exports selected a URL without registering a File, so Model #1165 could show its thumbnail while listing only geometry and a Top View image.

- Model creation and explicit thumbnail saves now register the image reference as an owned supportive-media File in the same transaction. Details uploads/exports retain Save Changes and Discard behavior. Files Export 2D Image saves immediately through the existing PATCH and refreshes the attachment list when the dialog closes.
- Existing saved thumbnails missing a matching File expose **Attach saved thumbnail** in Files. The POST endpoint reads the saved URL under an owner-scoped Model lock; it accepts no client-supplied URL and does not upload or fetch image bytes.
- Same-owner, same-Model, exact-URL attachments are reused without changing their type or relative path. Registration serializes on the Model row. Old attachments remain when the thumbnail selection changes or is cleared.
- No schema changes, bulk backfill, renderer changes or live persistence/storage validation. Existing HTTPS PNG/JPG/WebP references longer than the File column's 500-character capacity retain their ordinary thumbnail Save behavior; explicit attachment reports that limit instead of truncating the URL.
