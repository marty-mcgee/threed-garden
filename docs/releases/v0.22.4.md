# v0.22.4 — ThreeD Scenarios Preparations

**Production release candidate; deployment pending.** Package `threed-garden` is already version `0.22.4` from the User-confirmed preparation and documentation commits. This feature checkpoint connects the first persisted ThreeD Scenario definition to both Admin CRUD and a visible, read-only Project Scene card. The User confirmed both local presentations in browser screenshots. It also polishes the ThreeD Soccer sensor workflow.

## Changes

- Add the Project-scoped `threed_scenarios` table with owner, Project and ThreeD module references, a Project/module-scoped slug, description, active flag and timestamps. The new `/admin/threed/scenarios` workspace follows the ThreeD Admin blueprint with Project/module selection, server-side search, sorting and pagination, page-scoped bulk selection, and confirmed deletion. The Drizzle REST API checks owner scope and Project/ThreeD assignment. Scenario rows remain definitions: an active row appears in the owner-visible Scene card after the Project finishes loading, but does not control Scene loading, assign Models, create geometry or change Physics behavior.
- Add an idempotent, operator-run Scenario seed command for an active, owner-matched Project/ThreeD assignment. Project 15 now has **Physics Objects & Sensors — Test** (Scenario #1) in the configured Neon database, which the User confirmed is also used by Vercel Production. The script refuses a `NODE_ENV=production` process, but its `--confirm-development` flag does not establish database isolation; operators must verify the connection before rerunning it.
- Show active Project Scenario definitions in a dismissible, read-only Scene card using the owner-scoped API. The card gives a visible bridge from Admin to Scene without introducing object membership, Scene geometry, or a second Physics authority.
- Carry the saved Project marker ID as an optional Physics Event source field. Goal contacts and session entry counts distinguish the two Football 4k instances in ThreeD Soccer even though they share reusable Model 53. Legacy Model-key behavior remains for sources without a marker ID.
- Make the Imported sensors inspector show its Home and Away Goal members first, with group rename/delete controls collapsed below and a clear path to **Environment → Show Sensors**. The existing sensor counting UI remains session-local.
- Fix the reposition validation fixture so it supplies the interpolation context already used by the Scene callback. This is a fixture-only correction.

## Database handoff

The User confirmed that Vercel Production uses the same Neon `DATABASE_URL` as this checkout's `.env.local`. The configured database already has `threed_scenarios` and the Project 15 test record, verified by read-only queries and local browser/API use. There is no separate Scenario table migration to apply before this code deploy. The committed [Scenario-only SQL](sql/v0.22.4-threed-scenarios.sql) is an audit artifact, not an application instruction; running it now would try to create an existing table.

Drizzle remains the schema authority. The established workflow is `npm run db:generate` followed by a reviewed `npm run db:push` using strict confirmation. `db:push` reconciles the full declared schema; the current proposal includes previously approved Assembly tables and constraint/default normalization beyond the Scenario checkpoint. It was not accepted as part of this release and requires its own review. The Scenario seed record is real data in the shared database and must be preserved if the table is ever rolled back.
