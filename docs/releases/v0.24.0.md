## Included functionality

- Shared architectural editing in the active Project Scene: walls, floors, hosted doors/windows, named levels, Flat/Shed/Gable roofs and rectangular roof cutouts/skylights. Stable IDs and editable parameters drive linked 2D/3D geometry alongside existing Models, with Imperial inputs, selection and Undo/Redo.
- Aligned Assets/Properties left column and Scene/Plan right column, resizable rows, internal scrolling and X/Z rulers. Drawing and view tools overlay the Plan; Project-wide actions remain in the Project toolbar.
- Compact collapsible Properties sections with colored icons and accessible help tooltips. Navigation includes pointer-centered zoom, pan, Fit, Frame Selection, Reset and snapping.
- Staged JSON import with validation, explicit merge or architecture-only replacement, fresh IDs and Cancel. Export preserves portable editable architecture; unrelated Scene content is retained.
- Shared Project snapshots include architecture plus supported workspace preferences, cameras and active inspector references. Missing references are handled safely; captured-only acknowledgment retains edits made during Save.
- Model/asset DetailsCards reuse overlay header dragging, arrow-key movement and viewport clamping. One shared DetailsCard position per Project is saved with Project Save; Setup's Reset Default Overlay Positions restores the default placement. The external left gap is removed.
- Simulations overlay visibility now participates in Project Save/load. Close, Save and reload retains hidden state; Setup reopens it. Older Projects without the field retain the visible default. Closing still cancels active work without removing the runtime owner.
- View Mode icons are ordered **3D, Design, 2D, Combined**.
- Snapshot Save verifies returned workspace state inside the transaction as well as architecture. Missing or changed workspace rolls back the snapshot; JSONB object-key reordering does not cause a false failure.

## Storage and source boundaries

No new table or migration is required. Authoritative architecture remains in `project.config.threeDArchitecture`; workspace preferences are separate within `project.config.threeDViewState`, including `overlayPositions.details` and `threeD.showSimulations`.

The [Dashboard Scene page](../../src/app/dashboard/scene/page.tsx) captures the Project draft and live providers through `handleSaveThreeDProject`. The owner-scoped [snapshot API](../../src/app/api/project/threed-markers/route.ts) validates and transactionally saves markers/config while preserving unrelated settings. The [map API](../../src/app/api/map/threed/route.ts), existing session loader and [architecture hydration helpers](../../src/libraries/services/threed/design/project-architecture.ts) reconstruct the same Project. [View-state validation](../../src/libraries/services/threed/markers/project-view-state-core.ts) bounds saved preferences. No independent Design save mechanism is introduced.

Design preferences/sections mark the draft dirty. Camera, inspector, overlay-position and Simulations visibility changes use explicit Project Save and do not independently mark the architecture/workspace badge. Save after moving/resetting an overlay or changing its visibility.
