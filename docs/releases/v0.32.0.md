the responsive Project checkpoint. Package and both root lockfile versions are

## Accepted release scope

- Canvas-first narrow Project workspaces: Scene, Design plan, open Assets/library
  panel, then Properties, with focus/scroll shortcuts and retained desktop docking.
- Fluid container-relative panel sizing, usable short-height regions, shrinking
  long Project titles and measured toolbar offsets for default overlays.
- Coarse-pointer 44px toolbar/plan/menu targets and viewport-bounded Project/Add
  menus, preserving existing actions, guest guards and view order.
- Persistent Scene/editor owners, selected-wall drafts and read-only protection
  remain covered by focused/native fixtures and offline regression checks.

This release is the accepted Project-workspace responsiveness checkpoint.
The broader plan below does not establish certification of every App page or
device. Physical iOS/Android touch, keyboard, Character controls, WebGL and live
Save/reopen remain manual acceptance checks. Admin/public surface follow-ups
remain outside the implemented scope. Dependencies and schemas are unchanged;
no migration is required. The generated data explorer is refreshed for 0.32.0.

Make the existing App usable on phones and tablets while preserving desktop
layouts and behavior. ThreeD, Multimedia, Traffic and Learn remain peer Top
Modules. This work does not require a new schema, renderer, dependency or mobile
application framework. DXF work remains paused; JSCAD conversion is complete.

## Prioritized implementation sequence

### 1. Project panel access and available canvas space

- Measure the baseline at the viewport matrix below before changing layout.
- On narrow widths, make Assets/Properties explicitly openable and dismissible
  without reserving a permanent 288px canvas-side column. Reuse existing panel
  owners and state; decide drawer/sheet presentation from measured behavior.
- Keep a visible return-to-canvas action and accurate expanded/controls labels.
- Reflow around the same Scene/Canvas and Design editor instances. Breakpoint
  changes must retain selected IDs, drafts, history, camera and split preferences.
- Preserve desktop docking. Choose breakpoints from content measurements rather
  than treating every touch device as a phone.

Acceptance: at 320px and 375px portrait, closing a panel restores the canvas's
available width; opening it keeps its controls reachable. Switching views,
opening inspectors and rotating the viewport do not remount the persistent Scene
or lose unsaved edits. Existing selection and 2D/3D synchronization still work.

### 2. Toolbar, menus, overlays and touch targets

- Retain design, 3d, 2d, combined ordering and all owner/guest action gates.
- Measure toolbar wrapping and menu collisions; bound menus to the available
  viewport and keep Save/status accessible. Avoid hiding functionality merely
  to fit a phone.
- Extend the App's existing 44px coarse-pointer target approach where needed,
  including close controls and divider/resize hit regions. Keep compact visual
  treatment on fine-pointer desktop layouts.
- Use measured toolbar and viewport bounds for initial overlay position as well
  as dragged/restored positions. Account for safe areas and the on-screen
  keyboard without writing transient layout adjustments to saved Project state.

Acceptance: menu/overlay controls remain reachable in portrait/landscape and
after keyboard opening. Dragging a panel cannot move it out of reach. Closing
and reopening Multimedia retains selection/playback. Focus returns to triggers.

### 3. 2D/3D touch editing and Character controls

- Test Select, Pan, drawing tools, Model drag/resize, pinch zoom and cancellation;
  implement only missing input paths, retaining existing coordinate conversions.
- Keep canvas manipulation distinct from panel scrolling and browser gestures.
  Do not disable browser zoom globally or make essential actions hover-only.
- Review existing Character touch/controller affordances and verify Take/Release
  Control, Garden motion, Ecctrl input, idle/walk/run and supported targeted
  Actions. Do not introduce a replacement physics/input owner.

Acceptance: touch edits select the intended object, reflect Properties, preserve
locks/Environment protection and save through the existing marker path. A
cancelled touch never leaves a stuck drag or accidental edit. Keyboard/mouse
editing and existing Character/Simulation regressions remain release-blocking.

### 4. Admin workspaces and forms

- Audit shared headers/tables/forms first, then Models, Assembly Groups, Projects,
  Learn, Settings and Multimedia editors. Include remaining ThreeD/Traffic lists.
- Keep table overflow local and intentional; retain identity/actions and filters.
  Avoid page-wide horizontal scrolling or a blanket table-to-card rewrite.
- Keep Save/Discard/import controls reachable when fields focus and the keyboard
  opens. Preserve drafts, busy guards, errors and revision/ownership behavior.

Acceptance: users can find a record, edit/save/discard it and recover validation
errors without clipped controls. Mobile navigation opens/closes predictably.
The JSON import retains visible progress/actions without resizing per part.

### 5. Public surfaces, Learn and Multimedia

- Verify Home calls to action, Learn topics/library/reader, Markdown tables,
  illustrations/captures, Dashboard Multimedia and public Project browsing.
- Preserve real-screen capture provenance and saved guide content authority.
- Retain public read access and owner-only writes; local viewing controls must
  not acquire edit permissions as a side effect of mobile presentation.

Acceptance: links, content and playback controls fit and remain accessible in
both themes, including long labels, empty/loading/error states and text zoom.

## November 9 follow-up: fluid workspace sizing

The Developer rejected the first increment's reliance on a single viewport
breakpoint. That 700px implementation above is superseded by these changes:

- DesignWorkspace establishes a named inline-size container. Docked panel widths
  use `clamp(14rem, 24cqw, 18rem)`, varying continuously with the workspace.
- A single content-layout query at 56rem of **container width** changes docking
  to overlays to reserve useful canvas space. Overlay panels use
  `min(22rem, calc(100cqw - 1rem))`, adapting to the actual available width.
  A narrow embedded workspace therefore adapts even in a wide desktop window.
- The Properties access control uses the same container query as its panel.
  Escape checks the actual visible control rather than a separate viewport-width
  test. Presentation toggling still retains editor, selection and draft owners.
- The existing toolbar ResizeObserver exports its measured height as a local
  CSS variable. Default Assets, Weather, Multimedia and DetailsCard top/height
  bounds follow wrapped toolbar rows; docked Assets retain their host's height
  and restored inline overlay positions remain authoritative. Bottom bounds
  account for the safe-area inset, with the existing padding as a minimum.
- Project-header containers and their trigger can shrink; long Project names
  truncate visually while their full text remains available to accessibility.
- At short heights the existing split reserves the available lower workspace
  up to its 260px target while retaining a bounded Scene region. Saved split
  preferences are not rewritten. Overlay padding and title spacing scale with
  viewport height, keeping the field scroll area inside its panel.

Expanded validation:

  the 895/896/897px layout boundary, plus six 375px-wide heights from 240 to
  1080px. It checks fluid dock dimensions, bounded panels, available canvas

- A 375px workspace inside a 1440px browser confirms container-relative layout
  and working Properties/Escape. Draft, selected wall, read-only guards and

- The actual ProjectHeaderMenu with a long Project name is included. That

- Final fixture evidence is in local OS temp `threed-mobile-panels-dgx8vt`.
  The rest of the toolbar, Scene and Assets are fixture content; this does not
