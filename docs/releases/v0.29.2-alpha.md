## Post-release selection comparison

October 29: compared actual callback expressions from committed `02c2447b` and `6b77dc84`, executing them with the same local state boundaries. Each case starts with a wall and Model selected to expose how one selection affects the other. No live Project data was read. Both versions retain the same geometry/history object through these callbacks.

| Input | Original committed path | Alpha path |
| --- | --- | --- |
| Pick wall in native plan | Selects wall; retains Model selection; does not force Properties open | Selects wall; clears Model/competing inspectors; forces Properties open |
| Clear native plan selection | Clears wall; retains Model selection | Clears both |
| Select Model through map callback | Selects Model; retains wall selection | Selects Model; clears wall selection |
| Clear Model through map callback | Clears Model; retains wall selection | Clears both |

The existing UnifiedMapView clear callback forwards `onMarkerSelect(null)`, including the Scene Escape path. Its new delegation to `selectArchitecture(null)` therefore has a wider deselection effect than the original path. This is a demonstrated change in the later attempted fixes, not proof of the original reported Properties failure. The cyan footprint is presentation-only with `pointerEvents="none"`; drawing-tool handlers are unchanged between these commits.

Multimedia isolation: source tracing found no direct Design selection/history writes in the provider, bridge, Album inspector or Project Album list. The provider owns media state and a 300ms playback-validity check; the bridge supplies Scene context and observes existing physics events. Simulation keyboard listeners cancel active Simulation execution rather than handling Design input. These observations do not exclude all runtime interactions.

The native local-file fixture now accepts `--design-without-multimedia`, removing only the Design fixture's provider while retaining identical editor, section owner and assertions. Both provider-present and provider-absent runs passed physical toolbar activation, native Properties collapse/reopen, wall selection, numeric Height propagation to Three geometry and pointer dragging. Artifacts: OS temporary `threed-multimedia-browser-8PI0UX` (present) and `threed-multimedia-browser-zNmJ8P` (absent). The initial sandbox run timed out; outside-sandbox runs used temporary profiles and mocked HTTP/media without a server. A test race was corrected by waiting for the queued native details toggle event to update React state before checking persistence.

These tests use a simplified Project owner and no actual Canvas/Rapier or live Project #17. They establish that removing the idle provider does not change the tested behavior, not that all Multimedia additions or the full App are cleared of regressions. Callback comparison receipts remain in ignored `.next/selection-comparison`.

Only validation and documentation changed in this follow-up. No App behavior, schema, UI structure or runtime selection was changed. **Next Steps:** reproduce the remaining failure with the full Project selection/section owners, including selection-clear events and persisted workspace state; compare the identified deselection changes independently before choosing a focused restoration. The initial regression remains unresolved.

## Post-release 2D Project Model editing correction

The Developer authorized reconnecting Project Model selection to native Design Properties and pointer move/resize after source tracing established that Model image picks reached only the separate selected-marker path. This later implementation supersedes the preceding comparison-only status; it does not establish when the original regression began.

- A selected saved Project Model now opens the existing Design Properties section with its name, positions in metres and uniform scale. Save Model uses the existing Project marker update path, preserving the reusable catalog Model and unrelated marker metadata. Failed field saves retain entered values. Selection/view transitions and link navigation protect unsaved fields.
- Dragging an already selected Model image previews its position in the plan; a corner handle previews proportional resizing about the instance origin. Pointer release submits one bounded position/scale update. Height is retained when dragging, metre/Scene-unit conversion is explicit, and cancellation does not submit. Failed gestures retain the saved placement and show failure feedback. This uses the existing uniform scale multiplier, not new independent width/depth schema fields.
- The Project adapter validates the exact saved runtime marker, current edit authority and bounded values, prevents duplicate submissions, and reuses the existing marker transaction/selection reconciliation. Late 2D save responses after Project changes do not patch the newly selected Project. Model placement edits save through existing CRUD; native Architecture remains in its existing Project Save/history path.
- No Canvas, renderer, collider, architecture persistence, database schema or multimedia behavior was replaced. The 3D representation receives the same existing marker transaction after a successful save; the pointer preview is local to the plan until release.

Verification: native local-file tests physically select a Model image, open its Properties, drag, resize, check single-write-on-release/height preservation and retry a failed property save. Existing wall Properties/height/drag checks also pass. The actual Project adapter and movement callback pass mocked checks for exact-instance partial PATCH, denied edits, failed writes and cross-Project late responses. Focused `threed-designs`, `design-appearance-top-view` and `threed-overlay-layout` checks passed; the older pointer fixture gained the real event's `preventDefault` method. Native artifact: OS temporary `threed-multimedia-browser-Vp1qrP`. HTTP/persistence/media are mocked; actual Project #17, 3D Canvas/physics and Save/reopen acceptance remain pending. Changes are unstaged, with no version bump or deployment.
