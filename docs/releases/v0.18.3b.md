# v0.18.3b — ThreeD MQTT Control Layer: Phase 4L-D–4L-K

Released to production and verified on August 21, 2026.

## Release scope

- Adds the owner-scoped emergency Water-off audit repository and strict accepted-delivery context mapping.
- Adds a signed App-to-worker emergency request contract and a worker endpoint protected by the existing HMAC and replay boundary.
- Adds process-local emergency idempotency and shared per-FarmBot arbitration with normal Water and recovery execution.
- Adds exact emergency RPC acknowledgement correlation and authenticated worker-to-App outcome ingestion.
- Adds queued acknowledgement reporting with bounded retry and exact persistence-receipt validation.
- Removes unused later emergency handoff, dispatch-pilot, initiation, and authorization layers to finish Phase 4 with a smaller boundary.

## Safety boundary

- Production injects only `DisabledFarmBotWorkerEmergencyWaterOffExecutor`.
- Normal Water and recovery executors also remain disabled.
- Worker health continues to report `commandsEnabled: false`.
- The ThreeD MQTT transport exposes no publish operation.
- No browser or ThreeD World Action can initiate an emergency worker request.
- No physical FarmBot operation is enabled by this release.
- The single-device Water pilot remains a separate explicit approval and verification gate.

## Preserved behavior

- Read-only FarmBot MQTT connection, runtime freshness, status, position, event persistence, Admin controls, and Dashboard display.
- Existing ThreeD FBX loading, external animations, Garden wandering, Ecctrl WASD control, task crossfades, DetailsCard controls, targeted Water, targeted Pick Fruit, and harvest persistence.

## Validation

TypeScript, static animation assets, credential security, command policy, MQTT persistence, ThreeD MQTT, FarmBot worker, production build, deployment, and production verification passed.
