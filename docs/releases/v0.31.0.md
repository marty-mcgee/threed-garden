# v0.31.0 - App: Native TypeScript Validation and Zod Removal

## Status and scope

The Developer confirmed App smoke checks on November 3, 2026, after reporting recovery from the removed-Zod development runtime error, and requested production release preparation. The Developer established **0.31.0** as the breaking-change version after [v0.30.2](v0.30.2.md); this corrects the agent's patch-version assignment. Preparation began on `main` / `be17bd042c63ea7af93aa34c3a6b3fda245efcab` plus the accepted working-tree changes. Package.json and both root lockfile versions are **0.31.0**. **v0.31.0 is prepared for the Developer's production release**; deployment is not confirmed.

This release replaces the App's remaining Zod contracts with explicit native TypeScript runtime validation:

- Account registration and User administration retain role allowlists, email/name normalization, UTF-8 password limits, deletion safeguards and revisions.
- Workspace and Module appearance Settings retain strict fields, saved revisions and exact historical appearance compatibility.
- Learn guide creation, editing and import retain field bounds, defaults, slugs, ownership and publishing rules.
- Album relationships, Project/Scene Multimedia commands and Simulation selections retain typed identities, limits, command restrictions and response field allowlists.
- Manual Weather logs retain numeric conversion/ranges, optional fields, UTC date validation and owner-scoped handling.

Small shared checks and `InputValidationError` live in `src/libraries/utils/input-validation.ts`; each domain owns its parser and explicit types. Existing API error adapters keep their generic invalid-request responses. New native contract tests and the UI dependency-boundary check prevent direct/transitive Zod requirements from returning.

This is a breaking change for code importing the former Zod schema objects: use the named native parser functions and explicit types instead of schema `.parse`/`.safeParse` methods or Zod-inferred types. Invalid-input handling uses `InputValidationError` or the typed `tryParseInput` result. The shadcn generator CLI is also removed. The existing HTTP payload, ownership and persistence contracts remain the intended behavior, covered by the retained checks below.

The manifest and lock remove both Zod and the shadcn generator CLI, which required Zod transitively. Repository-owned shadcn/ui components, Radix, styles and aliases remain. All retained locked package versions are unchanged, including Next.js **16.4.3**. Previously withdrawn dependency upgrades and the browser CI job remain excluded. App/package-lock version metadata and generated Learn explorer provenance are updated for this release; schema inventory and relationships are unchanged.

Existing Project content, authentication/authorization, persistence transactions, Scene/Canvas ownership and Model controls remain in their established paths. No schema migration, data import, upload, device action or environment change is required. Existing [v0.30.2 behavior](v0.30.2.md) is retained.
