# v0.19.1c — ThreeD Project Rendering Authority

Released successfully to production through GitHub and Vercel on August 29, 2026. Manual verification, the release gate, deployment, and production checks passed.

## Included

- Bed, Character, FarmBot, Model, and Planting Add/Edit/Delete responses enter Dashboard state through one Project client transaction boundary.
- The Runtime Marker registry provides current-position reads for selection and Scene focus while Ecctrl retains Character movement and Rapier ownership.
- Dashboard marker selection is authoritative; ThreeD Scene Details and focus state are derived presentation.
- Superseded Project loads are aborted and stale responses cannot overwrite the newly selected Project.
- Runtime Marker validation rejects unsafe identities, duplicate marker IDs, partial or non-finite XYZ positions, unsupported transforms, invalid dimensions/scales, and overlapping movable Ecctrl spawns before Scene physics.

## Verified behavior

- Marker CRUD updates only the affected Project marker and returned Sub-Module source rows without reloading the Project, Canvas, or Rapier world.
- Unrelated Runtime Marker object identity, visuals, colliders, and controls remain stable.
- A moved Ecctrl Character can be reselected and focused at its registry-current position.
- Scene Layers remain presentation and runtime-participation controls rather than marker lifecycle authorities.
- Invalid marker records produce bounded diagnostics while valid sibling markers continue rendering.
- Existing Take/Release Control, WASD, model/capsule/halo alignment, camera behavior, Action Targets, and Sub-Module CRUD remain functional.

## Validation

- `npm run typecheck`
- `npm run validate:threed-runtime-markers` — 36 groups
- `npm run validate:threed-orchestration` — 18 groups
- `git diff --check`
- Manual production deployment and verification — confirmed successful

## Boundary

This release does not introduce another marker schema, replace `project_threed_markers`, move Ecctrl or Rapier ownership, reload the Scene during marker CRUD, or add automatic persistence. **Save ThreeD Project** remains the explicit complete-snapshot persistence boundary. No MQTT, FarmBot command, worker, credential, or physical-device authority is expanded.
