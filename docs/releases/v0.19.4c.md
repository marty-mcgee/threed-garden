# v0.19.4c — ThreeD Environment Character Collision

Released successfully to production on September 3, 2026.

## Included

- Direct Environment/Base Map geometry clicks remain selection-neutral while deliberate Project-menu and toolbar actions open the established Environment DetailsCard.
- The Project dropdown dismisses on an outside pointer press without interfering with its own actions.
- Loaded Environment mesh bounds are transformed into marker-local collider descriptions before physics construction.
- The persistent Environment Runtime Marker owns one fixed Rapier body and its bounded `CuboidCollider` children.
- Environment-first Model settling and Character-last admission remain intact.
- Character spawn areas exclude overlapping Environment collider descriptions before the Character enters Rapier.
- Active collider capacity was manually proven at 16, 64, 256, 512, and 1,024 cuboids.
- Cuboids spanning more than 128 Scene units on any axis are deferred as oversized aggregate bounds.
- Remaining candidates are prioritized by distance to stable Character Project positions, with deterministic preview order as the tie-breaker.
- Physics Debug draws cyan outlines only for descriptions mounted as active Rapier colliders.
- Bounded diagnostics report planned, active, deferred, spawn-overlap, oversized, capacity, and priority-point counts.

## Verified behavior

- A controlled ThreeD Character collides with cyan Environment structures rather than passing through them.
- Character model, Ecctrl capsule, halo, camera, selection, WASD movement, and animations remain one runtime unit.
- Character movement and stopping remain smooth without bouncing, trapping, or unbounded falling.
- The Environment loads before the Character on initial Project load and refresh.
- Oversized Scene-spanning debug boxes are removed from the active collider set.
- A tested Environment with 5,411 source meshes and 1,700 planned boxes remains bounded to at most 1,024 active colliders.
- No model/vendor names or filename-derived semantics control collider eligibility.

## Authority boundary

- The Project Environment marker owns transform, Layer participation, fixed-body lifecycle, and collider construction.
- Runtime Adapter JSX/TSX remains supportive visual construction only and creates no RigidBody or collider.
- Ecctrl retains Character motion, capsule, animation, and control authority.
- The Environment safety floor retains continuous ground support across the Environment footprint.
- This release adds no schema, API mutation, uploaded executable code, Project-marker rewrite, or movement-frame persistence.
- Full per-mesh activation and dynamic frame-by-frame collider streaming remain explicitly deferred.
