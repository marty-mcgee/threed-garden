# v0.27.5 - ThreeD Designs: Admin overview

## Admin ThreeD Designs

Problem: the Admin Designs route displayed only Project names and paging, with no shared Admin presentation, search, content summary or status filters.

Acceptance criteria: use the existing Admin header, table, help and URL-state conventions; list only owned Projects; search/filter/sort across the full result set before paging; retain direct Project Design bookmarks and existing Project editing/Save authority. No standalone Design mutations, schema changes or renderer changes.

Implemented:

- Shared Admin header/help and responsive table with Project names/IDs, saved wall/floor/roof/opening counts, status, visibility and Project Updated date.
- URL-backed Project-name search, active/visibility/content filters, name/updated sorting and 50-row paging; refresh, retry and distinct empty states.
- Read-only `/api/admin/designs` selects owner-scoped summaries from Project configuration without returning configuration documents or loading legacy Design records. Inactive Projects are included by default and can be filtered. Counts describe stored array entries, not a geometry-validity/readiness certification.
- Open Design and Edit Project links reuse existing routes. Valid `projectId` bookmarks retain their redirect into Design mode. No new creation/deletion behavior; the empty-state creation link opens the existing New Project page.
- Requests abort on changes; response identity includes account, filters and refresh generation to avoid displaying stale rows.

Validation: fresh `tsc --noEmit --incremental false --pretty false` passed using existing Node 24 installation. Actual route SQL compilation passed against a mocked PostgreSQL proxy: owner predicates, private caching, paging bounds, literal search escaping, sort allowlists and invalid/unauthenticated zero-query guards. Shared URL-state checks passed for 89 actual bindings with mocked React/browser and installed Next history wrappers. Existing Design snapshot/editor/geometry regression checks passed with mocked persistence; no live database access.

Developer accepted the final presentation, including the smaller empty-content label. Authenticated query execution and broader browser/navigation coverage remain separate from that visual acceptance. Package/root lock are prepared as 0.27.5; production release is not yet confirmed.

### Models-style presentation refinement

The Designs list now follows Admin Models: compact header with inline search/count/refresh, labeled 28px filters, pagination above the records, a separately scrolling table with sticky headings, tighter rows and badges, inline Project IDs and colored action hover states. Existing query/data/navigation behavior is retained. Shared URL-state regression checks passed again. Developer accepted this presentation and the final `text-xs` empty-content label.
