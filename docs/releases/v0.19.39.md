# v0.19.39 — ThreeD Characters: Models, Meshes + DetailsCard

Released to production, deployment User-confirmed; package `0.19.39`.

## Characters, Models and runtime readiness

Characters without a usable Model now retain a visible, selectable basic shape while preserving their established GardenCharacter or EcctrlCharacter runtime and physics capsule. Missing, failed or intentionally skipped Model loads settle animation availability instead of leaving the DetailsCard indefinitely loading. Successful Models retain first-pose gating, external FBX loading and semantic Action Mapping.

Character DetailsCards now explain the assigned Model and visible mesh separately from Character defaults and Project physics. The combined **Module / Position** disclosure contains Project position editing without duplicate coordinate summaries. DetailsCards use a readable translucent surface with a uniform header.

## DetailsCard interaction Blueprint

Save, Move and Delete/Remove are the first primary actions for Models, Characters, Beds, FarmBots and Plantings. Character control and module-specific sections follow those common actions. Character animation categories continue to distinguish loaded active actions from inactive or unavailable Action Slots.

The ThreeD Controls user guide documents the criteria for activating Character actions: active slots, Character-over-Model assignment precedence, active source records/files, skeleton binding and runtime action-key availability. It also explains that Take Control does not assign animations and that legacy fallbacks apply only to explicitly verified Models.

## Additional refinements

The Project toolbar's environment entry uses Project Tour when no Environment Map is assigned and opens the assigned Environment DetailsCard when one exists. The Environment Model Library remains the selection step within Project Tour.

## Validation and handoff

Passed TypeScript, static assets, Character animation restart/first-pose/fallback availability, assigned animation loading, Character assignment UI, Animation Action Slots, Character position-save, Library placement/readiness, Project session, orchestration and diff checks. No schema migration or database command was required.
