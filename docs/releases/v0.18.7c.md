# v0.18.7c — ThreeD Layers Scene Contracts

Released successfully to production through GitHub and Vercel on August 24, 2026.

## Included

- ThreeD Layers are the transaction boundary between Project marker data and the persistent R3F Canvas.
- The Scene retains one stable Runtime Marker collection keyed by `marker_id` and one persistent Rapier Physics world.
- Beds, Plantings, Characters, Models, and FarmBots retain Sub-Module-owned rendering and physics behavior.
- Layer show/hide transactions control presentation, pointer behavior, runtime input, collision participation, and Physics Debug output without deleting saved transforms.
- Marker updates do not reload the Project, rebuild the Canvas, or remount unrelated Scene markers.
- Initial and updated transforms flow through stable React/RigidBody props without duplicate imperative initialization writes.
- A bounded Canvas failure circuit stops repeated Rapier frame-error output and presents one contained Scene failure for troubleshooting.

## Planting Project instances

- Dashboard Planting placement creates independent `threed_plantings`, `project_assets`, and `project_threed_markers` records for the requested quantity.
- Spacing produces centered positions while every Planting remains independently selectable and editable.
- DetailsCard edits Project-instance scale and X/Y/Z position and can delete one Planting without deleting its siblings.
- Optional Bed assignment validates Project membership. Bed-local spatial restriction remains deferred.

## Authority boundary

- `project_threed_markers` remains the saved Project-instance authority.
- Runtime Markers retain stable Scene identity.
- ThreeD Layers issue Scene transactions; they do not create another marker store or Physics world.
- Character/Ecctrl control remains owned by the Character instance.
- The Rapier failure circuit is containment, not a substitute for healthy Scene validation.

## Safety boundary

This release does not enable MQTT publishing, worker commands, peripheral operation, or physical-device behavior. The ThreeD MQTT production safety boundary remains v0.18.3b through Phase 4L-K.
