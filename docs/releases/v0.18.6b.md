# v0.18.6b — ThreeD Project Marker Snapshots

Released to production through GitHub and Vercel on August 22, 2026.

## Included

- Provider-neutral Runtime Marker construction and registry ownership for Plantings, Beds, Characters, FarmBots, and Models.
- Canonical marker identity using normalized ThreeD Sub-Module type plus source asset ID.
- Explicit owner-scoped `project_threed_markers` snapshots representing the current saved ThreeD Project state.
- A manual **Save ThreeD Project** control that captures the complete unfiltered marker registry only when requested.
- Eligible snapshot restoration through the Project map loader without restoring removed or inactive Project assets.
- Saved EcctrlCharacter coordinates applied to both Runtime Marker placement and physics-body spawn data.
- Transitional Ecctrl live-position updates in the registry without render-frame database writes.
- On-demand current-position resolution when selecting an Action Target, calculating interaction range, and dispatching generic interactions.

## Preserved behavior

- GardenCharacter and EcctrlCharacter remain separate runtime paths.
- GardenCharacter autonomous wandering remains active and is not persisted continuously.
- Ecctrl Take/Release Control, target-relative WASD, camera modes, DetailsCard, and Action Target focus remain available.
- FBX character models, external FBX animations, semantic Animation Action Mapping, and task-to-locomotion crossfades remain intact.
- Targeted Water and Pick Fruit persistence retain their established post-animation boundaries.
- Projects without saved marker snapshots continue using their assigned source-asset positions.

## Safety boundary

Marker snapshot eligibility is derived from the authenticated owner, active Project relationships, active ThreeD modules, and assigned source assets. Snapshot data is size-limited and rejects credential-like JSON keys. Movement, rendering, MQTT messages, camera changes, and filters do not automatically write marker rows.

This release adds no MQTT publishing, worker command, peripheral operation, or physical-device authority. The ThreeD MQTT safety boundary remains v0.18.3b through Phase 4L-K, and production command executors remain disabled.
