## New features

- Global Module colors and Lucide icons for 41 Modules across Users, Projects, ThreeD, Multimedia and Traffic. Shared headers, sidebar identities and fixed record icons follow saved styles.
- Compact App Settings with collapsible groups/subgroups, per-User browser persistence for six main sections and a stationary personal Save/Discard/Refresh bar.
- Top-level Users Module: searchable paginated accounts, role filtering, explicit Save/Discard and Admin/Super Admin role editing.
- Installation-wide Super Admin authority for User management and global styling, separate from ordinary Admin content ownership through user_id.
- Developer-only first-Super-Admin bootstrap, read-only eligibility mode, explicit apply, repeated-bootstrap refusal, serialized role changes and atomic auditing.
- Same-origin writes, current-account authority checks, optimistic conflict detection, failed-draft retention and last-active-Super-Admin demotion protection.

## Global versus personal settings

Global styling uses existing settings/settings_audit_logs; the 40-entry saved format remains readable with the Users default added. Status icons and individual Layer colors stay independent. Personal navigation visibility, theme and Dashboard link choices retain their existing scope. Scene appearance and Model preview image dimensions remain browser-local. Sidebar expansion and six Settings disclosures remain keyed by signed-in User. Nested Module groups start closed; main defaults open all except Scene Appearance.

## Global Module appearance — October 27, 2026

Developer requested database-backed Module colors and Lucide icons in Settings > App Settings, explicitly shared globally with saves restricted to active accounts whose current `user.role` is `admin`.

Problem and acceptance: existing CRUD/header icons were hardcoded, while workspace settings were personal. A separate global editor must preserve current Module defaults, validate supported names, update shared Module identity presentation after explicit Save, reject ordinary/inactive users, retain failed drafts, detect concurrent edits and leave personal visibility/Scene preferences intact.

Implementation uses existing `settings` and `settings_audit_logs`, with the fixed system key `app.module-appearance.v1`. No schema migration or `db:push` is required. The first authorized Save creates the dedicated row. Current role/active status is checked and locked inside the save transaction; the settings row is locked, revision checked and the audit written atomically. Reads expose only validated Module styles and the caller's edit capability, not other settings or audit data. Invalid stored values fail closed; errors do not expose database contents. No accounts are promoted by this change.

The new independent global editor offers color/icon previews, Save Module appearance, Discard, Restore defaults (draft only) and Reload with dirty confirmation. Static Tailwind classes and a bounded Lucide registry avoid arbitrary CSS/imports. Existing brown/muted choices remain available. Shared Admin headers, Module navigation identities and fixed CRUD record-name icons consume the global styles. Traffic identity headers are connected too; status-dependent icons and per-record Layer color swatches remain separate. Embedded Multimedia headers use explicit Module keys rather than their parent page's identity. Existing sessions see their own save immediately; other sessions load shared values on App reload, not via realtime push.
