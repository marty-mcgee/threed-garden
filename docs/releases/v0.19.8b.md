# v0.19.8b — ThreeD Model Administration, Model File Management, Model Workspaces, Model Texture Dependencies

Released successfully to production on September 6, 2026.

## Included

- Unified Models, Model Categories, Model Animations, and Model Files as one Admin workspace family.
- Added compact, reusable workspace headers and consistent cross-workspace navigation.
- Moved Model Categories from a dialog into its own durable Admin page.
- Preserved selected Model context between Model Files and Model Animations through the `modelId` URL parameter.
- Retained the one-at-a-time Model administration workflow, shared Create/Edit validation, structural primary-file analysis, and attachment-integrity protections established in v0.19.8a.

## Model file and dependency management

- Made **Attachment directory** a required User-defined relative dependency namespace with a 100-character limit.
- Stored new attachment objects under `models/<modelId>/attachments/<relativePath>` without migrating or invalidating existing attachment URLs.
- Rejected absolute paths, parent traversal, invalid directory values, and case-insensitive relative-path conflicts.
- Added owner-scoped inspection of external texture and buffer references discovered in primary FBX, GLB, and GLTF files.
- Presented discovered requirements as **Attached** or **Missing** in the Model Files workspace.
- Used exact relative-path matching first and a unique-filename fallback only when it cannot resolve ambiguously.
- Added Model-owned Three.js dependency resolution so reusable FBX, GLTF, GLB, and OBJ markers can load matching attached Blob files at runtime.

## Architecture boundary

- `threed_models` remains reusable Model authority.
- `threed_model_files` remains attachment-record and relative-path authority.
- Vercel Blob remains file-byte storage behind authenticated, owner-scoped App routes.
- Existing Blob URLs are not migrated.
- No database schema change was introduced.
- GardenCharacter and EcctrlCharacter loading, external Character animation, Runtime Marker identity, Project placement persistence, and Rapier physics remain unchanged.
- Bulk Model import remains outside this release.

## Validation

- `npm run typecheck`
- `git diff --check`
- Targeted resolver checks for exact relative paths, unique filename fallback, and ambiguous filename rejection
- User-confirmed successful production deployment

## Next boundary

The next isolated stage is a requirement-level **Upload Needed File** action that preselects the missing dependency path while preserving the released attachment-directory and resolver contracts.
