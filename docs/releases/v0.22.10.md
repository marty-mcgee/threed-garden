# v0.22.10 — ThreeD Playable Soccer

Released to production, User-confirmed September 30, 2026. Package `0.22.10`; release commit `b952b885`. No schema migration is added.

A controlled movable Character can use the built-in Model **Use as Action Target** choice to select an exact movable ball, play a mapped foot-kick animation, and apply one bounded Rapier impulse after the one-shot completes. Kick requests verify actor/ball instance, current positions, control, visibility, range, and completion identity. The ball's existing body owns the effect; generic Physics Sensors remain the only score authority.

Project Save now includes Sensor counts and occupancy in the existing versioned view state. On load, Rapier reconciles a saved "inside" flag with the actual ball/sensor overlap once both colliders exist. A ball still inside does not score twice; a ball outside clears stale occupancy so its next entry can score. Sensor Settings support bi-directional and uni-directional counting, four X/Z travel choices, and Scene-coordinate or sensor-rotated direction axes. Existing Sensors default to bi-directional; Scene axes are the default for one-way directions.

The release also keeps ball selection rings level while a ball rolls, shows Character facing in Module / Position and saves it, moves animation/physics controls higher in DetailsCard, aligns the kick availability range and failure feedback, stabilizes the Scene camera after Model placement, and restores Ecctrl's native camera-relative WASD while a ball remains selected. Explicit Walk to Target and non-ball interaction steering retain their separate behavior.
