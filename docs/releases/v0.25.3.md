## Changes

### Import supported legacy architecture in the App

- Recognize supported legacy Paper.js Home Design JSON at the file-import boundary and convert it to the existing strict native version-5 architecture document. Native versions 1–5 remain supported through their existing parser.
- Convert legacy centimetres to metres and Paper X/Y to Design X/Z without recentering. Preserve supported level elevations, same-level shared corners, constant-height walls, valid floor polygons and independent roof slopes.
- Show counts and explicit conversion omissions before applying an import. Partial imports require acknowledgement. Keep merge versus architecture-only replacement explicit; invalid input, Cancel and stale file reads do not change Project content.
- Allocate fresh IDs and remap references through the existing Project import/history pipeline. Activate the first imported level so merged architecture is visible immediately in the plan. Existing Models and unrelated Scene content remain intact.

Ordinary **Import JSON imports architecture only**. It does not upload catalog Models or reconstruct their boolean masks. The original “Unsupported or missing design fields” error came from incompatible legacy JSON structure, not missing OBJ/MTL files.

Implementation: [file converter](../../src/libraries/services/threed/design/design-import.ts), [Import dialog](../../src/components/threed/design/DesignImportDialog.tsx), [Design editor](../../src/components/threed/design/DesignEditor.tsx) and the unchanged [Project architecture boundary](../../src/libraries/services/threed/design/project-architecture.ts). Editable data continues in `project.config.threeDArchitecture`, using the established Project Save/load pipeline; no new database table or independent Design save system is added.

### Recover catalog assets through an explicit operator script

`npm run threed:design:recover` adds separate `prepare`, `verify` and `apply` commands:

- Preparation and verification operate on local copied bundles without loading database/storage clients. They validate file paths, bounded geometry/dependencies, hashes and attribution while retaining original references.
- Catalog recovery preserves legacy bottom-center pivots, metre positions and XYZ rotations in radians. Signed/nonuniform scales become reusable OBJ variants with corrected mirrored winding/normals; UV and material references remain intact.
- Explicit apply creates a **new private Project** with Models, Files, assignments and placements using existing tables and validators. It does not overwrite an existing Project or primary Model. Uploaded files use the App's existing **public Vercel Blob storage**; private App records do not make those file URLs private.
- A durable journal, matching direct database connection, session lock, transaction/readback and confirmed-progress resume guard recovery. Uncertain upload/commit outcomes stop for review; uploaded files are retained rather than automatically deleted or replayed.

The default `report` mode retains catalog visuals and reports unresolved apertures. Optional `native` mode replaces only provably compatible catalog openings with generic native frames. These choices are reviewed before apply; neither mode promises full legacy geometry parity.

See the [operator commands, contracts and recovery record](../plans/legacy-design-json-import.md). Source boundaries: [CLI](../../src/libraries/scripts/recover-legacy-design.ts), [filesystem preparation](../../src/libraries/services/threed/design/legacy-recovery-files.ts), [geometry conversion](../../src/libraries/services/threed/design/legacy-recovery-geometry.ts), [injected apply coordinator](../../src/libraries/services/threed/design/legacy-recovery-apply.ts), [database adapter](../../src/libraries/services/threed/design/legacy-recovery-database.ts) and [direct-connection guard](../../src/libraries/services/threed/design/legacy-recovery-connection.ts).

### Clarify Model Library and DetailsCard guidance

- Accept an attached HTTPS MTL as an OBJ material source when its colors do not require image Textures. This removes the false setup blocker for color-only OBJ materials while retaining actual bundle/dependency validation in the existing loader. Metadata readiness is not proof that remote files load successfully.
- Explain **Placement setup**, **Color map assignments**, **Supporting files**, **No collection** and **No thumbnail**. Distinguish reusable Library Models from placed Project instances; Place adds an instance, while Project Assets selects an existing one.
- Enable Inspect for incomplete Models, preserve placement guards and prevent nested keyboard actions from also triggering card inspection.
- Rename DetailsCard sections to **Project placement**, **Object or environment**, **Collisions & movement**, **Whole-model entry counter** and **Model information**. Add accessible question-mark help, including Physics Sensors, and keep compact disclosure rows aligned.
- Preserve the original saved section keys and existing callbacks, transforms, physics and Save behavior while changing visible labels.

Implementation: [readiness](../../src/libraries/services/threed/models/model-library-readiness-core.ts), [Library panel](../../src/components/map/panels/ThreeDModelLibraryPanel.tsx), [DetailsCard](../../src/components/map/details/DetailsCard.tsx), [shared sections](../../src/components/map/details/DetailsCardSection.tsx), [placement editor](../../src/components/map/details/ModelInstancePlacementEditor.tsx) and [sensor editor](../../src/components/map/details/PhysicsSensorCuboidsEditor.tsx).

## Limitations and remaining manual checks

- Existing native doors/windows, roof cutouts/skylights, floor slabs and Flat/Shed/Gable roofs remain available. Recovered catalog doors/windows/skylights are ordinary Model instances, not native hosted openings. Report mode does not apply their legacy boolean apertures, so walls/slabs can cover them.
- Six sloped-top/tapered walls and the invalid two-point floor were omitted from this source. Floor holes, catalog-to-host links, advanced roof connections/forms and persistent annotations remain staged in the [capability roadmap](../plans/design-architecture-capabilities.md); they are **not implemented by v0.25.3**. Legacy appearance, lighting, camera and history are not fully reconstructed.
