# v0.18.3a — ThreeD MQTT Control Layer: Phase 4A–4L-C

Released to production and verified on August 21, 2026.

## Release scope

- Adds strict signed App/worker boundaries for future semantic Water delivery and Water-off recovery.
- Adds dormant owner-scoped delivery, dispatch, acknowledgement, completion, timeout, and recovery coordination.
- Adds process-local command/recovery arbitration, exact RPC correlation, queued persistence receipts, and restart timeout reconciliation.
- Adds an independent emergency Water-off request contract, applied audit table, and pure ordered lifecycle policy through Phase 4L-C.
- Preserves ThreeD ownership of the provider-neutral MQTT control layer, with FarmBot isolated as an integration adapter.

## Safety boundary

- Production Water and recovery executors remain disabled.
- Worker health reports `commandsEnabled: false`.
- The ThreeD MQTT transport exposes no publish operation.
- No browser route enables physical FarmBot execution.
- Emergency Water-off has no repository writer, route, worker handoff, UI control, MQTT publisher, or hardware caller yet.
- Raw MQTT topics, payloads, CeleryScript, credentials, arbitrary commands, coordinates, pins, and durations are not accepted from browsers.

## Preserved behavior

- Read-only FarmBot MQTT connection, runtime freshness, status, position, event persistence, Admin controls, and Dashboard display.
- Existing ThreeD FBX loading, external animations, Garden wandering, Ecctrl WASD control, task crossfades, DetailsCard controls, targeted Water, targeted Pick Fruit, and harvest persistence.

## Validation

TypeScript, static animation assets, credential security, ThreeD MQTT, FarmBot worker, MQTT persistence, command policy, database generation/application, production build, deployment, and production smoke checks passed.
