# v0.18.1b — ThreeD MQTT Control Layer

Released to production and verified on August 20, 2026.

## Release scope

- Introduces a provider-neutral ThreeD MQTT adapter contract, lifecycle policy, read-only session controller, transport boundary, and signed worker boundary.
- Organizes MQTT services under `core`, `transports`, `worker`, and `integrations/farmbot`.
- Uses FarmBot as the first ThreeD MQTT integration without making shared MQTT code depend on FarmBot.
- Moves the FarmBot registry onto the shared controller while preserving owner scope, grant replacement, worker session identity, position freshness, normalized events, persistence, retries, and credential cleanup.
- Keeps FarmBot REST credentials, tokens, peripheral configuration, readiness, and command policy outside shared MQTT infrastructure.

## Preserved production behavior

- Exact read-only FarmBot `status` and `from_device` subscriptions.
- Admin Start/Stop controls and MQTT activity history.
- Project-scoped Dashboard runtime status and position.
- Credential redaction, signed worker boundaries, bounded reconnects, and clean shutdown.
- Existing ThreeD character, animation, DetailsCard, Water, Pick Fruit, and harvest behavior.

## Safety boundary

MQTT publishing and physical FarmBot commands remain disabled. The Phase 3 semantic policy and audit table are dormant and have no writer or dispatch path.

## Validation

TypeScript, ThreeD MQTT, FarmBot worker, credential security, command policy, MQTT persistence, production build, and manual read-only MQTT tests passed before release.
