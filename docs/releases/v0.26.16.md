## Implementation status

- User-owned library; no module membership/schema expansion or ownership reassignment. Ownerless and mismatched legacy content is retained but excluded from public reads.
- Owner-only management and owned parent assignments; Link Album/Track combinations must agree. Existing Track/Media parent ownership is rechecked on edits. Album deletion blocks unresolved child ownership rather than cascading into another User's content.

Legacy signed keys must match the Track's Album folder. Playback reporting remains authenticated, validates accessible Track/Album membership and commits listener history/counter together.
- Public statistics use the same eligibility scopes. Admin Track counts follow Track ownership; recent listening titles require current access and matching Album membership.
- New sample Tracks receive session ownership. Legacy browser polling returns 405; cron fails closed without a matching secret and returns 503 even when authenticated, because global discovery cannot safely assign owners. The legacy service remains retained without route callers; no new operator role is invented.
- Existing Speech/version-to-Track owner checks and upload/delete behavior remain covered by the Multimedia regression group. No existing rows, files or environment settings were changed.

## Source findings

1. **Public listing and file delivery disagree.** Dashboard requests public/published Albums and active Tracks. New private S3 uploads resolve through `/api/multimedia/files`, which admits only the storage owner. Publishing an Album therefore does not by itself make its new uploaded files playable by other Users. Public cover art using that endpoint has the same limitation. Do not make a whole User prefix public to solve this.
2. **Streaming uses a broader visibility rule.** `/api/multimedia/stream/[trackId]` requires sign-in, then accepts Track owner, Album owner or `albumIsPublic`; it does not also require published Album and active Track for non-owners. Private-file redirects still encounter the owner-only file endpoint. Listing permission, file access and playback must converge on one explicit policy.
3. **Links can reference another User's parent.** POST/PUT checks Link ownership but assigns submitted Album/Track IDs without checking target ownership or that both parents agree. Foreign keys only prove existence. Public Album expansion currently filters attached Links by active status, rather than also verifying parent/child ownership consistency.
4. **Playback reporting trusts content references.** `/api/multimedia/playback/track` stamps the listener User but accepts submitted Track/Album IDs without checking accessibility or matching Album membership, then increments that Track's play count. History insertion and counter update are separate writes. Listening authority must be distinguished from edit authority.
5. **Legacy creation bypasses normal owner stamping.** The sample seed endpoint stamps Albums/Links but omits Track `userId`. S3 polling creates Albums/Tracks without a User and queries existing records globally. Nullable columns permit this; source alone does not establish whether such rows exist in production. Never silently claim or reassign ownerless records.
6. **Shared operations lack a matching authority boundary.** Any signed-in caller can trigger the global poller through GET and start/stop it through POST. Cron rejects a wrong bearer only when `CRON_SECRET` is configured, otherwise allowing the operation. These paths can reach storage and database writes; they were not executed during this review.
7. **Statistics use different scopes.** Public stats filter Album `isPublic` without also requiring published status or active Tracks. Admin Track stats use Album ownership, whereas the owner Track list uses Track ownership. These differ for legacy/mismatched parent-child owners. Listener history is correctly conceptually separate from content ownership, but joined titles also require accessible references.
8. **Public responses use broad row selection.** Album and Track public GETs select full rows, including owner/metadata fields; embedded Links/Media also use full rows. A deliberate public serialization allowlist is needed before treating internal fields as safe public data.

## Proposed policy and implementation sequence

These are recommendations, not newly established permissions:

1. Preserve the existing User-owned library model. Management requires the session User to own both the affected record and any destination parent. Parent associations never grant an ownership transfer. Keep the accepted Album Sort Order and manual navigation intact.
2. Add focused two-User/anonymous fixtures and centralize read/manage decisions. Cover private/public/draft/archived Albums, active/inactive Tracks, missing/mismatched owners, parent reassignment, nested responses and forged playback references. Use mocked persistence/storage only.
3. Close parent-reference and operational authority gaps first: Links, playback validation, seed owner stamping, fail-closed cron and explicit handling of shared polling. Preserve existing data; any legacy ownership reconciliation needs a separate reviewed operation.
4. Resolve public delivery deliberately: owner management stays private; approved published content may use a content-specific read path after eligibility checks. Decide whether anonymous consumption is intended and which metadata may be public before changing delivery. A published Album is not blanket permission to expose every file owned by that User.
5. Align statistics and public serializers with the selected rules, then verify Speech/version-to-Track, uploads, Album expansion and Dashboard playback together. Live acceptance, production release and any schema expansion remain separate gates.
