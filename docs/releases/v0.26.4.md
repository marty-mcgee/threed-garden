# v0.26.4 — ThreeD Simulations: Admin workflows and Results

Prepared locally October 15, 2026 on `main`, based on `a6e9e441` (v0.26.3) plus the accepted working changes. Package and root lockfile version fields are `0.26.4`. Production remains **Developer-confirmed v0.26.3**; the exact deployed SHA and independent production verification are unconfirmed. This preparation does not commit, tag, publish or deploy.

## Changes

- **Scene Simulation feedback:** one Run/Stop control, current Action progress, supported-action guidance and separate Result-save feedback/retry. The existing runner remains mounted when details collapse.
- **Admin Simulation management:** Project/availability filters, scoped navigation, compatible participant/Sensor choices, validation guidance, Action support groups and draft-preserving participant-choice reload. Revision conflicts and existing owner checks remain authoritative.
- **Simulation Results:** new read-only Admin list/detail pages use the existing private API. Filter captured attempts; inspect definition snapshots, Action outcomes and Sensor observations; export an explicit report JSON projection without ownership fields. Deleted definitions retain their history, and unfinished reports are not presented as currently running sessions.
- **One management surface:** Scene Create/Prepare links open Admin. Old Dashboard Simulation URLs redirect to Admin; supported creation context is preserved. A new save opens Admin View with an explicit Edit action. Dashboard Scene execution stays in place.
- **Related Admin conventions:** Scenarios, Characters, Animations, Animation Categories and Animation Slots gain appropriate filters, navigation, readable status, green Save actions, validation and retry feedback. Category links open scoped Clips/Slots; Slot filtering precedes pagination. Reference refresh retains edited drafts. The ThreeD overview and sidebar expose Simulation Results.

No database schema, API mutation contract, dependency upgrade, Project Save/load, Scene/Canvas owner or physics change is included. The Developer's README screenshot addition is preserved.

## Limits and manual smoke checks

- Scene execution still supports Run to target ball and contact Kick for one Character/ball pair. Other Actions can be authored/previewed; general executors and independent cross-Project definitions remain deferred.
- Results are browser-reported captured attempts. An unfinished record is not proof of a live session; a successful kick is not proof of a goal.
- Reload choices in the Simulation editor refreshes participants/Sensors; it does not provide universal retry for every Project/module selector read.
- Independent rendered-page, narrow/touch-device, authenticated CRUD and new Save/reopen checks remain manual. Existing GPU-driver stability diagnosis, legacy architecture parity and Builder acceptance remain separate limitations.
