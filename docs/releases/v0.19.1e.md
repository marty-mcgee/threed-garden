# v0.19.1e — ThreeD Planting Placement Surface Continuity

Released successfully to production through GitHub and Vercel on August 29, 2026. Manual interaction verification, the release gate, deployment, and production checks passed.

## Included

- **Place Planting** no longer forces the Dashboard from Combined View into standalone 3D.
- The already-mounted Combined View ThreeD panel remains the authoritative placement surface.
- The Combined panel split and supporting Leaflet surface remain visible during Planting placement.
- The existing Planting request and Project marker transaction are unchanged.

## Verified behavior

- Starting Planting placement in Combined View does not remount `UnifiedMapView`.
- The R3F Canvas and Rapier world remain persistent while awaiting the Scene ground click.
- Existing Runtime Marker identities, marker selection, DetailsCards, Scene Layers, Ecctrl control, and supporting Leaflet state remain intact.
- Planting placement still creates the expected individual Project marker records through its established API path.

## Validation

- `npm run typecheck`
- `npm run validate:threed-runtime-markers` — 37 groups
- `git diff --check`
- Manual Combined View Planting-placement verification
- Production release and verification — confirmed successful

## Boundary

This release changes only the Dashboard surface transition used to begin Planting placement. It adds no schema, API, marker authority, automatic persistence, Canvas lifecycle, Rapier ownership, MQTT, FarmBot command, worker, credential, or physical-device behavior.
