## Status and scope

Prepared for production November 10, 2026. Baseline main / ea8953a6;
preserve existing production follow-up and Settings edits. Package and both root
lockfile versions are 0.32.2. This is preparation, not deployment.

- Built-in General/Open Graph metadata remains present when App Settings values
  are missing, blank, disabled or unavailable. Enabled nonblank saved values take
  precedence. Blank Project fields inherit through the existing metadata path.

  description, site name, website type and an actual App screenshot image.

and private/inactive Project read restrictions are retained. Canvas, Rapier,

## Unreleased follow-up: Open Graph URL and Facebook App ID

This follow-up is now included in [v0.32.3 release preparation](v0.32.3.md), after
the Developer confirmed App Settings functionality. Entries below preserve the
implementation evidence before the version bump.

The Developer confirmed Meta's Debugger now displays the intended hero image,
then authorized og:url output and an optional fb:app_id form/schema field. This
is acceptance of the reported preview, not an exact deployment-commit assertion.

The existing native JSON contract now allows og:url (absolute HTTPS, without
credentials) and fb:app_id (one bounded numeric string). Blank App IDs are omitted;
there is no invented default ID, OAuth setup, App Secret or tracking SDK. These
rows use the existing Settings JSON/audit/revision transaction and Project
config.metaTags override path. No SQL table/column migration is needed.

App Settings labels og:url as the public site URL: its origin is combined with
the requested page path. The default origin is the established threedgarden.com.
The new src/proxy.ts overwrites an internal pathname header from Next's parsed
request path; incoming caller values and Host headers cannot choose the output
origin. It forwards requests without redirecting, authenticating or saving data.
API/framework/static asset routes are excluded. Root metadata uses the trusted
path, without copying arbitrary queries or fragments.

Authorized Project metadata adds /dashboard/scene?projectId=ID only after the
existing public-active/owner query succeeds. Explicit Project og:url and Facebook
App ID values can override their respective fields. Other private/inactive or
missing Projects do not expose Project-specific URL/metadata. Canonical links
remain unchanged; this does not resume the broad dynamic-content SEO resolver.

Use App Settings for one site-wide Facebook App ID. Use a Project's metadata
override when that Project belongs to a different Meta application. Enter one
ID per page/scope, never a comma-separated list or an App Secret. The App validates
format, not ownership or existence of Meta registrations. The Developer will
enter actual IDs; the agent has not written any Settings values.

Read-only local initial HTML checks pass for Home, Learn and public Project 17:
each has one page-appropriate og:url, Project view UI parameters are omitted,
Learn's description remains intact and no canonical link is introduced. A forged
incoming pathname header does not change those URLs. No fb:app_id is emitted
while none is configured. Focused parser/form/service/proxy/inheritance/private
access checks and fresh TypeScript pass. All 109 isolated offline CI tasks and
the guarded 165-page build pass, including Next's proxy compilation. The final
additional mock API save/read and compiled fb:app_id preview assertions pass
focused revalidation; they do not establish a real Meta App registration.
Logs: ignored .next/release-0314-tools/og-url-facebook-ci and og-url-facebook-build.
Browser form save/Meta re-scrape acceptance remains pending. Changes stay unstaged;
package/root lock remain 0.32.2, with no agent commit, push or deployment.
