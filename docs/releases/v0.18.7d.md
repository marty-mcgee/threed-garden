# v0.18.7d — ThreeD Ecctrl Spawn Safety

Released successfully to production through GitHub and Vercel on August 25, 2026.

## Included

- Runtime Marker validation detects two or more movable Characters resolving to the same XYZ spawn position.
- Every Character in an overlapping spawn set is rejected before an Ecctrl body enters Rapier.
- Valid Beds, Plantings, FarmBots, Models, and non-overlapping Characters continue loading in the persistent ThreeD Scene.
- The Dashboard displays bounded marker IDs, source record IDs, shared coordinates, and an Admin Character recovery link.
- The validation boundary does not move records, select one Character arbitrarily, or convert movable Characters into GardenCharacters.

## Verified production behavior

Five movable Character records resolved to `0,0,0`. The Dashboard skipped all five, displayed the safety warning, and loaded the rest of the ThreeD Scene without the prior Rapier/Rust error loop.

## Recovery

Use `/admin/threed/characters` to assign unique XYZ positions to the affected movable Characters. They become eligible for normal `isMovable` → `EcctrlCharacter` routing on the next Project load.

## Boundary

This release adds no database schema, automatic position mutation, new Character placement workflow, MQTT publishing, FarmBot command, or physical-device behavior.
