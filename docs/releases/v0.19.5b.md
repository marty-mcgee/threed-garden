# v0.19.5b — ThreeD Scene Loading Presentation

Released successfully to production on September 4, 2026.

## Included

- One opaque loading presentation across Dashboard handoff, Project data, dynamic ThreeD runtime, first Canvas frame, Scene controls, Models, and Characters.
- Environment-first and Character-last Scene admission.
- Separate GardenCharacter and EcctrlCharacter readiness signals after their complete visual/animation runtime or safe fallback settles.
- One whole-Scene fade from Pre-Production into Production, followed by a Post-Production presentation state.
- A stable Project-toolbar skeleton and loading viewport that retain their size and position throughout startup.
- Dark server-rendered first paint and App-owned light, dark, and system theme settings without an inline theme script.
- Safe direct Dashboard rendering that keeps browser-only map and WebGL dependencies outside server execution.
- Project-switch cleanup for selection, DetailsCard, Character control, camera mode, placement/movement state, and open asset panels.
- A Scene operation notification overlay that does not resize the Project toolbar during marker deletion or other transactions.

## Authority boundaries

- Project data remains the authority for the incoming Project; loading presentation state creates no persistence.
- Runtime Marker identity and the persistent Canvas/Rapier ownership model remain unchanged.
- Project Models settle before Character admission, while GardenCharacter and EcctrlCharacter remain separate runtime paths.
- Character readiness reports presentation completion only; it does not manipulate animation mixers, physics, actions, or world state.
- Incremental marker additions do not replay the Project startup loader or remount an admitted Character.
- Theme persistence stores only the bounded `light`, `dark`, or `system` preference in local storage and a non-sensitive cookie.
- No database schema, API contract, marker CRUD transaction, saved view-state contract, or Layer ownership changes.

## Verified behavior

- Direct Project loads no longer fail from server evaluation of browser-only `window` references.
- The complete Scene fades in with Models settled and Characters visually initialized.
- The Project header skeleton hands off without a visible size or position jump.
- Dark mode no longer first-paints as Light before hydration.
- A selected marker and its DetailsCard do not carry into another Project.
- Project changes do not reproduce the R3F null event-target error.
- Marker deletion feedback remains visible without changing the Project header or Scene height.
- Adding a Model after startup does not hide the Character or replay the full-screen loader.
