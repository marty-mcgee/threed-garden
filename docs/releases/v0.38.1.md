# v0.38.1 - ThreeD Object Duplication and Admin Projects

Admin Projects now uses the compact workspace header, filters and paged record table. The owner-scoped inventory reads active Module counts alongside the Project summaries. Its Duplicate action copies the saved Project. The former card page is preserved in Git at commit `4d67937c`, path `src/app/admin/projects/page.tsx`.

The standalone Model, Character and Terrain editors offer a named copy of the saved record. The source editor stays open while the copy can open in another tab.

- Models start private, with fresh File attachment IDs and a remapped primary File. The copy retains Category, material, Animation and Album assignments and reuses stored file bytes.
- Characters receive a fresh Character identifier, keep their Model links and retain explicit Animation overrides, including disabled actions.
- Terrains copy the latest saved surface and appearance into revision 1 under a new Terrain ID. Existing placements keep their original Terrain and revision.

Apply the [duplication receipt migration](sql/threed-object-duplication.sql) before testing. The copy and its owner-scoped receipt are committed together. Retrying the same submitted request recovers its destination.

Project, Model, Character and Terrain duplication reserve and complete receipts in the same table. Project Save As still captures the current Scene draft and fingerprints the submitted content. The migration backfills v0.38.0 Project receipts, checks their destination and hash, then clears the legacy key and hash from the Project rows. The source Project link continues to record lineage.

For rollout, pause duplication and let in-flight copy requests finish. Apply the migration, deploy v0.38.1 to all serving instances, then resume duplication. Repeat these migration steps even if an earlier v0.38.1 receipt migration was already applied. A conflicting owner/request key aborts the transaction for review.

Offline checks exercise all three POST paths with in-memory persistence, including distinct IDs, primary File remapping, disabled Character actions, Terrain revision reset, retries and cross-owner denial. Marty confirmed the unified receipt migration was applied and the database schema is accurate. Marty verified Project Save As with the unified receipt in the signed-in App. Marty also verified the Admin Projects list and confirmed that copied Models, Characters and Terrains can each be edited independently of their originals.

In Models, Characters and Terrains, the list row offers a Duplicate icon beside Edit. The saved record’s editor also offers a labeled Duplicate action in the workspace header.
