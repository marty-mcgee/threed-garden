# v0.19.10a — ThreeD Model Bulk Importing

The User confirmed successful release to Vercel production on September 9, 2026. Release commit: `16a92ae`. Package version: `0.19.10-alpha`.

## Included

- Added **Bulk Import FBX** to the dedicated Admin Models workspace, with batch defaults, per-Model overrides, shared local texture selection, dependency matching and explicit ambiguity resolution.
- Added **Assign Existing Texture File** at batch and per-Model level, including inheritance and None. Active owned reusable Textures are assigned as Base Color to all supported material slots without another Texture upload.
- Derived canonical material targets from the existing FBX parse and shared Model preview inventory; verified saved primary files, attachments and material assignments before activation.
- Kept preparation local until explicit import. Models are created inactive; activation requires opt-in and a successful saved dependency audit. Missing named files remain distinct from reusable Texture assignments.
- Preserved known Model IDs and review links after partial imports. Confirmed pre-create failures allow correction and retry after required staged-upload cleanup; uncertain creation outcomes cannot silently retry as new Models.
- Added importer checks to GitHub validation with Node 24, preserving the existing check name. The Admin footer now derives its version from `package.json`.

## Limits and recovery

Bulk uploads accept files up to **4 MiB each**, with at most **100 Models**, **500 selected local texture files**, and **500 discovered references per primary**. Existing-Texture assignment requires a complete inventory of **1–500 material slots**; empty or truncated inventories are not treated as complete assignments.

Queue state and results remain local to the tab. Known partial imports are repaired through Model Files; durable resume and automatic reconciliation of unknown creation outcomes are not included. The bulk chooser remains FBX-only, while existing single-Model formats remain available.

## Boundary

This release adds no schema migration, environment variable, dependency, production asset or Project-instance persistence path. It preserves the single-Model importer, Model renderer, persistent Canvas/Rapier ownership, Runtime Marker identity, separate GardenCharacter/EcctrlCharacter paths, world-action timing, MQTT boundaries and physical-device behavior.

[v0.19.10b — GLB/GLTF bulk importing](../plans/v0.19.10b.md), with intended package version `0.19.10-beta`, remains planned and is not implemented by this release.
