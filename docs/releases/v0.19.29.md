# v0.19.29 — Proximity-Based Environment Collision

Released to production, package `0.19.29`. Deployment User-confirmed on September 16, 2026. Build and deployment are User-managed; separate build output and post-deployment measurements were not supplied.

## Included

- Large static Environment Models prepare a spatial triangle-reference index instead of allocating full-map collision geometry.
- Nearby fragments from different meshes share bounded spatial regions, preserving internal transforms and spanning-triangle coverage.
- Region selection follows enabled dynamic and kinematic Rapier bodies, including uncontrolled balls and movable Characters. Bounds distance, speed margins and retention margins determine proximity.
- Active regions own triangle buffers; inactive buffers are evicted. Stable region identities retain unchanged colliders inside the existing fixed Environment body.
- Small eligible Environments retain full-surface triangle collision. Large, invalid or capacity-limited geometry retains guarded box fallback while triangle regions prepare or cannot provide complete nearby coverage.
- Physics Debug reports preparation phase/rejection, region counts, active triangles, deferred regions and reference memory.

## Limits

The reference index retains metadata for the complete supported asset; it does not reduce renderer geometry memory. Preparation uses a soft four-millisecond frame allowance, and an individual batch or region extraction can exceed it. Full-surface limits are 500,000 triangles/1,500,000 vertices; indexing supports three million source triangles and 50,000 regions. Selection allows 100,000 active triangles and 64 regions, with at most 8,192 triangles per region. Capacity deferral retains fallback rather than guaranteeing triangle coverage everywhere. Transitions can briefly overlap fallback and triangle colliders. Dedicated teleport readiness gating is not included in this release. Unsupported/skinned geometry continues to fail closed to fallback.
