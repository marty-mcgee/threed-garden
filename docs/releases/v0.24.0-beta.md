# v0.24.0-beta — ThreeD Designs: Dashboard workspace

Developer confirmed production release October 10, 2026. Application and root lockfile versions remain **0.24.0-beta**; dependencies are unchanged. This beta follows [the alpha Project Scene integration](v0.24.0-alpha-project-design.md). The confirmation establishes release status only: authenticated architecture Save/reload, resolution of the disappearing-content report, detailed post-deployment verification and exact deployed SHA remain unconfirmed. Prior preparation checks below are not post-deployment testing.

## Implemented and accepted scope

Dashboard `design` View Mode edits architecture in the existing active Project and Scene. The shared typed drawing parameters drive linked 2D/3D geometry alongside existing Models. Switching View Modes retains Scene owners, architectural IDs, history and supported selection; Design does not create a separate Project or independently saved document.

The Developer accepted the revised layout October 10. This confirms the layout checkpoint, separately from real persistence acceptance:

- One established Project toolbar above the workspace, preserving identity/menu and shared theme styling.
- Assets above Properties in the left column, using the existing Assets/Model Library width. Scene above the 2D canvas in the remaining right column, with aligned edges.
- A horizontal height divider, internally scrolling Properties and responsive canvas bounds. Upper-right floating panels, including Simulations, retain their existing behavior.
- Icon drawing/navigation tools in the toolbar middle; Undo/Redo/import/export beside the existing Project Save on the right. Accessible names, hover/focus Tooltips and active/disabled/loading feedback remain. The redundant embedded Plan header is removed; X/Z rulers remain.

Shared tools support walls, floors, hosted doors/windows, named levels, Flat/Shed/Gable roofs and hosted rectangular roof cutouts/skylights. Selected-object properties expose applicable position, dimensions, elevation, rotation, geometry flips and host-relative settings. Drawing defaults remain separate. Imperial inputs convert to the authoritative metre document, and generated geometry converts to Project Scene units.

Navigation includes Pan/middle/Alt-drag, pointer-centered wheel zoom, Fit Plan, Zoom to Selection, Reset View, endpoint/grid snapping, Shift axis constraints, captured dragging, Escape, Delete/Backspace and Undo/Redo shortcuts that leave typing alone. JSON import validates before mutation, explicitly merges or replaces architecture only and assigns fresh IDs with remapped references. Export contains supported editable architecture; unrelated Models and Scene settings are preserved.

## Actual Project storage and lifecycle

There is **no new table or migration** for this integration. The authoritative storage is the existing `project.config` JSONB column, under `threeDArchitecture: { version: 1, document }`; the editable document is version 5. Possible legacy `threed_designs` records are read-only recovery material, not the active save target.

| Boundary | Existing implementation |
| --- | --- |
| Backing column | [`project` schema](../../src/libraries/schema/project/index.ts): `config = jsonb('config')`. |
| Editor draft and Save capture | [`Dashboard Scene page`](../../src/app/dashboard/scene/page.tsx): Project-keyed drafts, `changeArchitecture`, `handleSaveThreeDProject` and `loadData`. Save captures architecture with markers/view state. |

The earlier disappearing-architecture investigation found a client baseline mismatch: raw default numbers differed from validated/normalized history, falsely marking the empty placeholder dirty and preventing saved content from hydrating. The baseline now uses normalized history. Mocked round-trip checks exercise the actual client Save, API transaction, load response and hydration, including retained Models/settings, failed Saves, edits during Save and Project isolation. See [diagnosis and regression evidence](../plans/v0.24.0-alpha-design-layout-reload.md).

**Real authenticated architecture Save/reload remains unverified after the disappearing-content report.** A Save success message does not prove the live backing field was restored. This beta does not claim that the reported live issue is resolved or that previously lost content was recovered. “Unsaved Project Architecture” reflects draft-versus-baseline dirty state, rather than independently proving a database failure.

## Remaining beta limitations and next acceptance

- Authenticated draw → Save → reload → editable reconstruction remains the primary acceptance gate. Verify real Project isolation, pending edits and failed Save feedback too.
- Split height is page-session state. Touch and very small phone layouts remain unverified. Existing Project snapshot concurrency has no separate architecture revision conflict system.
- Architecture is visual/editable geometry; architectural physics, managed material/catalog bindings and architecture GLB registration are deferred.
- Roof joins/hips/overhangs/gable infill, opening rehosting/door handing, stairs, annotations/text/dimension entities, underlays and persistent guides remain unsupported or deferred. These are not implied by existing measurement labels or transient guides.

Manual acceptance: open a Project containing a Model; switch to Design; draw a room, floor and door. Resize the divider, select in either view, edit a dimension and Undo/Redo. Switch to 3D and verify both room and Model at consistent scale. Save Project, reload the same Project and confirm the Model and stable editable room remain, with an unchanged document starting clean. Repeat after switching Projects. Keep a JSON export for explicit recovery while live persistence acceptance is pending.
