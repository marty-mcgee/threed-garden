# v0.19.3c — ThreeD Character Environment Runtime

Released successfully to production through GitHub and Vercel on August 31, 2026. The Character/environment workflow, release gate, deployment, and production behavior were confirmed successful.

## Included

- Character Library placement onto a visible Project environment Model through the existing authenticated Character transaction.
- Preservation of Character-record authority for GardenCharacter-versus-EcctrlCharacter routing.
- Immediate Ecctrl interaction after placement without routing the Character Model through generic Model rules.
- Ground-relative Ecctrl selection and control halo positioning.
- Environment-safe halo rendering above large environment geometry.
- A persistent halo for the duration of **Take Control**, with the established timed fade retained for selection-only state.

## Verified behavior

- Farmer Kate can be placed at a unique position on the Project environment and becomes immediately interactive.
- The Character Model, Rapier capsule, halo, camera, live-position reporting, and WASD movement remain one Ecctrl-owned unit.
- The blue halo appears at the Character's feet and remains visible while controlled.
- The environment remains visible while the procedural ground remains hidden.
- The invisible placement surface and fixed Rapier floor remain operational.
- Character runtime separation, Runtime Marker identity, persistent Canvas ownership, and unrelated markers remain intact.

## Boundary

This release integrates Characters with the flat-floor Project environment boundary. It adds no terrain-mesh collision, elevation-aware navigation, alternate Character runtime, secondary placement API, database schema, or generic Model ownership of Character behavior. GardenCharacter and EcctrlCharacter remain distinct runtime paths selected by the Character record's `isMovable` value.
