# v0.19.35 — ThreeD Scene: Character Interaction UI/UX

Released to production, User-confirmed. Package: `0.19.35`; release commit: `e24c65e`. Development was User-reviewed and accepted. Separate production-build output was not supplied.

## Changes

- Character DetailsCard distinguishes selection from control, offers explicit control-switch wording, labels camera mode and shows animation Loading/Loaded state. Supporting movement, target-readiness and keyboard guidance live in collapsed `? Help`; action reasons use nonvisual accessible labels and hover tooltips.
- One shared, transparent hover title identifies Characters, Models, Beds, Plantings and FarmBots near the hovered asset. Placement tracks camera/asset movement, keeps the initial anchor steady, avoids workspace/Controls panels and clamps to screen edges. Large assets use the hovered surface. Environment Maps have no hover title; Traffic incidents retain their separate presentation.
- Controls starts with Environment. North-Up View, Center View and Save Current View share a group. Gizmo has neutral resting styling; Legend and Compass render above workspace panels. Ground Size/Height use inline rows and clearer labels.
- Unsaved sunlight defaults to 45° elevation. Changing direction from overhead lowers elevation to 45° so its direction becomes visible; the elevation control reflects that value. Saved angles restore normally and shadow updates follow both angles.
- Assigned-asset reads retry once on recognized connection disconnects. Persistent failures reject the Project response rather than silently dropping assets.
- Inactive/invisible movable Characters whose Model loads are intentionally skipped now settle Project preparation. Enabled loads retain first-pose gating. A 15-second pending-Character diagnostic identifies remaining preparation stalls.
