# v0.27.6 - ThreeD Projects: Save snapshot fix

## Project Save oversized Model data correction

Developer reported Project #17 Save failing with `Invalid ThreeD Project marker snapshot`. Diagnostic retries narrowed it to Marker 4's `data`, then confirmed `data.metadata` contained 176,255 bytes, exceeding the existing 32 KiB per-record JSON limit. Removing derived asset collections alone did not resolve this; the catalog metadata was the confirmed remaining blocker.

Acceptance: save existing Project instance state through the established snapshot transaction without copying catalog metadata/assets into every instance, weakening size/security/owner checks, changing schemas or rerunning legacy recovery.

Implemented:

- Model snapshot serialization omits catalog `data.metadata`, `files`, `materialAssignments` and `textureFallbacks`. Current Model records already rehydrate these fields during Project load. Instance transforms, scale, custom data and the separate `marker.metadata` remain intact. The helper does not mutate live render resources.
- The existing client upsert merge retains loaded assets when the compact Save response is acknowledged. Project load restores catalog metadata through the current Model record; no second Save path or renderer owner is introduced.
- Snapshot validation reports a bounded marker index/field and JSON size-limit reason. The largest field is named only from a fixed allowlist, with byte count and no values. Missing/ambiguous active Module assignments receive separate diagnostics. Existing HTTP/JSON/owner/transaction checks remain authoritative.

Developer confirmed **Save Project #17 succeeds** after the catalog-metadata correction on October 24, 2026, then confirmed the requested reopen/layout/appearance check and authorized production preparation. Broader production verification remains separate.
