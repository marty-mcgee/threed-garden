## Problem and acceptance criteria

AdminSidebar already consumed Module appearance for exact module routes, but admin-navigation retained duplicate hard-coded entity icons and section styling depended on its first link. Use explicit typed Module keys for every configured entity and section, resolve both saved icon and color through the existing ModuleIcon/provider, and preserve labels, order, routes, utility icons and user-scoped expansion preferences. Super Admin remains the sole writer; global appearance remains readable by other Users.

## Implementation

- admin-navigation.ts replaces configured entity/section icon components with typed moduleKey references. Create actions, Dashboard and Settings retain utility icons because they have no matching Module appearance definition.
- AdminSidebar.tsx renders those references through the existing ModuleIcon and removes first-link/route inference. Expanded, nested and collapsed presentations share the same saved appearance.
- validate-admin-sidebar.cjs exercises actual ModuleIcon rendering with mocked context: changed saved icon/color values, collapsed section appearance, complete entity mappings and preserved utility icons, alongside existing route/storage/account/mobile checks.
