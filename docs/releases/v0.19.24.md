# v0.19.24 — Multimedia Speech Records + Version History

Production deployment User-confirmed, package `0.19.24`. The user also confirmed applying the Speech schema. A separate manual build result was not reported. The original release checklist below is retained as historical context.

## Included

- Multimedia → Speech → All Speeches / New Speech navigation; the old `/admin/music/audio` page redirects to Speech.
- Full-page Speech creation with title, text, voice, explicit Save Speech, and saved audio preview.
- Persistent `multimedia_speech` drafts and `multimedia_speech_versions` generation history. Owner-scoped APIs, revision conflict checks, archive and restore preserve existing records.
- Explicit generation snapshots saved inputs, reserves a unique request/version, generates through Fish Audio's existing `s2.1-pro-free` path, uploads directly to S3, and verifies output before marking it ready.
- Version playback and explicit acceptance. Regeneration does not replace accepted audio. Failed/interrupted attempts remain recorded; repeated request IDs do not resubmit generation.
- All Speeches follows the Admin blueprint: shared compact header, sortable data columns, server pagination, page selection, bulk archive/restore and colored success/error reporting.
- Track deletion retains S3 files referenced by Speech history.
- Database setup errors distinguish missing tables/columns from other query failures without exposing raw database diagnostics.

## Boundaries

Publishing a saved version as a Track without copying its audio remains unfinished and is excluded from this checkpoint. The former temporary generator's Save as Track control is not part of the new saved form. Existing Music Tracks remain available.

Generation and S3/database writes are not one atomic transaction. Interrupted attempts can be superseded after ten minutes by an explicit new generation. Reserved keys remain for diagnosis if storage succeeded but registration failed; automatic object reconciliation and permanent Speech/file purge are not implemented.

No new Help, ThreeD runtime/physics, Fish model upgrades or other module redesign is included.

Local validation covers TypeScript and offline Speech schema, draft, version, form, list, bulk, error-classification, Fish generation and Track deletion fixtures. These mocks do not certify live PostgreSQL contention or every AWS/provider failure case.

2. Ensure the **production database** contains both approved Speech tables and their constraints. Local schema installation does not prove the deployment database is updated. Track file deletion now depends on the version-reference query and fails closed if unavailable.
3. Confirm production retains the existing server-side Fish Audio and AWS configuration.
4. Smoke-test New Speech → save → generate → preview → accept; reload and verify retention. Generate another version and confirm acceptance is unchanged. Check All Speeches sorting and bulk archive/restore.
5. Review and commit through the user's normal workflow using `v0.19.24 — Multimedia Speech Records + Version History`, then deploy and record confirmation.
