# v0.31.10 - ThreeD: STL Import as GLB Models

## Scope

- Import local ASCII or binary STL files from **Admin > ThreeD > Models > Add Model**, using explicit source units and an upward-axis choice.
- Review dimensions and the converted GLB in the existing 3D Model preview before choosing **Upload converted Model** and **Create Model**.
- Preserve the existing owner-scoped staged upload, Model/File records, Project placement and Save workflows. Temporary preview resources are released without changing ordinary Scene caching.
- Initial mesh import only: native Design walls/floors, CAD constraints and automatic Assembly component extraction are outside this checkpoint.
- No dependency upgrade, schema migration or live data backfill is required.

## Implementation and validation evidence

The following evidence predates release preparation and remains distinct from the Developer acceptance and fresh release gates above.

After the Learn checkpoint, the Developer supplied `openjscad.stl`, confirmed **Inches**, and authorized the proposed import workflow. Work began on clean `main` / `fc0dcdb3`, with package and both root lock versions at 0.31.9. This implementation was separate from the Learn checkpoint. Its subsequent acceptance and release preparation are recorded above.

Problem: the existing Model file path accepts GLB/GLTF/FBX/OBJ/USDZ but cannot inspect an STL or recover its missing unit metadata. Acceptance criteria: require source units, expose upward-axis selection and real geometry preview before upload, retain correct size in existing Scene units, and hand the converted GLB to the ordinary authenticated Model/File workflow. No separate importer persistence or native Design reconstruction is authorized.

Implemented scope:

- **Add Model > Primary Model File > Import STL**, with **Geometry > Source: Model**, inspects local ASCII/binary files, requires units, and previews the converted GLB through the shared Model viewer. Upload stays disabled until geometry and the fitted preview are ready.
- Conversion retains all source triangles and origin, rotates Z-up input to Y-up when selected, and bakes the unit conversion into vertices. One Scene unit is 0.3048 metres; authored inches therefore convert at 1/12 with Model scale 1. Manual Model form fields are preserved.
- Input is bounded to 32 MiB / 250,000 triangles, and output to the existing 32 MiB GLB tier. Malformed, truncated, non-finite and degenerate geometry is rejected. Supported binary colors are retained; otherwise a neutral material is used.
- Explicit **Upload converted Model** delegates to the existing staged direct uploader. Failed/cancelled uploads retain the preview for retry. **Create Model** still performs the existing owned Model/File save. The original STL is not uploaded; keep it for CAD editing.
- Local STL previews opt into transient resource ownership: they bypass the shared Model cache and release their geometry/material/texture resources after replacement, cancellation or close. Ordinary saved-Model/Scene caching remains the default. Blob URLs are revoked and stale conversion results cannot replace a newer selection.
- Ordinary Project placement, 2D plan rendering and explicit Project Save remain downstream consumers of the saved Model. No Scene/Design renderer replacement, semantic walls/floors, separate component extraction, new schema, raw-STL server allowlist, dependency or version change is included.

The supplied sample contains 1,574 triangles. With Inches and Z up, the converted Model measures approximately **1.23825 × 0.8429625 × 2.460625 metres** (width × height × depth); the 114,392-byte GLB retains every triangle. These are geometry/conversion results, not watertightness or physical-collision certification.
