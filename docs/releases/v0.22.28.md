## Released scope

- **Open Scenario** opens a plan; **Run Simulation** executes Actions and collects Results. Simulation definitions and Results have no Scenario columns, foreign keys, indexes or Drizzle relations. CRUD, forms, capture and Scene readiness no longer depend on a Scenario; historical snapshot/report JSON remains intact.
- One-click Scene launch prepares the exact saved Character and target ball through existing owners, with bounded readiness, clear disabled-state guidance, Refresh, Stop and collapsed details. Opening/changing a Scenario neither filters choices nor starts or interrupts a Simulation.
- Authorized public visitors run locally. Project owners retain private revision/reference checks, capture before dispatch, immutable terminal Results and save-only retries. Private catalog/results access is not expanded.
- Scenario View has compact transparent inventory sections, colored icons, title-adjacent help, exact Edit navigation and a green left-aligned Project-assets action. Simulation Save blocks active empty definitions with actionable guidance; inactive empty drafts remain savable.
- The Developer's `threed:scenarios:import` script naming is preserved.

Definitions still require Project/module bindings. Full Project/module independence, versioned participant roles, explicit per-run context and publication are the next separate refactor. General Action executors, cross-Project asset copying, automatic Project saves, MQTT and physical-device operations are excluded. Preserve the persistent Canvas/Rapier world, Garden/Ecctrl separation, retained sources, first-pose/visibility/editing guards and correlated navigation/contact outcomes.
