## Included changes

- App Settings accepts an Open Graph public site URL and optional Facebook App ID
  through the existing JSON contract, CRUD, revision and audit workflow.
- og:url uses the configured HTTPS origin and actual page path. The established
  default origin is https://threedgarden.com/. The new pathname-only Next proxy
  overwrites caller-supplied values; request Host headers do not control origin.
- Authorized Project pages retain their Project ID. Explicit Project URL and App
  ID values override their respective defaults through the existing owner-scoped
  configuration. Private/inactive/unauthorized Projects retain access protections.
- Facebook IDs accept one bounded numeric string per scope; blank values omit
  fb:app_id. Different Projects may use different IDs. No placeholder ID, Meta
  registration, App Secret, login integration or tracking SDK is introduced.
- HTML preview emits fb:app_id as a property tag. URL validation requires HTTPS
  without credentials. App Settings uses the configured URL's origin for page
  output; Project overrides can identify a specific URL.

Learn's description, existing title owner/suffixes, General/Open Graph defaults,
hero image and canonical-link behavior remain intact. The broad dynamic-content
resolver stays on hold. Canvas, Rapier, runtime markers and Project Save/load are
unchanged. Existing Settings JSON and Project config store these fields; no SQL
migration, dependency change or live agent write is required.

## Unreleased maintenance: Next.js 16.4.5 security patch

Requested November 10, 2026, as a focused patch separate from broad dependency
updates. Baseline lock/install: Next 16.4.4; App version remains 0.32.3.
Existing v0.32.3 production-confirmation documentation is preserved.

Primary advisories:

- [GHSA-mfr8-8qww-v76h](https://github.com/vercel/next.js/security/advisories/GHSA-mfr8-8qww-v76h):
  16.4.5 fixes disclosure when a root-param-reading use-cache function is invoked
  both directly and through unstable_cache during a cold-start race. A source
  search found no use-cache directive, unstable_cache, rootParams or
  cacheComponents use in src or next.config.ts. React's request cache in metadata
  is distinct from that pattern. This is not evidence of production exposure
  or a complete security assessment.
- [GHSA-pc58-hwjq-p385](https://github.com/vercel/next.js/security/advisories/GHSA-pc58-hwjq-p385):
  16.4.5 also fixes response injection/disclosure in self-hosted deployments
  forwarding fetched responses behind a susceptible HTTP/1.1 proxy. No claim
  that this site's deployed infrastructure meets those conditions is made.
