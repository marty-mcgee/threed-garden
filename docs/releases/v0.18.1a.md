# v0.18.1a — ThreeD MQTT Module: FarmBot Read-Only Adapter

Status: production checkpoint. Released and verified August 20, 2026.

Release scope: FarmBot Integration Phases 2A–2D, connected read-only through the provider-neutral ThreeD MQTT Module.

This release establishes the provider-neutral ThreeD MQTT Module and connects its first adapter to owned ThreeD FarmBot records and FarmBot's message broker while keeping publishing and physical commands disabled.

Highlights:

- ThreeD-owned, provider-neutral MQTT transport, signed worker authentication, runtime, and normalized event services, with a separate FarmBot adapter.
- Separately run MQTT.js worker with owner-bound sessions, bounded reconnects, redacted errors, graceful shutdown, and a health endpoint.
- Exact QoS 0 subscriptions to FarmBot `status` and `from_device`; no wildcard subscriptions and no publish interface.
- Encrypted server-only credential handoff through short-lived identity-checked grants.
- Normalized `threed_mqtt_runtime` and `threed_mqtt_events` persistence without raw payloads, complete status trees, credentials, or arbitrary CeleryScript.
- Owner-scoped Admin MQTT Activity with Start read-only, Stop, refresh, current state, position, filters, pagination, and history cleanup.
- Authenticated Project-assignment-aware Dashboard FarmBot status showing connection/freshness, message/status times, X/Y/Z position, and token expiry.
- Public map data remains free of MQTT runtime information, broker identity, worker session identity, credentials, and event history.

Production verification confirmed broker connection, message and status timestamps, normalized X/Y/Z position, stale-state recovery, database persistence, clean Stop, Admin activity, and Dashboard status. Repository TypeScript and focused ThreeD MQTT, FarmBot worker, and persistence validation passed during development and release preparation.

FarmBot character targeting remains animation-only. Planting-targeted Water and Pick Fruit persistence remain separate from MQTT. Phase 3 command safety/auditing, MQTT publishing, and every physical FarmBot operation require separate approval under the [ThreeD FarmBot Integration Plan](../developers/FARMBOT_INTEGRATION.md).
