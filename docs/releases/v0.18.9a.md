# v0.18.9a — ThreeD Character Library and Snapshot Recovery

Prepared as a production release candidate on August 26, 2026. Production deployment and smoke tests remain pending.

## Included

- Owner-scoped Character Library discovery and one-shot Project Scene placement.
- Character placement routes through `isMovable` to EcctrlCharacter or GardenCharacter and never through generic Model rules.
- Project-instance Character XYZ editing through the authenticated Project marker API.
- Planting and Character client updates patch only their affected source and marker records without reloading the Project.
- Explicit Save ThreeD Project uses stable marker upserts instead of deleting and recreating every snapshot row.
- Controlled Ecctrl Characters report finite live positions; uncontrolled mounts and clicks cannot save temporary initialization coordinates.
- Pre-render safety rejects overlapping Ecctrl capsule spawn areas before Rapier mounting.
- Rejected Character snapshots expose authenticated source-position recovery without deleting the reusable Character.

## Verified development behavior

- Character Library placement returns the expected Character and marker JSON.
- Planting and Character position changes render immediately and survive refresh.
- Editing a Planting does not separate an Ecctrl Character model from its capsule, halo, camera, or WASD control.
- A Project containing five Character snapshots in one spawn area loads safely with later overlaps skipped.
- Restoring the four skipped snapshots to their separate source positions makes them eligible for the next Scene render.
- Farmer FBX loading resolves the base clip plus all 35 external semantic animation clips.

## Manual production checks

1. Load an owned Project and confirm all repaired Characters appear at separate positions.
2. Take control of an Ecctrl Character and confirm model, capsule, halo, camera, and WASD remain together.
3. Edit and save a Planting, then continue controlling the same Character.
4. Save the ThreeD Project and confirm there is no Scene reload, `invalid_position`, Physics Stopped overlay, or stale marker PATCH ID.
5. Refresh and confirm saved Character and Planting positions restore.
6. Confirm external Character animations load and semantic actions still return to locomotion.

## Boundary

This release adds no database schema, automatic frame writer, generic Character-as-Model runtime, MQTT publishing, FarmBot command, or physical-device behavior.
