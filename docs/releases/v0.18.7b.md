# v0.18.7b — ThreeD Bed Project Placement and Editing

Released successfully to production through GitHub and Vercel on August 24, 2026.

## Included

- Dashboard creation and one-shot ground placement for new rectangular Beds.
- One authenticated transaction creates the owned `threed_beds` source, active `project_assets` assignment, and authoritative `project_threed_markers` instance.
- Pre-placement name, dimensions, color, Y rotation, and scale controls.
- DetailsCard editing for Project-instance width, length, height, X/Y/Z position, and Y rotation.
- Degree-based Bed rotation in stored marker data, converted to radians only at the Three.js/Rapier boundary.
- Live translation and rotation synchronization through each fixed marker's existing Rapier body ref.
- Marker-local client updates without a whole-Project reload or unrelated marker remount.

## Authority boundary

- `threed_beds` is the reusable source created with the Bed.
- `project_assets` owns its active Project and ThreeD-module membership.
- `project_threed_markers` owns the saved Project instance after creation.
- Editing a Project Bed does not mutate its source Bed.
- Later source Bed changes do not overwrite saved Project-instance dimensions or transforms.

## Preserved behavior

- The Canvas and Rapier Physics world remain persistent.
- Bed visuals, fixed bodies, colliders, selection, and Physics Debug outlines remain aligned during edits.
- Unrelated Characters and markers retain their runtime identity.
- GardenCharacter and EcctrlCharacter remain separate paths.
- Character Take/Release Control, WASD, animations, Action Targets, and established world actions remain unchanged.

## Safety boundary

This release does not enable MQTT publishing, worker commands, peripheral operation, or physical-device behavior. The ThreeD MQTT production safety boundary remains v0.18.3b through Phase 4L-K.
