# v0.19.1d — ThreeD Shared-Surface Operation Authority

Released successfully to production through GitHub and Vercel on August 29, 2026. Manual interaction checks, the release gate, deployment, and production verification passed.

## Included

- One Project-session Runtime Marker registry supplies registry-current local positions to separately mounted ThreeD and Leaflet surfaces.
- Controlled Ecctrl movement updates the supporting Leaflet marker without writing movement frames to the database.
- Bed, Character, FarmBot, Model, and Planting updates retain the selected DetailsCard by Project marker record identity.
- Deleting a Project marker clears selection only when that exact marker is selected.
- The Dashboard header derives one Add/Edit/Delete/Move operation status from the existing Sub-Module request states.
- Destination-waiting placement and move modes remain cancellable; issued POST, PATCH, and DELETE requests display pending status and complete through their established handlers.

## Verified behavior

- Leaflet receives throttled current-position updates from the shared registry and a final trailing update.
- Pure ThreeD view performs no unnecessary Leaflet projection rerenders.
- Marker PATCH responses reconcile the active DetailsCard without reloading the Project, Canvas, or Rapier world.
- An unrelated marker transaction cannot dismiss the active DetailsCard.
- Existing Sub-Module request locks, Project client transactions, Runtime Marker identities, renderers, and RigidBody owners remain intact.
- Ecctrl Take/Release Control, WASD, Character model/capsule/halo alignment, Rapier physics, Layers, and Action Targets remain functional.

## Boundary

This release adds no schema, automatic movement persistence, secondary marker authority, Scene reload, or cross-Sub-Module physics ownership. Ecctrl remains authoritative for controlled Character movement, Rapier remains authoritative for runtime physics, and **Save ThreeD Project** remains the explicit complete-snapshot persistence boundary. No MQTT, FarmBot command, worker, credential, or physical-device authority is expanded.
