# v0.19.28 — ThreeD Scene Physics + Project Settings

Released to production, package `0.19.28`, deployment User-confirmed. Separate manual build and cross-Project regression results were not reported. The handoff below is retained as the historical release checklist.

## Included

- Dashboard Model Library loads all eligible pages, including Models previously missing from local search.
- All Models support exact pre-placement XYZ, scale, Y rotation and Environment assignment. Rotation input uses degrees and saves radians.
- Environment toolbar opens the assigned Model editor; Project Tour is a separate Project menu action.
- Eligible static Environment assets use triangle-surface collision, with bounded extraction and guarded box fallback for unsupported assets.
- Movable-ball Project instances have editable mass, gravity multiplier, friction, bounce and rolling resistance. Local geometry measurement avoids rotation-inflated bounds.
- Movable Characters expose mass, walk/run speed, jump strength and ground clearance while preserving Ecctrl/Garden runtime separation.
- Scene controls add sunlight direction/elevation and a larger ground plane with size, height, placement support and collision.
- Project Save retains the new Environment settings with existing camera, layer and marker state. Character and ball settings remain Project-instance metadata.
- Model labels appear on hover; the control halo fades; orbit and view-cube movement settle promptly.

## Release handoff

1. Run `npm run build`.
2. In ThreeD Soccer (Project 15), check a 90° pre-placement rotation and select each ball. Test ball pushing and Character WASD, jump, Take/Release Control, animation transitions and targeting.
3. Save Character/ball settings, adjust sunlight and ground, then use top-level Project Save. Refresh and check settings, positions, camera and layers. Switch to another Project and check isolation.
4. Publish through the normal Git/Vercel workflow with title `v0.19.28 — ThreeD Scene Physics + Project Settings`.
5. Confirm production deployment.

No database migration, environment change or dependency update is required. No commit, push, tag or deployment was performed by the agent.

## Scope limits

Character contact remains capsule-based rather than animated foot-mesh collision. Sunlight changes the directional light, not sky imagery or a clock-driven day cycle. Project snapshots do not restore velocity or animation time. Triangle extraction is limited to 50,000 triangles and falls back for unsupported geometry. Existing below-surface placements are not automatically relocated. The lower Character clearance requires live slope/step regression checks.
