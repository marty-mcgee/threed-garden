# v0.18.2b — ThreeD MQTT Control Layer: Phase 3D–3F

Released to production and verified on August 21, 2026.

## Release scope

- Adds authenticated, owner- and Project-scoped semantic Water authorization.
- Enforces server-owned peripheral binding, pin mode, five-second duration, expiry, idempotency, and per-FarmBot concurrency rules.
- Adds command audit persistence and exact requested, validated/rejected, accepted, dispatched, acknowledged/rejected, completed, and timed-out lifecycle preparation.
- Adds an offline fixed Water delivery envelope and exact FarmBot RPC acknowledgement mapping.
- Adds a separate Water-off recovery envelope, recovery audit schema, and dormant required, dispatched, confirmed, and failed recovery transitions.
- Keeps ThreeD as owner of the provider-neutral MQTT service and FarmBot as an integration adapter.

## Safety boundary

- The authenticated command route stops at `validated` and reports `deliveryEnabled: false`.
- Shared MQTT transport has no publish method.
- Worker health reports `commandsEnabled: false`.
- Lifecycle and recovery repository writers have no route, worker, scheduler, or response-observer caller.
- No physical FarmBot command is enabled by this release.
- Raw CeleryScript, MQTT topics, pins, durations, coordinates, credentials, and provider responses are not accepted from browsers or stored as command payloads.

## Preserved behavior

- Read-only FarmBot MQTT connection, status, position, event history, Admin controls, and Dashboard display.
- Existing ThreeD character loading, animations, autonomous movement, WASD control, task crossfades, DetailsCard controls, targeted Water, targeted Pick Fruit, and harvest persistence.

## Validation

TypeScript, static animation assets, FarmBot command policy, FarmBot worker offline coverage, MQTT persistence, production build, database schema application, and production deployment checks passed.
