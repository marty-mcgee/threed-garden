# v0.18.7a — ThreeD Model Library Project Placements

Released to production through GitHub and Vercel on August 24, 2026.

## Included

- Public and Library classification for existing `threed_models`, with owner-scoped Admin CRUD and replacement file upload.
- A shared read-only Library scope that excludes Character-classified models from the general placement path.
- One-shot Dashboard ground placement backed by owner-scoped `project_threed_markers` CRUD.
- Multiple independently selectable Project marker instances referencing one reusable Model asset.
- Local Three.js DRACO decoder assets for compressed GLB/GLTF rendering.
- Composed reusable-model and instance scale, grounded placement, Y rotation, instance naming, and deletion controls.
- Whole-rendered-asset fixed collision bounds for general Model placements.
- Marker-local create, update, and delete state changes without whole-Project reloads.

## Persistent Scene and Layer authority

- The Canvas and Rapier Physics world remain persistent for the current Project session.
- The complete marker collection remains keyed by stable `marker_id`.
- Every Character, Model, Bed, Planting, and FarmBot retains its Sub-Module-owned runtime and RigidBody path.
- Scene Layer visibility suspends only the matching layer's visuals, pointer input, physics participation, and debug outlines.
- Layer changes do not rebuild colliders, change Scene bounds, reset marker transforms, or transfer Ecctrl movement away from its Character.
- Physics Debug selectively displays enabled Rapier collider outlines while preserving normal model opacity and depth.

## Preserved behavior

- GardenCharacter and EcctrlCharacter remain separate runtime paths.
- Character-classified models remain outside general Model Library placement.
- Ecctrl Take/Release Control, WASD, selection halo, camera behavior, and animation paths remain intact after Model CRUD and Layer changes.
- FBX loading, external animations, idle/walk/run, task-to-locomotion crossfades, DetailsCard, Action Targets, targeted Water, and Pick Fruit persistence retain their established boundaries.

## Safety boundary

This release does not enable MQTT publishing, worker commands, peripheral operation, or physical-device behavior. The ThreeD MQTT production safety boundary remains v0.18.3b through Phase 4L-K.
