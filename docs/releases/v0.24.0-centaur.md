# v0.24.0-centaur — ThreeD Designs: Workspace tools and state

Developer confirmed production release October 10, 2026. Application and both root lockfile version fields remain `0.24.0-centaur`. Previous production: [v0.24.0-beta](v0.24.0-beta.md). This confirms release status only; authenticated Save/reopen, post-deployment verification and exact deployed SHA remain unconfirmed. The preparation checks below are prior local evidence, not post-deployment testing. No dependency or database schema changes are included.

## Checkpoint scope

- Preserve the accepted two-row workspace: Assets above Design Properties at the shared sidebar width; Scene above the 2D Plan on the right, with a resizable horizontal divider and X/Z rulers.
- Drawing tools and Fit Plan, Frame Selection and Reset View now overlay the upper-left Plan, clear of rulers. Project Undo/Redo, JSON import/export and the existing Save remain in the Project toolbar.
- Import JSON opens an App dialog with file validation, explicit merge/architecture-only replacement, Import and Cancel. Invalid/cancelled imports leave content unchanged; imported entity IDs are renewed and unrelated Models remain intact.
- Properties uses shared panel surfaces and collapsible sections with accessible help tooltips. All five section headers have colored inline icons and reduced vertical padding (8px to 2px). The Developer accepted these visual refinements; that acceptance does not certify persistence.
- Existing shared architecture tools, Imperial properties, linked 2D/3D geometry, stable IDs, selection, navigation and Undo/Redo remain intact.

## Project storage and workspace state

Editable content remains in `project.config.threeDArchitecture` (envelope version 1, document version 5). Workspace preferences are separate within existing `project.config.threeDViewState`: Design pan/zoom, active level/selection, row split, visibility/snap and section states; the supported active inspector reference; camera position/target plus optional zoom/FOV. Nothing uses a separate Designs save system or new table.

The [Dashboard Scene page](../../src/app/dashboard/scene/page.tsx) captures the latest Project-keyed draft and live Scene providers in `handleSaveThreeDProject`. The existing owner-scoped [snapshot API](../../src/app/api/project/threed-markers/route.ts) validates and transactionally saves markers/config, preserving unrelated configuration. The [map load API](../../src/app/api/map/threed/route.ts), existing session loader and [architecture hydration/acknowledgment helpers](../../src/libraries/services/threed/design/project-architecture.ts) restore the same Project. [Workspace validation](../../src/libraries/services/threed/design/workspace-state.ts) and [view-state parsing](../../src/libraries/services/threed/markers/project-view-state-core.ts) bound serialized preferences.

Design preferences and section changes mark the draft dirty. Successful acknowledgment advances only the captured baseline; newer edits remain unsaved and failed Saves retain edits. Camera/View Mode/inspector-only changes are captured on explicit Project Save but do not independently mark the architecture/workspace badge dirty. This is not autosave.

Inspector reconstruction waits for required entities and ignores unavailable references. The existing single active asset/Sensor/Group/ground inspector is supported, not a new collection of pinned cards. Saved camera targets outside Model bounds are retained; intentional Follow/Topdown modes and orbit constraints still apply.
