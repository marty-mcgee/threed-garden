# v0.19.4b — ThreeD Environment Interaction UX

Release candidate prepared September 3, 2026. Production deployment remains user-controlled.

## Included

- Direct Environment/Base Map geometry clicks no longer open its DetailsCard or replace the active marker selection.
- Environment geometry remains an intentional destination for Add/Move placement operations.
- The Project dropdown exposes **Environment Details** for each Project Environment Model.
- The top toolbar exposes a compact **Open Project Environment Details** action.
- Both explicit actions reuse the existing Dashboard Runtime Marker selection and Model DetailsCard.
- The Project dropdown closes when the user presses outside its trigger and menu boundary.

## Verified behavior

- Direct Environment clicks remain selection-neutral.
- Project and toolbar actions open the Environment DetailsCard.
- Projects with multiple Environment Models retain explicit named choices in the Project menu.
- Menu actions remain clickable, while an outside press dismisses the menu.
- Environment-first loading, Character-last animation readiness, Character position recovery, and existing Scene physics remain unchanged.

## Validation

- `npm run typecheck`
- `npm run validate:threed-runtime-markers` — 48 groups
- `git diff --check`
- Client-run production build remains the final release gate and is treated as successful unless the user reports otherwise.

## Boundary

This is a UX-only follow-up to v0.19.4a. It activates no internal Environment collider, adds no schema or API, and introduces no secondary marker-selection authority. The next development stage remains the isolated activation of a small bounded subset of Scene-owned fixed Environment colliders.
