## User flow

In **ThreeD Soccer**, load/start **Practice Soccer**, Take Control of **Farmer Kate**, and select the saved movable ball as Action Target. Choose **Run to target ball then kick the ball** in the Scenario card and Run explicitly. If needed, **Prepare Soccer Simulation** opens a dedicated editable, inactive draft with both Actions and current bindings; review, activate and save through normal Admin CRUD.

Kate navigates through the existing Ecctrl movement owner, slows for the final approach and waits for arrival before the mapped contact kick. Completion requires the exact ball owner's applied result. Stop, manual keys, control/target/visibility/placement changes, Project switches and timeouts prevent further dispatch. Misses receive no substitute impulse.

## Included boundaries

- Bounded version-1 `runToTarget`/`kickBall` vocabulary, readable labels and compatible saved actor/ball choices; owner-scoped exact record/reference/revision preflight.
- Exact Scenario/module/environment bindings with backward-compatible saved guidance. Legacy guidance requires reload/start before execution.
- One transient Scene run, captured definition, request correlation, sequential responses and bounded per-step results. A failed/interrupted approach always stops; Continue applies to failed kick steps.
- Optional run-window Sensor Group event/count summaries without resetting shared counters or asserting causal goal completion. Collection ends with the run.
- Existing stable Canvas/Rapier/marker owners, Garden/Ecctrl separation, first-pose and retained-source safeguards, manual controls, assisted kick and ordinary world-action boundaries remain.

No additional migration, data seeding, run/results persistence, automatic Project saves, general Action executor, cross-Project reuse, MQTT/worker or physical-device behavior is included. The production v0.22.25 definition-table SQL must not be rerun for this candidate.
