## Automatic visual counterparts — November 1

`ModelMarker3D` now exposes an opt-in transient capture callback, requested by Project Models without saved Top View images. It waits for loaded geometry (or the existing built-in Shape) to be attached, then queues one image per frame using the same WebGL renderer. The capture uses a temporary orthographic snapshot of that Model, shares its loaded geometry/materials/textures, and never reparents the live object or starts another Canvas/physics world. The PNG is at most 512 pixels on its longest side, uses negative Z up and carries its measured local bounds through the existing calibrated Project plan callback. Changes to geometry/scale cancel obsolete work and regenerate the image. It is local presentation data, excluded from Model/Project persistence.

Capture restores the render target, cube/mip selection, viewport, scissor, clear color/alpha, auto-clear, XR and shadow auto-update state in `finally`, disposing its temporary target and cloned skeleton resources. Source geometry/materials/textures remain owned by the Model. Unmount/source changes cancel queued work; failure retains the selectable bounds and does not retry a failed renderer. Existing SafeCanvas behavior, Scene shadows, physics and animation owners remain. Labels now appear only on hover or selection.

Final checks pass fresh TypeScript, all **102 offline CI tasks**, actual Scene forwarding/projection/selection checks and the new mocked capture lifecycle/queue checks.
