## Automatic visual counterparts — November 1

`ModelMarker3D` now exposes an opt-in transient capture callback, requested by Project Models without saved Top View images. It waits for loaded geometry (or the existing built-in Shape) to be attached, then queues one image per frame using the same WebGL renderer. The capture uses a temporary orthographic snapshot of that Model, shares its loaded geometry/materials/textures, and never reparents the live object or starts another Canvas/physics world. The PNG is at most 512 pixels on its longest side, uses negative Z up and carries its measured local bounds through the existing calibrated Project plan callback. Changes to geometry/scale cancel obsolete work and regenerate the image. It is local presentation data, excluded from Model/Project persistence.

Capture restores the render target, cube/mip selection, viewport, scissor, clear color/alpha, auto-clear, XR and shadow auto-update state in `finally`, disposing its temporary target and cloned skeleton resources. Source geometry/materials/textures remain owned by the Model. Unmount/source changes cancel queued work; failure retains the selectable bounds and does not retry a failed renderer. Existing SafeCanvas behavior, Scene shadows, physics and animation owners remain. Labels now appear only on hover or selection.

Final checks pass fresh TypeScript, all **102 offline CI tasks**, actual Scene forwarding/projection/selection checks and the new mocked capture lifecycle/queue checks. The latter cover complete state restoration after successful/failed readback, shared source resources, image row orientation, one capture per frame, cancellation and detached-owner rejection.

Native local-file Edge/software-WebGL checks exercise actual GLTF and procedural Model owners. They verify real PNG pixel colors, 512×256 aspect/orientation, local bounds, scale regeneration, retained Canvas identity and released render-target textures. Existing Assembly manipulation/CRUD and native Design/Multimedia checks also pass with mocked APIs. The initial capture fixture intercepted Three's `Request` objects for embedded GLTF data; correcting that fixture boundary resolved its timeout. Final artifacts: `threed-assembly-workspace-gayMzX` (generated PNG inspected) and `threed-multimedia-browser-pCH1gt` in the OS temporary directory. ## Project Model editing locks — November 2

DetailsCard now offers **Lock Model / Unlock Model** for each saved placed Project Model. The existing partial marker update persists `metadata.transformLocked`; it applies to this placement rather than every use of its catalog Model. Position, rotation and scale controls are disabled while locked, and Design dragging/resizing, Scene Move placement and geographic marker dragging reject protected edits. Selection, inspection and non-transform editing remain available. Lock changes respect existing busy and unsaved-draft guards; failed requests retain the current state.

The Developer-requested appearance follow-up shows a closed red padlock while locked and an open neutral padlock while unlocked. The yellow inline lock explanation is removed; the existing **Project placement ?** help tooltip explains editing protection and retained runtime behavior. Fresh TypeScript, the existing native mocked Design/DetailsCard/Multimedia checks and whitespace review pass after this styling/copy-only change. Native artifacts: OS temporary directory `threed-multimedia-browser-C85aaE`. Real-App color/help appearance acceptance remains pending; the earlier full-CI evidence below predates this follow-up.

Environment role separately protects direct canvas movement/resizing, including the reported 2D Design path. Deliberate numeric Project placement remains available in DetailsCard unless the Model is explicitly locked. Physics, Actions and Simulations retain their existing runtime owners and behavior; the lock does not freeze a body or suspend a Simulation.

The marker PATCH handler takes the existing Project advisory lock and reads the current owned Model row with `FOR UPDATE` before checking proposed transforms. Generic metadata updates cannot change the lock. A request cannot combine unlocking with movement of a currently locked Model. Project Save uses the same lock, retains the current saved flag despite stale snapshot metadata and rejects changed locked transforms atomically. The existing movable-ball runtime-position snapshot path remains allowed. No schema, migration, dependency, catalog identity or separate Save path is introduced.
