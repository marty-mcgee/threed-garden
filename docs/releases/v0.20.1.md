# v0.20.1 — ThreeD Physics

Release candidate accepted by the User, including the final Sensors panel and DetailsCard layout. Package `0.20.1`. Production deployment is not yet confirmed.

This release establishes a bounded ThreeD Physics Event API and uses Soccer and read-only FarmBot observations as the first reference integrations.

## Physics Sensors and Groups

- Invisible owner-local cuboids attach to Models, Beds, Plantings and FarmBots.
- User-defined names, Trigger/Count Entries behavior, detection filters and groups replace fixed sports roles.
- Groups support sensors on multiple owners; counts are keyed by stable sensor identity and remain session-local.
- Mouse Move XYZ, Rotate Y and Resize use draft previews and explicit Save/Cancel.
- Project Assets lists attached sensors; Setup Environment Map selects without changing the camera.
- Existing sensor configurations retain their geometry through compatibility reading; no database schema change is required.
- Sensor counts are optional via **Environment → Show/Hide Sensors**, with a closeable right-side panel and foldable groups.
- DetailsCards have workspace-bounded scrolling and a non-scrolling header.
- User acceptance is recorded. See [Physics Sensors and Sensor Groups](../developers/THREED_PHYSICS_SENSORS.md).

## Live FarmBot presentation

- Added a strict Project-scoped FarmBot live-state response with explicit live, stale, disconnected, and unavailable conditions.
- Added a foldable **Live FarmBot State** DetailsCard section.
- Added an optional foldable **Physics** section with saved alignment settings for origin, scale, yaw, axis direction, and physical bounds.
- When enabled, confirmed in-bounds MQTT positions move the existing FarmBot Scene representation through a position-based kinematic body with bounded interpolation.
- Stale, disconnected, invalid, or out-of-bounds observations do not invent movement; the last confirmed presentation is retained for the current Project session.
- Saved Project placement remains separate from observed live position.

## Project toolbar navigation

- Project Tour, Environment, and Add to Scene are mutually exclusive, preventing right-side toolbar dropdowns and the Tour from overlapping.
- Project Assets remains an independent full-height left workspace while right-side toolbar menus open and close.
- The Environment menu includes **Setup Environment Map**, which opens Project Assets, selects the assigned Environment Model, and presents its DetailsCard for sensor and Model configuration.

## Safety boundaries

The release adds no schema, dependency, MQTT publisher, automatic World Action, or physical equipment command. Credentials, raw broker messages, worker session identity, and unrestricted coordinates remain server-only or excluded. Project loading does not wait for live telemetry.

Database ThreeD Layer records still do not assign individual Runtime Markers. Configurable Farming work/tool/planting/no-go zones therefore remain a later marker-assignment checkpoint rather than an implicit v0.20.1 behavior change.

## Validation

Focused validators passed for Physics Events, Soccer Physics, FarmBot live state, FarmBot coordinate alignment, Runtime Markers, MQTT persistence, TypeScript, and whitespace integrity. The User confirmed browser/readiness acceptance. The User confirmed a successful production build; deployment confirmation is pending.

## Deferred after this checkpoint

Whole-Model TransformControls, further FarmBot expansion, Add to Scene collections, persistent counter history and additional detection adapters are outside this release. No schema commands are required.
