# v0.24.0-alpha — ThreeD Designs: Project Scene integration

Prepared October 9, 2026 for manual production release. Package and both root lockfile version entries remain **0.24.0-alpha**. This is a continuation of the [previously released alpha checkpoint](v0.24.0-alpha.md), not a new stable release or confirmation of deployment. The prior release record remains historical; no existing GitHub tag or release has been changed.

## Resulting behavior

Design View edits architectural content in the active Project Scene. Switching between **3D, 2D, Combined and Design** retains the same Project, architectural parameters and existing Models. The Plan drives geometry alongside those Models inside the existing Canvas. **Save Project** saves architectural parameters with the established marker and view-state snapshot; reopening reconstructs editable architecture and its geometry.

- Shared `Design*.tsx` tools retain walls, floors, hosted doors/windows, levels, roofs, cutouts/skylights, Imperial inputs and Undo/Redo.
- Stable architectural IDs link editable parameters to generated Scene objects. Metre source geometry converts through the Project's Scene-unit scale, and map outlines use established Project coordinate transforms.
- Scene Canvas, Model/Character owners and Rapier world persist across view changes. Existing Model transforms, materials, resource references and unrelated Project configuration are preserved.
- Visible dirty/error feedback, owner/readiness guards, duplicate-save protection and captured-source acknowledgment retain failed or newer edits.
- JSON export contains architectural content only. Import validates before mutation, explicitly merges or replaces architecture only, and allocates fresh IDs with remapped internal references. Unrelated Scene content remains intact.
- Admin/Dashboard Designs entry points choose an existing Project. Independent Design writes are retired; possible older candidate records remain read-only for explicit recovery.

## Persistence and deployment

The new application JSON contract **project.config.threeDArchitecture** uses the existing `project.config` JSONB column. The existing `/api/map/threed` loader and `/api/project/threed-markers` snapshot transaction handle loading/saving. **No new table, migration, SQL Editor script, or database push is required for this integration.** The superseded independent-record SQL reference is not part of this release procedure.

No dependency update is included. Existing Builder, Model/File/Texture, Scenario/Simulation and Character boundaries remain. Architecture adds visual geometry and picking; new architectural physics colliders, managed material bindings, catalog instances and GLB registration remain follow-ups. Existing Project snapshot concurrency semantics remain unchanged.
