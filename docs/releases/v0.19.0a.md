# v0.19.0a — Shared ThreeD Model Library Placement

Released successfully to production through GitHub and Vercel on August 27, 2026. The manual build gate, deployment, and production verification passed.

## Included

- One existing ThreeD Model Library supplies reusable Models to both Dashboard placement surfaces.
- **Place → click** works on the existing Leaflet 2D Map and React Three Fiber ThreeD Scene.
- Native Model Library drag-and-drop works on both surfaces.
- A reversible Project X/Z and Leaflet latitude/longitude adapter keeps both views aligned around the current map center.
- Leaflet and R3F drops call the same Dashboard-owned Model placement handler and authenticated `project_threed_markers` creation route.
- Combined View displays the returned Project marker through current Runtime Marker and Model Sub-Module ownership.
- Cancellation and drops outside valid placement surfaces perform no write.

## Verified behavior

- 2D click placement creates exactly one marker.
- 3D click placement creates exactly one marker.
- 2D drag-and-drop creates exactly one marker.
- 3D drag-and-drop creates exactly one marker at the ground intersection.
- 2D, 3D, and Combined View resolve the same saved Project marker.
- Invalid drops and cancellation create no record.
- Existing click placement remains available as a keyboard, touch, and troubleshooting fallback.

## Boundary

This release adapts a useful workflow observed in developer-local legacy code; it does not merge or run that legacy application. It adds no Paper.js runtime, second Leaflet map, second R3F Canvas, second Rapier world, marker registry, persistence format, database migration, or API route. Character-classified models remain under GardenCharacter or EcctrlCharacter rules rather than general Model placement.

The developer-local `reference/` directory is intentionally ignored by Git. It contains research and testing material only and is not App source, a public asset directory, or part of the production deployment.
