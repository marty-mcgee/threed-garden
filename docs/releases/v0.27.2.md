## Problem and acceptance criteria

Model Files showed an embedded-image count without per-image inspection, download or an explicit way to create reusable Texture records. The Developer approved staged implementation: browse original saved images with declared material/channel relationships, download originals individually/together, and optionally register selected images. Accept only explicit owner-authorized saved geometry, preserve its primary authority/bytes and existing appearance, keep embedded resources distinct from attached Files/Library links, and never infer runtime material-slot IDs from source names or indices.

## Stages implemented

1. Embedded images gallery inside the existing Linked Texture and embedded resources section. Choose primary or alternate saved GLB/GLTF geometry, search, filter by source material/channel, browse six cards per page, and inspect encoded-header dimensions, format and size. Material-use buttons filter the exact declared source relationships; the preview Materials section links to the gallery. These links do not select or change live preview materials. External image/buffer declarations are labelled and are never fetched by this inspector. FBX/OBJ and other formats retain existing previews/attachment management; individual embedded extraction here supports GLB/GLTF only.
2. Individual original-byte downloads and selected-image ZIP export. ZIP stores original bytes without image conversion. The browser reads one bounded saved source after the metadata catalog; visible cards use local Blob URLs and revoke them on paging/source changes/unmount. There is no per-card geometry download. Visible previews share a 16 MiB/16-megapixel page budget; selected original image bytes are limited to 32 MiB before extraction, preventing overlapping bufferViews from amplifying allocations. KTX2/AVIF can be downloaded but have no native preview or registration action.
3. Explicit Save selected as Textures review/action. The server reads/extracts the owned saved source; the browser sends only Model/File/image identity and a source stamp. Each supported PNG/JPEG/WebP up to 4 MiB creates one reusable Texture and one attached Model File referencing the same Blob, inside the existing schema. No material assignment, source rewrite, primary selection or new metadata contract is introduced. Same-source/image/hash aliases and Model/File locks reuse existing copies on retry/concurrent requests. Reuse retains existing Library names and Active settings. Failed transactions/race losers attempt cleanup only of their own unreferenced staged Blob. No existing Blob is deleted. Successful rows survive a later save/refresh failure; remaining work stops for review and can be explicitly retried.

## Authority and bounds

GET /api/threed/models/[id]/embedded-images requires an authenticated owner and explicit saved geometry fileId. Catalog, stamped source and stamped individual-image responses are private/no-store/nosniff. Reads accept only eligible owner-scoped saved Blob URLs, reject redirects, stream at most 32 MiB with a 30-second timeout, and verify File identity again after reading. Source stamps include the exact File identity and source bytes; stale reads/saves reject with 409. Source images, external URLs, exporter extras and private metadata are not published through a Library serializer.

The explicit POST /api/threed/models/[id]/embedded-images/register action reuses existing Model, Model File and Texture tables and existing storage path/cleanup owners. It enforces bounded identity-only JSON and validates source/image/mime/dimensions before uploading. The UI serializes selected saves, bounds each request, blocks duplicate clicks and keeps the existing parent busy/navigation guards; an error or lost response does not trigger automatic retries. Raw embedded image presence and saved references remain separate from render correctness. No migration, dependency upgrade, live validation write or automatic extraction/upload is performed.
