## Status and scope

The Developer requested this accumulated checkpoint be prepared for production as **0.30.0-centaur**. Preparation began on `main` / `5818bf9b` with existing unstaged changes preserved. Package and both root lockfile versions now agree at 0.30.0-centaur; dependency versions are unchanged. Preparation is not deployment, and the broader [v0.30.0 milestone](v0.30.0.md) remains open.

- The Project toolbar's **Multimedia** menu combines assigned Album/Track browsing with the current playback status, media/video presentation and Play/Pause/Stop/Rewind/Next Track controls. The separate floating player is removed. Closing/reopening the menu preserves one media element and ongoing playback; no mini player is included.
- Project Assets places Multimedia after sibling asset sections. Album buttons open the menu and share selection/current Track status with its player. Browsing does not autoplay or replace current playback; **Show current Album** returns to the current Project Track.
- **Save ThreeD Project** captures the menu's open/closed state and Album/Track IDs through the existing snapshot transaction. Reopening revalidates access and restores paused, without autoplay or persisted URLs/playing state.
- Initial ThreeD preparation covers the whole Project workspace, including Assets, Design panels and restored overlays. Reported pending Scene resources hold initial readiness. The Canvas and existing owners stay mounted; later asset edits do not restart preparation. Failure UI remains accessible and 2D-only mode remains usable.
- Project Multimedia Module creation uses unique slugs for repeated names and consistent Multimedia terminology. The toolbar uses neutral Multimedia icon color, **Scene** instead of Environment, and **Tools** instead of Setup, preserving existing commands and identities.
