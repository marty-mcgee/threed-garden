# Apply ThreeD Admin Page Blueprint

For a page review, use the [route inventory](../../../plans/admin-page-blueprint-audit.md#threed-route-inventory) to locate the component and its other callers. The [review prompts](../../../plans/admin-page-blueprint-audit.md#what-the-agent-skill-should-ask) cover who may act on each record, how the page behaves in each host, and what the user sees after a partial or failed save. Recheck the cited source when a route changes.

1. Read [AGENTS.md](../../../../AGENTS.md), [CONTEXT.md](../../../../CONTEXT.md), and the [Blueprint and rollout plan](../../../plans/admin-threed-workspace-blueprint.md). Inspect the current diff. Start with the canonical route, then trace the record, schema, authorization, list query, writes, and any embedded or public callers.
2. Map the supported actions for the requested page. Use Tasks for sorting and selection, Assembly Groups and Terrains for saved rank and Active, and Waterings and Harvests for CRUD dialogs and scoped bulk updates. Use the common Admin header, controls, help tooltips, status states, and editor styles. Omit the **Multimedia Albums** button from standalone ThreeD Admin page headers. When using `AdminWorkspaceHeader`, set `showModuleAlbums` to false for the standalone host and verify that any existing record-level Album editor is still reachable. Keep existing navigation, typed drafts, and the behavior of embedded callers.
3. Sort and filter the authorized result set before paging. Use stable tie-breakers and keep totals aligned with results. Clear page selection when its scope changes. For manual ordering, follow the [drag-and-drop Sort Order Blueprint](../../../plans/admin-threed-workspace-blueprint.md#drag-and-drop-sort-order). Identify who owns the rank and which hosts can move records. Compare the grip, record icon, name and rank cells with a working peer table. Use one scoped transaction for pointer and keyboard moves, including when the user moves rows on a later page.
4. Apply the [ThreeD Bulk Edit Blueprint](../../../plans/admin-threed-workspace-blueprint.md#bulk-edit-on-threed-admin-pages) on standalone editable catalogs. Check the page’s field table and both edit and delete eligibility. Freeze page-local IDs, parent scope and conflict stamps when the dialog opens. Validate opted-in fields and domain rules on the server, save the complete authorized batch in one transaction, and refresh on success. Preserve existing parent-scoped editors and read-only reports. Confirm deletions and retain module-specific status, visibility, provenance, units, revisions, and history. Get explicit approval before expanding schema or persistence.
5. Test search and sorting across page boundaries, selection reset, drag and keyboard reorder where supported, save/reopen, mixed access, and failed mutations. Use the [validation ladder](../../VALIDATION.md) and mocked persistence. Record Developer acceptance, local verification, database migration status, and production status separately. Update the [Admin Guide](../../../users/ADMIN_GUIDE.md), rollout plan, and matching release record when the user-visible workflow changes.
