# plans: docs: v0.19.9 — Guided ThreeD Project Creation and First-Run Experience

Status: completed and released successfully to production September 7, 2026. Current production is **v0.19.9 — Guided ThreeD Project Creation and First-Run Experience**.

## Objective

Help a first-time User build a useful ThreeD Project through the App's existing Project, Library, placement, DetailsCard, and Save workflows without creating a second asset inventory or automatic mutation path.

## Stage 1 — Focused Project Tour progression

Status: implemented and manually verified September 7, 2026.

- Derive one recommended next step from authoritative Runtime Marker state.
- Guide the User through **Environment → Model → Character**.
- Present progress and completion without requiring stored onboarding state.
- Keep every foundation step directly accessible for advanced Users working out of order.
- Keep Project Settings secondary to the active Scene-building step.

The Tour still waits for the complete ThreeD Scene presentation, yields to existing Library workspaces, returns after successful placement, dismisses explicitly, and resets on Project change.

## Deferred progression after v0.19.9

The focused Project Tour is the approved v0.19.9 release boundary. The following ideas remain available for reconsideration in a later version rather than expanding this checkpoint.

### Contextual workspace handoff

- Clearly identify the active Tour task inside the existing Environment, Model, and Character Library surfaces.
- Preserve one left workspace and avoid adding another overlay above it.
- Return to the Tour only after a successful existing placement transaction or explicit cancellation.
- Keep all Library browsing and placement controls usable outside onboarding.

### Placement review and Project completion

- Guide the User from first Model placement into the existing DetailsCard adjustment controls.
- Make the distinction between reusable Model base scale and Project-instance placement scale explicit.
- Add a deliberate final Save handoff using the established **Save ThreeD Project** action.
- Derive completion from existing Project and UI transaction state; do not add onboarding database schema.

### Recovery and accessibility

- Verify dismissal, reopening through **Setup**, Project switching, and refresh behavior.
- Verify keyboard focus, readable progress, reduced-motion behavior, and compact viewport layout.
- Recheck Scene loading order, Project Header stability, Library/DetailsCard boundaries, and persistent Canvas/Rapier ownership.
- Run the relevant repository validation ladder and complete manual new-Project regression coverage before release preparation.

## Preserved boundaries

- Runtime Markers remain the Tour's Project-progress source.
- Existing authenticated placement and Save transactions remain the only mutation paths.
- `project_threed_markers` remains Project-instance authority.
- The Dashboard retains one persistent React Three Fiber Canvas and Rapier world.
- GardenCharacter and EcctrlCharacter remain separate runtime paths.
- The Tour does not automatically create assets, save a Project, publish MQTT, issue FarmBot commands, or operate a physical device.
