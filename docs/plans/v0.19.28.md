## Soccer Scene grounding and interaction review

User reported below-field contacts, an unclickable small ball, persistent labels/control halo, and slow camera settling. Inspected causes: broad floor-like environment bounds were discarded (zero-thickness surfaces were invalid); environment and invisible ground handlers could stop selection propagation; names always rendered; Ecctrl halo was persistent; OrbitControls damping was enabled.

Changes: retain up to 64 broad thin floor surfaces as positive-thickness ground cuboids with their top aligned to source bounds, separately from the obstacle activation budget. This is a flat-surface approximation, not triangle-accurate terrain support. Environment surfaces and unused invisible ground no longer block ordinary object clicks. Model labels display on hover with pointer-transparent, low-z-index HTML. Fading rings are non-raycastable. The Ecctrl control ring resets on control changes, holds for two seconds, and fades over 0.3 seconds. Orbit damping is off and view-cube clicks orient directly; the auxiliary axis gizmo retains its library transition.

TypeScript, 50 Runtime Marker groups, headless ball contact, hidden-layer checks, new flat/thin/invalid environment-ground fixture, and diff checks passed. No live Project edits or build. Browser acceptance still required for imported Soccer Field geometry, all three ball clicks, hover labels, control halo timing, and mouse/view-cube response. Existing saved static Models are not automatically moved upward; balls/Characters spawned wholly below an elevated floor may require repositioning above it before physics can settle them. No claim of universal terrain grounding is made.

## User-adjustable ball response and lower Character contact

User confirmed triangle-surface collision works, then reported excessive rolling and inaccurate feet/ball contact. Inspection found hard-coded ball damping 0.35, mass 0.43, and Ecctrl suspension clearance 0.3, leaving a 0.26-diameter ball wholly below its capsule. Acceptance: configurable bounded per-instance response, shorter default rolling, and capsule contact with that small ball, preserving controller and animation ownership.

Added collapsible Ball physics fields (mass, gravity multiplier, friction, bounce, rolling resistance) saved through existing owner-scoped marker metadata merge. Runtime normalizes invalid values to bounded defaults. Defaults now use mass 1, gravity multiplier 1, friction 0.8, bounce 0.2, and linear/angular damping 1.5. Existing balls without explicit settings use these defaults. Reduced Ecctrl suspension clearance to 0.05 with its existing visual ground-offset calculation following the same constant; capsule dimensions and animation paths remain unchanged. This is approximate capsule contact, not animated foot-mesh collision, and affects movable Characters generally.

Validation: TypeScript and hidden-collision-mount passed; native Rapier ball-settings fixture proves reduced rolling distance, bounded settings, and small-ball contact at 0.05 clearance versus missed contact at 0.3. Diff check passed. Browser acceptance remains: save/reopen each ball's settings, push the small ball with Kate, and verify WASD, slopes/steps, jump, Take/Release Control, and animation transitions with the lower suspension. No schema change, build, commit or deployment.
