## Corrected scope — complete list workspace blueprint

User rejected header-only alignment and explicitly requested the same presentation as Models/Characters/Beds/FarmBots. Evidence: Albums remained a card grid; other lists lacked search, sortable headings, selection and paging; the route hosts still scrolled as entire pages. This supersedes the first pass's header-only scope.

Implemented full standalone Albums, Tracks, Media and Links list workspaces: title/count/search/action header; result range, current-page selection, confirmed Delete selected and Clear selection; 25/50/100/200 page sizes and First/Previous/Page/Next/Last; compact sortable table columns; consistent blue entity icons and text/boolean status presentation; independently scrolling records and sticky headings. Albums cards become rows with View/Edit/Delete actions. Existing forms, media uploads, Track playback and single-record mutations remain in their owning components. Embedded CRUD instances retain their existing data flow and natural sizing through the pageHeader flag.

Added a dedicated authenticated `/api/music/admin-list` read endpoint for these standalone views. It uses allowlisted module/column identifiers, bounded query parameters, owner filtering, name search, NULLS LAST and an ID tie-breaker before paging. Row/count queries share the scope. Existing public/music detail API semantics are unchanged. Shared hook cancels obsolete requests, clears selection on query changes, clamps empty trailing pages, and reports partial deletion failures. Bulk deletion delegates to each existing DELETE endpoint; Album cascading behavior is included in its confirmation and Track S3 protections are retained.

Reviewed and explicitly enabled fixed workspace hosting only for the four standalone music lists and All Speeches. Speech retains its existing controls and now also has the matching fixed header/pagination and scrolling table. New Speech and detail/player pages are not constrained this way. Overview remains analytics rather than pretending to be a CRUD record table.

Validation: TypeScript, actual admin-list fixture (auth, identifier allowlists, shared search/owner scopes, paging), actual bulk-handler fixture (confirmation, off-page exclusion, partial failures, duplicate exclusion), existing Track deletion fixture and diff checks passed. No browser or live database test was performed. User owns build. Review all four list routes plus Speech at narrow/short window sizes, search older records, sort columns, page, and test selected deletion only with disposable records. No schema change, package bump, commit, push or deployment.
