# v0.22.8 — Project Scenario Setup

This is Stage 1 of the [ThreeD Project Scenarios experience plan](threed-project-scenarios-experience.md).

**Local preparation; not released.** The package version is 0.22.8. This checkpoint makes the existing saved Scenario definition easier to create from a Project or its Scene. It does not expand Scenario persistence, assign Scene objects to a Scenario, or change physics behavior.

The current Admin Scenario form already saves an owner-scoped definition for a Project and one of its assigned ThreeD modules. The missing path was discovery: a User starting in a Project or Scene had to find the standalone Admin workspace and reselect the Project. This preparation adds **Set up Scenario** in Project Modules and **Save a Scenario** in the Scene's Scenarios panel. Both links open the Admin form with the owned Project preselected. If that Project has no assigned ThreeD module, the form points back to its Modules section. The existing temporary Scene setup checklist remains available.

Acceptance for this checkpoint:

- A Project or Scene entry point opens a new Scenario form with that owned Project selected.
- A missing or unowned Project query parameter does not preselect a Project or open the create dialog.
- The form continues to require an assigned ThreeD module and the existing owner-scoped API validation.
- Saving a definition makes it available in the Admin list and the Project Scene's read-only Scenario card; it does not create Scene objects or sensor configuration.

Validate with `npm run validate -- threed-scenario-admin`, `npm run typecheck`, `git diff --check`, and the release-preparation `npm run build`. Browser acceptance should exercise Project → form → save and Scene → form → save, plus a Project without an assigned ThreeD module. Keep these Scenario changes uncommitted until reviewed for the v0.22.8 release.
