# v0.19.15 — ThreeD Admin Pages: UI Updates

Prepared September 12, 2026. **Release candidate; not deployed.** Package `0.19.15`. Current production remains v0.19.14 (`a5491e9`). The User approved milestone validation and release preparation after incremental visual acceptance of the updated pages. Manual production build is User-confirmed successful; final live regression/deployment remain pending; the agent did not run a build, access the live database, commit, push or deploy.

## Outcome and scope

Admin lists previously repeated headings, scrolled their controls out of view and often searched only the first 100 fetched records. The planned remaining pages now follow the Models workspace blueprint: compact header/search/actions, stationary navigation, independently scrolling records, sticky headings, accessible horizontal overflow and compact rows. Standalone routes opt into constrained height; embedded Project components retain natural sizing.

| Page | Included behavior |
|---|---|
| Plants | Server search/sort/pagination and page-local bulk deletion; green Sprout icons, outlined Type badges, adjacent Status/Active |
| Beds | Server search/sort/pagination and page-local bulk deletion; retained dimensions, transforms and forms |
| Plantings | Server search/sort/pagination and page-local bulk deletion; Plant, Bed, Planting ID, Position, Growth, Status, Active, Actions; brown Bean icons |
| Characters | Server search/sort/pagination and page-local bulk deletion; retained animation assignment/edit actions; redundant name badges removed |
| Layers | Server search/sort/pagination and page-local bulk deletion; Visible/Locked retained as sortable columns alongside existing action buttons |
| FarmBots | Server search/sort/pagination and page-local bulk deletion; existing connection/activity controls and response sanitization retained |
| Waterings | Separate read-only Schedules and History views, server search/pagination, correct units, target IDs, refresh and honest empty/error states |
| Harvests | Server search/Project filtering/sort/pagination and page-local bulk deletion; Harvest Name, Plant, ID, Quantity, Weight, Date, Active, Actions; World Action provenance retained |

CRUD lists use 25/50/100/200 page sizes and First / Previous / Page N of M / Next / Last. Selection clears on page/search/sort/scope changes. Confirmed sequential bulk deletion reuses existing owner-scoped single-record deletion paths, reports partial failures, refreshes totals and recovers emptied final pages. Superseded list reads are aborted/ignored. Waterings has no unsupported selection/mutation actions.

List APIs validate paging/search/sort inputs, use shared count/row filters and stable ordering. Grouped search remains inside owner scope. Related Model/Bed lookups are batched where previously performed per row. New GET `/api/threed/watering-history` provides authenticated history browsing. Eight offline list fixtures are registered in package scripts and GitHub validation.

## Preserved boundaries

No schema, data migration, dependency or environment change is needed. Bun lockfile contains no root package version to update. This candidate relies on the existing production schema; no db:push is part of this handoff.

Model Files remains a specialized customization UI. Prior Models, Categories, Textures and Animations work remains in place. Character runtime separation, primary File authority, shared Texture reuse, persistent Scene/Rapier ownership, saved transforms, animation mappings and completion-gated world actions are unchanged. FarmBot operation/credential gates are not expanded; existing deletion still performs its established related-record cleanup.

## Known limits and follow-up scope

- Waterings is early development: Schedules/History browsing only. Editing, execution, richer relationship navigation and history details remain future work. Missing measurements display a dash, not zero.
- Watering History lacks stored historical Project identity. Embedded module scope uses current active owner Project links to Plantings/Schedules, as disclosed in the UI; it is not historical attribution.
- Some Create/Edit relationship selectors retain their existing 100-record limits. Full list pagination does not remove those form limits.
- Harvest Name displays the editable `harvestId`; ID is the numeric record key. No separate name/status field was added. Quantity sorting compares stored numbers without unit conversion.
- Tasks/Analytics remain excluded from the rollout; their removal was not implemented here. Settings/Registration remain deferred. Overview and specialized Marker administration were not added to the agreed eight-page sequence.
- Dedicated Model animation assignment editing and retargeting remain separate animation work.
