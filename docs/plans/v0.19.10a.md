# v0.19.10a — ThreeD Model Bulk Importing

Status: released successfully to Vercel production, confirmed by the User September 9, 2026. Package version: `0.19.10-alpha`; release commit: `16a92ae`. This releases the FBX/Texture implementation after the earlier planning-documentation deployments. See the [production release record](../releases/v0.19.10a.md), [implementation record](v0.19.10a-implementation.md) and [deployment preparation record](v0.19.10a-release.md).

## Objective

The App is working well. Revisit ThreeD Model Bulk Importing using the established single-Model FBX upload and configuration workflow as the baseline. FBX is the current dominant Model file type and the first bulk-import priority.

## Initial scope

- Inspect the existing bulk-import implementation and compare it with the working single-FBX workflow before choosing implementation changes.
- Identify concrete gaps in FBX bulk uploading and configuration, then address them incrementally using the repository's Prove → Act → Document workflow.
- Preserve working single-Model FBX uploading, configuration, and downstream Model use.

GLB/GLTF bulk importing and its texture/buffer requirements are the next planned [v0.19.10b beta milestone](v0.19.10b.md). The alpha implementation stays FBX-only. OBJ improvements remain deferred.

## Development stages

1. **Audit existing importing — complete.** See [Stage 1 findings and acceptance criteria](v0.19.10a-audit.md). The dormant bulk component diverges from current primary-file registration, attachment paths, configuration, and recovery contracts.
2. **Define batch preparation — complete.** See [Stage 2 preparation design](v0.19.10a-preparation.md): FBX selection, shared local texture pool, explicit matching, inherited defaults, import-ready selection, and inactive import for deferred configuration.
3. **Implement bulk importing — implemented.** The dedicated Models workspace now exposes FBX batch preparation and sequential importing, primary registration, saved-file verification, inactive defaults, and guarded retry. Following User testing, **Assign Existing Texture File** adds batch/per-Model saved-Texture selection with verified Base Color assignments during import. Initial files are capped at 4 MiB by the existing deployed transport. See [implementation and validation](v0.19.10a-implementation.md).
4. **Support review and recovery — included in alpha.** Known partial imports retain their Model IDs and Model Files handoff; uncertain creation cannot retry automatically. Confirmed pre-create failures allow correction after staged cleanup. Durable batch resume and automatic reconciliation remain later work.
5. **Validation and deployment recorded.** Automated and mocked-browser validation passed; the User accepted the checkpoint and confirmed successful Vercel production deployment. Detailed per-scenario production smoke results were not separately reported; the deployment preparation record retains the regression checklist.

## Preserved boundaries

- Keep changes focused on Model importing; do not combine repository restructuring with feature changes.
- Preserve authenticated ownership, reusable Model configuration, and Project-instance separation.
- Preserve persistent Canvas/Rapier ownership, stable Runtime Marker identity, and separate GardenCharacter/EcctrlCharacter paths.
- Database schema changes require explicit approval. This boundary does not expand world persistence, MQTT, or physical-device behavior.
