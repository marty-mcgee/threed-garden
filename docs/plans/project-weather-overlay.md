# Project Weather overlay

Phase 1: Weather belongs to the selected Project Scene. Add a bounded, independently scrolling overlay with current readings, observation time, source, alerts and recent history. Opening/reopening reads stored data only; Update Weather is an explicit owner-only operation. Resolve the location from the saved Project Weather override, calibrated Project origin, owned existing OpenWeatherMap source coordinates, then the existing shared ThreeD Weather module defaults (39.3, -123.5). No manual coordinate entry is required to inherit the existing Weather location. Missing coordinates remain an actionable empty state. Project switching/closing cancels stale UI requests without remounting the Scene.

## Existing Weather coordinates integration

Developer explicitly corrected the setup requirement: existing ThreeD Weather coordinates/data sources must populate Weather Settings automatically. WeatherPoller already used latitude 39.3 and longitude -123.5 for both current observations and forecasts. These values now have one shared typed constant reused by the poller and Project resolver. When no explicit Weather override or Project origin is saved, the server first reads valid coordinates from owned OpenWeatherMap rawData.coord records, then falls back to those existing module values. Foreign/unowned records are never read as that owner's source. Settings inputs show the effective inherited location immediately; no Save, calibration, location guess or data migration is needed. Explicit Project overrides remain authoritative. The overlay uses the same resolver and enables Update Weather when the provider is configured.
