# v0.19.10b — ThreeD GLB/GLTF Bulk Importing and Texture Requirements

Status: **released to production**, September 9, 2026, package `0.19.10-beta`, commit `ab5f1ea`. The User manually accepted the final local checkpoint and its build gate, then confirmed successful production deployment. See the [release record](../releases/v0.19.10b.md), [completed handoff](v0.19.10b-release.md) and [implementation record](v0.19.10b-implementation.md).

## Objective and preserved alpha behavior

Extend the bulk importer to GLB and GLTF Models, including their embedded resources, external texture images and binary buffers. Preserve authored materials and support the existing **Assign Existing Texture File** batch/per-Model workflow once GLB/GLTF material-target parity is proved.

The [alpha implementation record](v0.19.10a-implementation.md) is the behavioral baseline. Preserve FBX selection and scanning, stable local identities, shared-file matching, inherited settings and overrides, explicit submission, inactive defaults, saved-Texture assignment, primary registration, saved-file verification, dependency audit, known-Model review links and guarded retry. A beta change must not weaken FBX behavior or relabel the deployed alpha build.

Keep preparation in browser memory and retain sequential imports through authenticated owner-scoped endpoints. Preserve the distinction between Model-owned dependency attachments and reusable Texture material assignments. Keep Base Color as the only bulk assignment channel; retain authored normal, roughness, metallic and other supported maps through the existing loader rather than inventing new assignment controls.

OBJ, ZIP extraction, folder traversal, server-side remote asset import, larger-file transport, durable batch queues and database schema changes remain outside this plan. Single-Model importing is a regression surface, not a separate redesign. Project persistence, Character routing, Canvas/Rapier ownership, MQTT and physical-device behavior remain unchanged.

## Beta resource contract

The implemented target is glTF 2.0 `.glb` and `.gltf` primaries, case-insensitively, alongside the existing `.fbx` path. Version, minimum-version and required-extension checks run during preparation. File availability is shown in preparation; actual resource decoding and material-target discovery run before upload. Rendered appearance remains a manual acceptance check.

| Resource case | Intended preparation and import behavior |
|---|---|
| GLB with embedded geometry and images | Validate container/JSON/resource bounds; do not create artificial image or buffer attachments for embedded resources. Preserve the original primary bytes. |
| GLB with external image or buffer URIs | Classify and match the external resources explicitly. A `.glb` filename must not imply that all resources are embedded. |
| GLTF with relative `.bin` and image URIs | Show separate binary and texture requirements. Match each selected file to the correct Model and destination, then save it with the correct attachment classification. |
| `images[].bufferView` or supported `data:` resources | Treat as embedded resources. Validate referenced ranges, supported encodings/media and bounded decoded sizes; absence of an external filename is not sufficient validation. |
| Missing or invalid external geometry buffer | Block the row. **Resolve missing texture files later** must not waive required geometry or malformed buffer data. |
| Missing external image | Permit an explicit inactive review path only after the chosen loader/target-discovery workflow is shown to support that state. Continue showing unresolved image work; a reusable Base Color assignment does not fulfill the named file. |
| Existing reusable Texture | Preserve batch inheritance, per-Model override, None and active-owner checks. Assign only proved runtime target keys; verify saved target/channel/Texture IDs before activation. Preserve embedded/authored materials when no override is selected. |

Implemented file support is `.bin` for external buffers and PNG/JPEG/static WebP images. Actual Chromium checks prove WebP and `EXT_texture_webp` loading and DRACO decoding through the existing local assets. Alpha's TGA/BMP selection remains available for FBX. KTX2/BasisU, Meshopt, AVIF, GPU instancing, unsupported image formats and unknown required extensions produce an explicit unsupported-row result. The User has accepted the working local checkpoint; retain representative assets and the saved Scene path in production smoke checks.

Local relative URI handling must preserve source identity and a known selection root. Keep safe directories where available; use an explicit Model-owned destination for bare filenames, with `buffers` proposed for `.bin` and the existing `textures` default for images. Match dependency type as well as path/name. A buffer must not satisfy an image requirement merely because a basename matches.

Reject unsupported remote HTTP(S), persisted `blob:`, absolute/workstation, parent-traversal and unsafe encoded references visibly in the initial beta contract. Do not silently omit them, fetch them during preparation or rewrite the Model source to hide them. Stage 1 must define query/fragment and percent-decoding rules that agree with stored paths and the loader; ambiguous or unsupported forms should block the affected row. Preserve current FBX workstation-filename compatibility separately. Supporting a parent-relative GLTF layout within a known bundle root would require its own proved resolution rule.

Retain the implemented bulk ceiling of **4 MiB per selected file**, including primaries, companions and previews, and one attachment per request. Do not present the single upload route's 256 MiB application check as bulk transport capacity. The 100-Model queue and 500-entry companion/resource/inventory limits remain. Beta adds a **32 MiB** bundle budget and decoded-geometry ceiling, bounded graph/accessor complexity, image dimension limits and a 30-second local inspection timeout; exact limits appear in the implementation record. Preview images remain separate from material textures and dependency names.

## Development stages and acceptance

The following stages retain the original acceptance criteria. Stages 1–4 are implemented and covered by offline/Chromium checks. Stage 5 automated validation passes; the User has accepted the local checkpoint and its manual build gate. Production deployment is User-confirmed; the detailed live regression checklist is retained.

### 1. Prove the format and resource contract

Inspect the existing single-Model GLB/GLTF workflow using small, representative local assets. Record asset provenance, declared format/extensions, embedded/external resources, actual preview behavior and gaps in current scanner/server analysis. Compare both GLB readers, URI normalization, buffer byte lengths/ranges and loader behavior; define the initial extension and URI matrix from evidence.

Affected areas: companion and structural inspection, Model Files requirements, upload analysis, `ModelMarker3D`, existing import validators, and the new beta fixture/validation files selected during this stage. This stage does not enable beta writes.

Acceptance: ordinary GLB and GLTF examples have documented resource graphs; malformed/truncated containers, unsafe/unsupported URIs, missing buffers and unsupported required extensions are explicitly identified. Distinguish an inspection limitation from zero external dependencies. Record the intended decoded-resource budget and the unresolved implementation choices below before editing the importer.

### 2. Extend preparation for typed dependencies

Incrementally extend the existing preparation model with explicit primary format and buffer/image requirements. Preserve shared source identities, same-root matching, explicit duplicate-name choices, destination validation, inherited defaults and stale-scan guards. Show embedded resources separately from files the User must supply. Adapt labels so GLTF errors and binary requirements are not described as FBX texture errors.

Affected areas: `ThreeDModelsBulkImport.tsx`, `model-bulk-preparation-core.ts`, companion helpers and preparation validators. Add small pure helpers if necessary; avoid restructuring Model administration in the same step.

Acceptance: selecting or editing any supported format makes no mutation requests. Mixed FBX/GLB/GLTF rows retain their own file types and requirements. Same-name buffers/images in different selections require correct choices; a shared image may serve several Models without satisfying unrelated buffers. Missing geometry blocks only its row even when texture deferral or an existing Texture is selected. Counts, labels and submission use one readiness result.

### 3. Prove GLB/GLTF material-target discovery

Choose a bounded discovery path that reproduces the `GLTFLoader` default-scene object and the existing material inventory. Compare exact `mesh:<index>:material:<slot>` keys and their resolution against the actual preview/runtime object. Do not derive those keys from JSON material indices or assume that declarative geometry inventory ordering is equivalent.

Decide whether discovery runs against a fully selected local bundle or after owned dependencies are saved. External buffers, image loading, decoder workers and object-URL cleanup make this a separate proof from FBX's inert server parse. Do not add unrestricted dependency fetching or change saved target identity to simplify the import path.

Affected areas: GLTF inspection/discovery helpers, upload or an existing owned inspection path if needed, the shared inventory as a preserved contract, runner handoff and focused loader-parity fixtures. Any API change must be identified from the chosen lifecycle before editing; this plan invents no endpoint.

Acceptance: nested nodes, multiple primitives, repeated mesh instances, shared materials, skinned meshes, default-scene selection and supported compressed assets produce the same resolvable keys as Model Files. Empty, truncated or invalid inventories cannot be reported as all assigned. Preserve the complete 1–500 canonical-key requirement for batch saved-Texture assignment. If discovery must follow creation, failure retains a known inactive Model and review link without another create attempt.

### 4. Extend the existing import transaction sequence

Carry the exact primary format through upload response checks, `primaryFile`, Model creation and saved primary verification. Save selected `.bin` attachments as binary and images as textures, one request at a time. Integrate the proved target discovery/assignment lifecycle, readback and dependency audit before any explicit activation.

Affected areas: `model-bulk-import-runner.ts`, upload/Model Files contracts only where inspection proves a gap, and mocked runner checks. Preserve Model creation's primary registration, owner checks, bounded assignment requests, staged-upload cleanup and uncertainty handling.

Acceptance: a ready GLTF persists a correct primary and binary/image attachment set; a self-contained GLB creates no fabricated companions. A stale Texture, failed attachment, invalid buffer, lost assignment response or unknown create response retains the appropriate inactive/review/uncertain result and cannot silently duplicate a Model. Successful unrelated rows continue. Saved Texture assignment does not replace dependency verification.

### 5. Validate the beta across formats and prepare its release boundary

Run the narrow [validation ladder](../agents/VALIDATION.md), extend the existing import/preparation/runner checks, and add actual GLTFLoader/material-parity fixtures. Cover a mixed batch containing successful, invalid, missing-resource, deferred and uncertain rows; verify that only the intended rows are submitted. Keep all FBX and existing-Texture acceptance checks passing.

Use real assets for an embedded GLB, an external-texture GLB, GLTF with `.bin` and images, duplicate filenames in distinct directories, embedded/data resources, supported compression, multiple materials and a skinned mesh. Add corrupt/truncated and unsupported-extension cases. Test near-limit deployed multipart uploads separately from local fixtures. Track small redistributable fixtures with provenance where appropriate; do not make tests depend on the ignored `reference/` directory or unstated external downloads.

Acceptance: saved Models reload with correct buffers, images and Base Color assignments in Model Files and Library/Scene placement. Verify authored materials with None selected, a batch Texture across multiple Models, row overrides, missing-resource messages, inactive deferral and explicit activation. Repeat single-Model FBX/GLB/GLTF importing and the affected Character/Scene regression checks; maintain stable Project markers, Canvas and physics ownership. Offline orchestration tests alone do not establish appearance or deployed transport behavior.

Set the package to `0.19.10-beta` only when beta development is explicitly begun after the alpha deployment boundary is recorded; do not relabel the accepted alpha build as beta. Record beta production readiness and deployment separately, following the [release index](../releases/README.md).

## Resolved implementation decisions and remaining proof

- Discovery runs locally before any upload against an immutable capture of the selected primary, companions and settings. It uses the actual default GLTF scene and shared material inventory. Original bytes are uploaded unchanged.
- The loader can inspect an explicitly deferred image using an internal one-pixel placeholder while preserving scene topology and material keys. That placeholder is never saved; the missing image remains a named dependency and the Model remains inactive.
- The supported URI, extension and resource limits are enforced in a separate pure bundle helper and browser inspector; existing scanners, APIs and runtime loaders retain their contracts.
- Original synthetic fixtures prove embedded/external/data resources, PNG/JPEG/WebP, DRACO, nested/repeated/skinned meshes and authored PBR map preservation. No private vendor assets or external downloads are required by the validators.
- The User accepted the local checkpoint. Authenticated upload, Model Files reload, final appearance, Library placement and near-limit deployed transport remain in the production smoke checklist; no per-asset inventory is inferred from the general acceptance.
