# v0.22.6 — ThreeD Traffic Module Import

This release candidate introduces `ThreeD Traffic` as a supported App Module through `npm run traffic:import`. The version-1 seed creates one private, active Traffic module. Its `projectIds` list is empty, as requested, so neither Project 8 nor Project 15 receives an assignment during this import. Each Project can receive its own assignment later without changing the module record.

The importer validates the JSON offline by default. `--commit` loads the checkout's `.env.local`, verifies the target user and ownership of every requested Project, and creates missing module and assignment rows in one transaction. Reruns preserve matching records. This increment uses the existing Traffic and Project-Traffic schema and does not import live or historical CHP, Caltrans, 511, or Cal Fire feed rows. It adds no Scene behavior or database migration.

The User authorized the initial write to the shared Neon database used by this checkout and Vercel Production. The first committed run created one `threed-traffic` module and zero assignments for the owner of Projects 8 and 15. The second committed run created zero modules and preserved the existing one. Readback confirmed one active, private module with zero assignments. Existing `traffic-main` and `demo-farm-traffic` records were preserved.

Validation: offline dry run and malformed-file rejection passed; `npm run validate -- project-templates`, `npm run typecheck`, and `npm run validate -- ci` passed. `npm run build` passed, and the local development server was restored on port 4444 after the build. Final diff review passed with `git diff --check`. Code remains uncommitted for User review; production deployment is a separate step.
