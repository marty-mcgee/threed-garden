## Interactive garden hero

Approved first increment: an isolated, read-only miniature garden canvas beside the introduction, with orbit/zoom, reset, planning dimensions, forest-green presentation and a Scene link. Inspection found no bundled GLB/GLTF garden models; the shared PlantModel is a placeholder. The demo therefore uses procedural geometry rather than private database assets or the full Project runtime.

Implemented `src/components/home/GardenHero.tsx` and `GardenHeroCanvas.tsx`, integrated in `src/app/page.tsx`. The scene contains a raised bed, eight plants, a potted plant, stepping stones, a half-meter grid and labeled dimensions. Lighting and shadows give the geometry depth. The separately loaded canvas uses demand rendering, capped pixel density and a brief orbit introduction that stops on interaction. Reduced-motion preferences disable that introduction. Intersection/document visibility pauses rendering offscreen or in a hidden tab. Reset restores the initial camera without remounting the scene.

An inline SVG garden illustration remains visible during loading and replaces the canvas on initialization errors or context loss. Controls retain textual instructions and an accessible reset button. The existing music player, Project Canvas, physics and persistence paths are untouched. No dependencies or remote assets were added.

### Hero fallback correction

User browser review exposed the live canvas switching to the static poster shortly after mounting. The installed R3F Canvas renders its `fallback` prop as ordinary canvas children, including on supported browsers. The initial Unavailable component incorrectly called onFailure from its mount effect, tearing down a healthy canvas. Replaced it with inert fallback text; actual Canvas errors still reach the error boundary, and actual context loss retains its listener. A runtime server-render probe against installed R3F confirmed fallback is rendered inside the canvas rather than being an error-only branch. TypeScript and diff checks passed. The User subsequently accepted the corrected browser experience and confirmed production deployment.
