The User-owned production build and deployment are not yet confirmed. Current confirmed production is v0.20.9. See the [release handoff](v0.20.10-release.md).

## Proven problems and acceptance criteria

The User reported `ThreeDModelFormValidationError: Model file path is required` when saving Edit Model while an attached primary file was selected. The attachment picker changed only `mainModelFileId`, but the shared payload builder always required `filePath`. The PATCH API already validates primary-file IDs against the authenticated owner, Model and attachment type, and resolves file authority server-side.

Expected validation errors were also passed to `console.error`, producing a development error overlay. The Edit dialog scrolled its title and Save button with the entire form, and its row-based two-column grid left large gaps beneath short sections.

Acceptance: Edit can submit an assigned primary file without a cached URL; Create still requires its upload path; invalid input remains guarded; validation failures retain edits and appear inside the dialog; actions remain accessible while the form scrolls; save/close cannot race an upload. Preserve primary File authority, existing API ownership checks and all unrelated Model/Character runtime behavior.

## Changes

- `model-admin-form-core.ts`: explicit Create/Edit payload mode; Edit accepts a positive primary-file ID without requiring a redundant URL. Missing files and invalid IDs still fail validation.
- `ThreeDModelEditorFields.tsx`: choosing an attachment synchronizes its ID, URL and size. Prevent selection changes while a replacement upload is staged. Disable fields during uploads, bound the attachment list height and use section headings instead of unattached labels. The unassigned placeholder is not a detach action; file removal remains managed by the existing Files workspace.
- `ThreeDModelsCRUD.tsx`: Edit validation/API errors appear in an alert beside persistent Save/Cancel controls and keep edits intact. Expected validation errors no longer call `console.error`. Save/close are guarded during uploads. The Edit overlay has a fixed header/footer, a scrollable body and responsive independent columns, scoped to this dialog. The header names the Model and explains when changes are saved.
- `validate-threed-model-admin-form.cjs`: exercise the real payload builder for assignment-only Edit, missing/invalid assignments, Create compatibility, uploaded replacements and existing JSON/transform validation.
- `package.json`: candidate version `0.20.10`.

No schema, API, environment, dependency or global stylesheet changes.

## Panel opacity slider correction

The User reported coupled slider movement. `PanelAppearance.tsx` raised Hover with Default via `Math.max`, used Default as Hover's moving minimum, and rejected persisted Hover values below Default. Both sliders now retain fixed 0–100% bounds (expanded at the User’s request) and update only their own value; saved values allow either ordering. Reset remains 80% Default / 98% Hover. The code inspection explains coupling and shifting thumb positions; it did not independently reproduce a numeric zero.

`workspace-settings` now exercises the actual provider and slider handlers with mocked browser storage: independent changes, fixed bounds, CSS variables, reload with Hover below Default, zero-valued preferences/CSS opacity and reset all pass. TypeScript and diff checks pass. The User accepted the revised slider behavior; retain drag/keyboard checks in the smoke checklist. No build run.

## Explicit Save for panel opacity

At the User's request, opacity no longer auto-saves on slider changes. `SettingsManager` owns an opacity draft and includes it in the page's dirty state, Save Changes, Discard, Refresh confirmation and unload warning. Changes preview only within the Settings card; saved values continue controlling Scene panels until Save. Opacity remains browser-local and does not add database schema or account preference fields. Opacity-only saves do not issue account writes. Combined saves persist account changes first; a failed browser write keeps the opacity draft dirty and displays an error for retry.

The panel button is now **Reset Defaults** and stages 80% / 98% until Save. Both sliders remain independent with 0–100% ranges. Browser-storage failure no longer applies an unsaved global opacity value. The earlier automatic-save description applies only to the pre-change implementation.

Validation: TypeScript, workspace-settings and shadcn-ui-boundary passed. Form fixtures cover no persistence on edit, opacity-only Save, Discard, confirmed/cancelled Refresh, storage failure retention and staged Reset Defaults. Verify live browser preview, Save/reload and Discard before release. No build run by the agent.
