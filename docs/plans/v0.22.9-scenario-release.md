# v0.22.9 — ThreeD Scenario Setup and Start

**Release candidate.** Package and lockfile are set to `0.22.9`; this checkout remains uncommitted. Production deployment is a separate User gate.

## Scope

Admin saves versioned Soccer/Farming setup with a Project Model marker and optional Soccer Sensor Group. The Dashboard loads an active Scenario through **Templates (Choose a Scenario)** and preselects its saved setup in the Guide. Legacy outlines remain unconfigured until deliberately edited. Readiness checks inspect current Project assignments; they do not persist proof of working physics. **Start Scenario** closes the Guide, presents a short instruction card, and, for Soccer, opens the relevant Physics Sensor counts. Starting does not alter assets or reset counts. The Dashboard uses the focused chooser instead of duplicating the Admin saved-list CRUD panel.

Scene instruction and sensor cards now share a responsive rail. Project Assets dims the instruction card while counts stay visible; central setup panels and menus dim both. Dimmed cards remain mounted but leave pointer and keyboard interaction. Closing the foreground panel restores them without resetting session counters. The Admin Scenario list and shared CRUD remain available.

The follow-up Project Save change persists the selected Scenario, current Guide choices, started status, and instruction/Sensor/panel visibility in the existing versioned Project view-state JSON. Project IDs guard restoration; switching Projects clears the prior selection before the new Project loads. Sensor counts themselves remain session-only. Physics Debug once again enables Rapier's full active-collider wireframes instead of showing only the custom Sensor guides. No additional database schema is required for Project UI-state persistence.

## Data rollout

The additive [setup migration](../releases/sql/threed-scenario-setup.sql) adds nullable `public.threed_scenarios.setup` JSONB. The migration is prepared in the worktree; its application to the target production database has **not been independently verified** in this release preparation. Verify the column exists before deploying v0.22.9. If absent, review and apply the SQL first. Existing rows stay `NULL` and must be edited to save their setup. Do not infer setup from their title or description. Keep the migration and application code in the same release review.
