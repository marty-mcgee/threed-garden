# v0.20.3 — ThreeD Model Library Collections

Status: proposed plan. Package remains `0.20.2` until implementation begins. The v0.20.2 Scene Workspace + Inspectors release candidate is the starting checkpoint.

## Product goal

Make **Add to Scene** a concise, browsable Model Library. A User should be able to start with a meaningful collection such as **Soccer** or **Farming**, find an eligible Model, understand whether it is ready, and place it through the existing placement flow.

This is a library-presentation version. It does not alter the Scene workspace, DetailsCard inspector contract, Runtime Marker identity, Rapier world, collision behavior, sensors, camera behavior, or FarmBot command boundary.

## Screenshot findings carried forward

The screenshot shows the former overloaded parent inspector: the selected Soccer Field included the full editor for both attached sensors, while the Project Assets hierarchy also repeated those sensor identities. v0.20.2 resolves that with one focused inspector at a time. v0.20.3 must preserve that result:

- Project Assets remains the Project-owned hierarchy and selection surface.
- The DetailsCard slot presents one selected asset, sensor, or group.
- Environment → Show Sensors remains an optional read-only Scene overlay.
- Add to Scene is a separate library browser. It must never compete with Project Assets for ownership of already placed Models.

## Proven starting point

`ThreeDModelLibraryPanel` already has category, readiness, search, inspection, and placement inputs. It currently presents categories in one flat select menu. The Project Toolbar already opens the library independently from Project Assets and the other toolbar dropdowns.

## Stable numeric checkpoints

### v0.20.3.1 — Define collection authority

- **Proof:** Inspect existing Model category records, category slugs, readiness values, and current library filtering. Record which categories are assigned to the Soccer and Farming demonstration Models, without inferring categories from names.
- **Act:** Normalize only the client-side collection view from the existing assigned categories. Keep the current category records as authority; do not add schema fields or hard-code a Model into a collection.
- **Validate:** Add a focused collection/filter validation that proves a Model can appear in multiple assigned collections, unassigned Models remain reachable through All Models, and readiness filtering still applies.
- **Resolution:** The library has a trustworthy collection input without changing stored Model data.

### v0.20.3.2 — Grouped Add to Scene navigation

- **Proof:** The flat category select makes collection browsing hard to scan and gives Soccer/Farming no first-class presentation.
- **Act:** Replace the flat category-first entry point with a compact grouped browser: All Models plus assigned collection headings, each with a Model count. Keep text search and readiness filters. Selecting a collection changes only library results and never selects, focuses, or changes an existing Project asset.
- **Validate:** Browser acceptance: open Add to Scene from Soccer and Farming Projects; change collections, search within a collection, clear search, and confirm Project Assets stays unchanged. Verify only one toolbar dropdown remains open.
- **Resolution:** Users can browse their own assigned collections before inspecting a Model.

### v0.20.3.3 — Placement-ready Model cards

- **Proof:** A collection label alone does not tell a User which Model can be placed or why another one cannot.
- **Act:** Present each library result with its existing readiness badge, short type/category metadata, and the established Inspect/Place affordances. Keep a single selected library Model and use the existing one-shot placement request. Do not add free-form Model transforms.
- **Validate:** Browser acceptance: inspect a ready Model, begin placement, cancel, place once, and confirm the new Project asset uses the existing Runtime Marker path. Verify needs-configuration and unavailable Models do not create markers.
- **Resolution:** Collection browsing leads clearly to the current safe placement behavior.

### v0.20.3.4 — Responsive presentation and durable guidance

- **Proof:** The Model Library shares the same constrained left workspace area as Project Assets and must remain usable beside the focused inspector.
- **Act:** Apply the established workspace-panel sizing, scrolling, and narrow-screen overlay rules to collection browsing. Add user guidance that distinguishes a library Model from a Project Asset and explains category readiness.
- **Validate:** TypeScript, focused library/placement validation, existing `threed-library-placement` and `threed-runtime-markers` checks, `git diff --check`, and User browser acceptance at desktop and narrow widths.
- **Resolution:** Add to Scene remains understandable, responsive, and compatible with the current Scene Workspace blueprint.

## Explicit exclusions

- No schema migration, database command, new package, or external service.
- No automatic category assignment or name-based collection inference.
- No whole-Model TransformControls.
- No FarmBot command, MQTT publishing, or physical-device behavior.
- No changes to generic Physics Sensor Cuboids, Sensor Groups, count semantics, or the persistent Canvas/Rapier lifecycle.

## Acceptance sequence

1. Open **Add to Scene** and choose All Models, Soccer, and Farming collections.
2. Search and clear a search within a selected collection; change readiness filters.
3. Inspect a ready Model and place it once; cancel a second placement attempt.
4. Confirm Project Assets lists the resulting placed Model while the library remains separate.
5. Open Environment and Project Tour in sequence; confirm toolbar-menu exclusivity and retained Project Assets visibility.
6. Repeat on a narrow viewport and confirm library scrolling and close controls remain reachable.
