# v0.19.43 — ThreeD App Legacy Code Cleanup: Project Toolbar

Status: released to production; deployment User-confirmed September 20, 2026. Released package `0.19.43`. See the [production handoff](v0.19.43-release.md) and [release record](../releases/v0.19.43.md).

## Objective

Reduce legacy Project Toolbar code and visual duplication while preserving the v0.19.42 toolbar as the authoritative Project navigation surface. Cleanup must remove complete unused behavior paths rather than merely hide their buttons, and must preserve Project Save, Project loading, Scene orientation, Runtime Marker identity and the persistent React Three Fiber/Rapier world.

## Proven current state

The Project Toolbar currently contains:

- 3D, 2D and Combined view selection;
- Project Tour;
- Environment;
- Add to Scene;
- active Scene-operation status;
- Project Assets;
- a legacy global Filter trigger;
- full Project Refresh; and
- far-right explicit Project Save.

The legacy global Filter path is separate from current workspace filtering. It owns `showFilterPanel`, `filterText`, `filterActiveOnly` and `filterAssetType` in the Dashboard page, renders `ThreeDSceneFilterPanel` as a full-width strip below the toolbar, and passes presentation filters through `UnifiedMapView` to Runtime Markers and traffic incidents. Project Assets already provides scoped name/type filtering, and the Model Library has its own search/category/readiness controls.

Refresh still performs an explicit Project data reload and is not equivalent to Project Save. The bottom-left geographic compass and bottom-right Three.js view gizmo are Scene orientation tools rather than Project Toolbar controls. Gizmo visibility is part of saved Project view state.

## Proposed release boundary

### 1. Remove the legacy global Filter UI and its complete state path

User-approved scope:

- remove the Project Toolbar Filter button and active-filter dot;
- remove `ThreeDSceneFilterPanel` from the Dashboard composition;
- remove page-level filter-open, text, active-only and asset-type state when no remaining caller requires it;
- remove filter props and derived filtering branches from `UnifiedMapView` only after proving that Project Assets, Scene Layers and module workspaces cover the retained workflows;
- delete the unused panel component only after repository-wide reference checks pass.

The cleanup must not change Project Assets search/type filtering, Model Library filtering, Scene Layer visibility or Project ownership rules.

### 2. Remove the standalone legacy Refresh path

Repository-wide inspection confirmed that the toolbar was the only caller of the manual refresh wrapper and `refreshing` state. Remove the button, wrapper, loader option and unused state while preserving normal initial Project loading, Project switching and sequenced request cancellation.

### 3. Preserve or deliberately consolidate Scene orientation widgets

The compass communicates geographic north. The Three.js gizmo provides camera-axis orientation and clickable view changes. They are related but not identical. Preserve both unless the User explicitly selects one for removal. Any consolidation must retain North-Up behavior, saved gizmo visibility, camera controls and mobile accessibility.

### 4. Tighten toolbar contracts

- remove obsolete props, imports, state setters and comments exposed by the approved cleanup;
- keep Project Tour, Environment and Add to Scene as explicit open/close menu controls;
- retain Project Assets, active-operation cancellation and far-right Save;
- keep the shared `#111A28` elevated-surface and `#0B0B0B` Project-toolbar blueprint;
- preserve narrow-screen wrapping and accessible names, expanded state and focus behavior.

Do not combine this cleanup with Ground Map behavior, schema changes, marker CRUD changes, Character runtime work or Rapier changes.

## Acceptance criteria

## Development checkpoint 1 — global Filter and manual Refresh removal

Implemented September 20, 2026:

- Removed the Project Toolbar Filter and Refresh buttons, their props and icon imports.
- Removed the full-width `ThreeDSceneFilterPanel`, deleted its component and removed its open/text/active/type state plus stat-filter handler.
- Removed the legacy filter props and approximate marker/traffic filtering branches from `UnifiedMapView`. Layer configuration and established module visibility continue to determine Scene presentation.
- Preserved Project Assets name/type filtering, Model Library search/category/readiness filtering and Scene Layer visibility.

## Development checkpoint 2 — shared App Header

The Dashboard and Admin layouts previously maintained separate header implementations. The Dashboard header included a decorative system-status claim while the Admin header included an unwired search field and notification badge. Their heights, surfaces, controls and responsive behavior had diverged.

The layouts now use one shared App Header contract:

- compact product identity on the Dashboard;
- consistent Dashboard/Admin surface switching with current-page semantics;
- Settings-driven global navigation and browser theme control on both surfaces;
- retained authenticated account menu in Admin;
- shared `#111A28` menu surface, border, focus and blur treatment; and
- responsive icon-first controls at narrow widths.

The unwired Admin search and notification controls and the decorative Dashboard system-status claim were removed. Authentication, routing, workspace settings and Admin sidebar behavior remain unchanged.
The legacy product slogan was also removed from the Dashboard brand block, leaving the App name as the single header identity.

### Blueprint color consolidation

The navigation hierarchy now uses two explicit colors instead of several competing near-black theme values:

- `#111A28` identifies the main App Header, elevated menus, Admin sidebar and workspace panel family;
- `#0B0B0B` identifies the Project Header/Toolbar and the deepest App shell background.

DetailsCards and Scene panels retain their established 50% resting and 82% hover/focus opacity behavior using the updated `#111A28` base.
