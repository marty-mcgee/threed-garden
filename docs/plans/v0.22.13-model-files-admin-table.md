## Read-only API and ownership boundary

`GET /api/threed/models/files/list` accepts `search`, `modelId`, `fileType`, `role`, `limit`, `offset`, `sort` and `direction`. Unknown and duplicate keys are rejected. Search is limited to 200 characters and rejects NUL; SQL wildcard characters are searched literally through bound values. Model IDs must be positive PostgreSQL integers. Limit defaults to 50 and is bounded to 1–200; offset is bounded to 0–2,147,483,647. File types are the existing `model|texture|binary|other|animation` classifications; role is `primary|supporting`. Sort is `name|path|model|type|role|size|loadOrder`, direction `asc|desc`, default name ascending.

Authenticate before reading. Inner join File to its parent Model and require **both** owner IDs to match the session. An optional parent guard gives the same 404 for missing and foreign Models. Count and page use the identical joined predicates. Group filename/path/Model-name OR search inside those owner AND conditions. Sort fields/directions are allowlisted, nullable values sort last, and File ID ascending is the final tie-breaker.

The response is `{success,data,pagination:{limit,offset,total}}`. Rows contain only File/Model identities, parent name/type, filename, relative path, classification/settings, size, load order and role; no saved storage URLs, metadata or owner IDs. Every handler response uses `Cache-Control: private, no-store`. There are no storage or mutation calls.

Primary means the assigned geometry File: exact `mainModelFileId`, matching parent/owner, and `fileType='model'`, consistent with existing primary authority. Never infer primary from extension, load order or the first geometry row. Supporting includes retained alternate geometry. Include inactive owned Models. Orphan/unbound/mismatched-owner rows are excluded from the manageable list; embedded resources and unresolved dependencies are not synthetic saved rows. The table does not establish storage availability. Deterministic ordering is for a fixed dataset; concurrent mutations can still change offset pages/counts between requests.
