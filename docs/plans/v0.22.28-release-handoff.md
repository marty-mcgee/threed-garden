## Included

- **Open Scenario** opens a plan; **Run Simulation** executes Actions and collects Results. Simulation definitions and Results have no Scenario columns, foreign keys, indexes or Drizzle relations. CRUD, forms, launch, capture and readiness no longer depend on a Scenario. Historical snapshot/report JSON is retained.
- One-click Scene launch prepares the exact saved Character and target ball through their existing owners, with bounded readiness, visible guidance, Refresh, Stop and collapsed details. A Scenario does not filter, start or interrupt a Simulation.
- Authorized public visitors run locally. Project owners retain private revision/reference checks, capture before dispatch, immutable terminal Results and save-only retry. Private definitions/results remain protected.
- Scenario View uses compact transparent inventory sections, colored icons, title-adjacent help and a green left-aligned Project-assets action. Edit navigation remains exact. Simulation Save blocks active empty definitions with actionable guidance; inactive empty drafts remain savable.
- The Developer's `threed:scenarios:import` script naming remains intact.

Definitions still require Project/module bindings. Removing those bindings, introducing versioned participant roles, choosing context per run and explicitly publishing independent definitions are the next separate refactor. This checkpoint establishes independence from **Scenarios**, not full Project/module independence. General Action executors, cross-Project asset copying, automatic Project saves, MQTT and physical-device operations remain excluded. Preserve the persistent Canvas/Rapier world, separate Garden/Ecctrl paths, retained sources, first-pose/visibility/editing guards and correlated navigation/contact outcomes.
