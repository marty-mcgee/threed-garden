# Design workspace refinements after v0.24.0-beta

October 10, 2026. Version remains 0.24.0-beta. Local implementation only; no live database tests or release operations.

## Inspection and acceptance

`DesignEditor` currently portals drawing tools to the Project toolbar, permanently displays import mode in Properties and applies a selected file immediately. `DesignPlan` owns unsaved local pan/zoom. `DesignWorkspace` owns local split height. `PersistentDetails` uses browser storage rather than the Project snapshot. The Dashboard already captures architecture plus `threeDViewState` through the owner-scoped `/api/project/threed-markers` transaction; `/api/map/threed` loads both. Camera position/target and one selected marker already have capture/restore paths. Additional inspectors and Design preferences are missing from that snapshot.

Acceptance: retain aligned Assets/Properties and Scene/Plan columns; move drawing/navigation icons inside the Plan clear of rulers; stage import with validation/cancel; reuse Assets panel sections/help styling; add bounded optional Design/section/inspector preferences to the existing view-state JSON; preserve source IDs, geometry, unrelated content, Project isolation and pending/failed edits. Restore only available entity references after loading. Camera restoration must survive automatic fitting. Tests use mocked persistence; real authenticated Save/reopen remains manual.

## Implemented contracts

- Drawing and Fit Plan/Zoom to Selection/Reset icons render in the Plan at ruler inset + 8px. Project undo/redo/import/export and the existing Save remain in the Project toolbar. Pointer/wheel events from the overlay cannot reach SVG drawing handlers.
- Import JSON opens the shared App Dialog. File parsing is bounded to 1 MiB and staged. Explicit Import applies the validated merge/replacement with fresh IDs; Cancel, invalid files and stale file reads cannot commit content. Replacement is named explicitly in the selector, feedback and confirmation action.
- Properties shares Assets surface/sidebar classes and PersistentDetails sections, with compact summaries, tooltip help and internal scrolling. Project section preferences use the Project context; nonowner/standalone consumers retain their existing local section behavior.
- Editable source stays in project.config.threeDArchitecture. Workspace preferences stay separately in project.config.threeDViewState: optional design contains Plan x/y/scale, active level, selected architecture ID, level/roof visibility, snap, row split and scoped section booleans. workspace.inspector identifies the supported active asset/Sensor/Group/ground inspector. threeD retains position/target and now optional cameraZoom/cameraFov. No runtime objects, temporary new-Sensor forms, gestures or playback are serialized.
- Existing handleSaveThreeDProject captures the current Project-keyed draft plus live Scene/Map providers. Existing owner-scoped PUT /api/project/threed-markers parses view state, merges config with architecture and saves markers in its established transaction. Existing GET /api/map/threed, session loader and loadData hydrate the same Project. No schema/migration or second Save system was added.
- Inspector restoration waits for Project/Scene and Sensor Groups readiness; deleted references are ignored. Camera restoration waits for controls and applies once per loaded view. Finite nondegenerate saved orbits are no longer rejected merely because their target lies beyond Model bounds (architecture may extend there). Existing orbit constraints and intentional Follow/Topdown behavior still apply.
- Design preferences and scoped section changes DO mark the Project draft dirty. Successful Save acknowledges only captured architecture and Design preferences, retaining newer edits. Existing camera navigation, View Mode and asset/inspector selection retain their prior save-on-explicit-Project-Save behavior: captured every Save, but do not independently turn on the architecture/workspace dirty badge. They are not reset by Save responses. This is not autosave.
- Existing DetailsCard architecture supports one active asset/Sensor/Group/ground inspector, not a new collection of simultaneous pinned cards. Section flags reconstruct UI from current entities. Missing entity/level selections fall back safely. Existing last-committed snapshot concurrency remains; no revision-conflict mechanism is introduced.

## Manual verification still required

1. Open an owned Project with an existing Model. In Design, draw/edit a room, floor and door. Move both views, choose a level, resize the divider, collapse sections and open a Character or Sensor DetailsCard.
2. Save Project, reload, and confirm the Model plus editable geometry, both views, supported card and section state are restored. Confirm the architecture/workspace badge is clean until another tracked edit.
3. Import JSON: cancel a valid file and try an invalid one; neither should change the Project. Explicit merge/replace must preserve unrelated Models; Undo must restore architectural content.
4. Simulate a failed Save, edit during a pending Save, then switch Projects. Verify retained edits, correct dirty state and isolation. Save again to capture any camera/inspector-only changes.

Real authenticated PostgreSQL Save/reopen, existing reported disappearance, production camera/provider timing, concurrent-user writes and mobile/touch acceptance remain unverified. A success message alone is not evidence of persistence. Version remains 0.24.0-beta; no release operation is included.
