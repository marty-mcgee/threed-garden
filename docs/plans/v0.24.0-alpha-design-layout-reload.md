## Proven problem before editing

Read AGENTS.md and CONTEXT.md fully; inspected the actual Dashboard, Design editor, resizable split, legacy `reference/home-design`, API routes and Project schema. The preceding layout kept the 2D Plan beside the Scene and portalled only controls underneath. The required layout is the full-width persistent Scene, horizontal divider, then the complete Design workspace containing toolbar, Plan/rulers and properties.

The reload failure is confirmed in the client hydration boundary, independently of live database state. A new regression asserting `!architectureIsDirty(projectArchitectureDraft())` failed before the fix. `projectArchitectureDraft` constructed normalized history via `designHistory(document)` but serialized the unnormalized default document as its saved baseline. `validateDesign` rounds metre parameters to six decimal places: the raw 96-inch default is `2.4383999999999997`, while history contains `2.4384`. The initial empty placeholder was falsely dirty. Dashboard `loadData` preserved a dirty cached draft instead of installing the loaded API architecture. Consequently saved objects could be returned successfully but remain absent from the client and Scene.

The exact warning is in `src/app/dashboard/scene/page.tsx`, conditional on `architectureIsDirty(architectureDraft)`. It means current source JSON differs from its acknowledged saved baseline; it does not prove a database failure. The warning remains and is now based on a consistent baseline. No browser-storage workaround or label-only change is used.
