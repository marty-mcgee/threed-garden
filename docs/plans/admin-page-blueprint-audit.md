## What the agent skill should ask

Keep one canonical Blueprint skill. Add the page-specific reference only when the requested change touches that workflow. Use these questions when reviewing a proposed UI or API change.

1. **Where else does this page run?** Record the exact route, aliases and query modes. Follow its component into Project tabs, per-record editors and public/Dashboard callers. Identify which host owns URL state, scrolling, preview and return navigation.
2. **Which records can this actor read, change or assign?** Trace the actual schema identity, list and count queries, detail read, mutation, and any Project or parent membership boundary. Capture a mixed-access example. A mounted Admin page or visible button is insufficient evidence.
3. **What happens if the second write fails?** Identify the transaction, revision or partial-success contract. Check whether the UI retains the draft, removes stale selection and reports what actually persisted. Keep retrying a save separate from rerunning an external action.
4. **Which reference and fixture match this operation?** Choose a comparable list, editor, relationship picker or read-only viewer. Record one positive case, one denied or failed case and one navigation case. Label source findings, mocked tests, browser observations and Developer acceptance individually.
