# v0.19.16 — Animations: Character and Model Assignment + Preview Interface

**Current direction: independent Animations Library, optional assignments for all Models, and Character overrides.** Static Models require no animation assignments. Character runtimes consume defaults now; generic Model playback is a later implementation stage. The Model editor and Character assignment/preview workspace are implemented and User-accepted. Scene diagnostic checks pass offline; release scope and deferred gameplay UX are recorded in the final accepted scope below. This supersedes the temporary Character-only direction below.

User-approved development milestone after v0.19.15 (`9157e06`), whose production and documentation releases are confirmed. Package is now 0.19.16 for the released interface checkpoint. No new schema, live database change, automatic retargeting or physical-device behavior is approved by this plan.

## Stage 1 — relationship audit

Repository audit, not a live database/browser assessment. Starting worktree was clean.

| Layer | Current authority and behavior |
|---|---|
| Source | threed_animation_files holds reusable FBX/self-contained GLB source URLs; threed_animations identifies clips by source and clip index |
| Assignments | threed_model_animation_assignments and threed_character_animation_assignments store action-to-clip references or explicit disabled mode |
| API | /api/threed/animation-assignments GET/PUT/DELETE validates owner/action/target; assigned clips must be active with a nonempty source path; DELETE restores inheritance |
| Effective result | contracts.ts resolveAssignments chooses Character override, Model default, then legacy behavior. Disabled stays disabled; unavailable explicit clips never silently fall through |
| Admin | Characters row Animations dialog edits per-action overrides. getAssignments returns the owner-accessible linked modelId, own/inherited assignments, referenced clips and effective state |
| Scene | assignedCharacterAnimations.ts resolves the actual rendered Model's defaults if it differs from the reusable Character modelId; loads each assigned source once per Character load; selects stored index and validates authored track targets |
| Runtime | GardenCharacter and EcctrlCharacter separately await assignment loading, merge clips and preserve semantic mapping/first-pose gates. No shared movement runtime or new mixer control is needed |

Affected audit files: animations/contracts.ts and library.ts, assignment API route, CharacterAnimationAssignments.tsx, assignedCharacterAnimations.ts, GardenCharacter.tsx, EcctrlCharacter.tsx and their existing fixtures.

Concrete gaps:

1. Admin compressed source/state/clip into one line, with no explicit unsaved marker. “Assigned” describes a saved relationship, not verified rig binding or playback.
2. Admin resolves the reusable Character's linked Model, whereas Project instances can use another Model. The editor must disclose this difference rather than promise the same inherited result for every Scene instance.
3. Model default assignment APIs exist, but a dedicated Model assignment editor is absent. Navigation must keep the Animations Library autonomous.
4. There is no Character-with-draft-clip preview. Scene loading is currently the first binding check; node matching is not retargeting or visual compatibility proof.
5. Assignment changes require Scene reload. API 404/inaccessible targets supply no overrides; other request/clip failures use the established loading-error path. This behavior deserves explicit coverage when adding Project-aware diagnostics.

## Stage 3 — first on-request Character clip preview

Proved: existing generic asset previews have no Character action playback. GardenCharacter already owns Model/texture loading and initial semantic action playback, but also registers positions and listens for Scene action events. Acceptance: explicitly requested draft clip preview; no assignment writes, Project mutation or physical world; preserve current runtime paths and hide the character until posed; show source/binding errors.

Implemented Preview clip per Character assignment row when an active explicit clip is selected, including unsaved drafts. It opens an inline iframe at authenticated `/threed/character-animation-preview?characterId=…&animationId=…`; Close preview removes the frame. New owner-scoped single-clip GET on the existing animations endpoint resolves authoritative source metadata rather than accepting a browser-supplied source URL. Character/clip metadata reads are abortable and preview has a 60-second deadline. Error or timeout removes the renderer. The frame uses the reusable Character's linked Model, a stationary normalized pose and normal animation speed, with orbit controls and fitted bounds.

The GardenCharacter preview option loads only that requested clip using existing FBX/GLB source parsing and authored-node checks. Its clone is normalized to idle solely for the established stationary initial-action path; mixer update(0) applies the first pose before reveal. Preview skips global mixer registration, position updates, movement and Scene action listeners. Ecctrl is unchanged. The iframe owns a separate runtime/cache context and no Project coordinator or physics. Ordinary Character rendering omits the preview option and retains its existing path.

Limits: this is a looping clip/rig visual inspection, not the full semantic action's one-shot/crossfade, Ecctrl locomotion, root-motion correction or automatic retargeting. Preview is not yet available for Use defaults/Disabled or generic Models. It does not preview a Project-specific Model replacement. Saving/reloading the actual Scene remains necessary to verify effective mappings and gameplay. Source download limits and parsing use the existing assigned-animation loader.

Validation: TypeScript, assignment-editor tests (draft preview URL/open/close with no Save), assigned-character fixture (real FBX preview binding, source-only load, inactive/wrong-rig rejection), Library API fixture (owner-scoped clip read, invalid IDs and missing clip), animation restart, Character position save, orchestration (18 groups), Runtime Markers (49 groups plus response checks), and diff checks passed. No build/live write/browser visual acceptance claimed.

Manual test:

2. Find Idle (or another action), choose an uploaded animation by name/filename in its dropdown, then click Preview animation before Save. The preview appears directly below that action’s controls.

4. Select another clip and preview again. Try a known incompatible clip and confirm the error rather than a successful-looking preview. Close/reopen during loading to check teardown.
5. Save only when desired, reload the Scene and verify actual action behavior. Test Garden wander and Ecctrl control separately, plus targeted completion/crossfade and saved transforms before release.
