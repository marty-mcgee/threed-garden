## Verification and promotion gates

For each fix: inspect the exact implementation, record reproduction and expected result, make a focused change, add meaningful regression coverage where needed, run TypeScript and relevant offline validations, and update evidence. Persistence tests must use mocks; do not run real database writes, migrations or seeds. Authenticated manual acceptance belongs to the Developer.

Before proposing `0.24.0-rc.1`: resolve release-blocking bugs or explicitly agree on exclusions; record the authenticated acceptance results above; run the maintained offline CI suite and guarded agent-owned `npm run build`; review final changes and update release notes with remaining limitations. A successful Save notification is insufficient evidence. Exact deployed SHA and post-deployment testing remain separately recorded.

Stable `0.24.0` follows successful release-candidate acceptance, not merely completion of the delta version bump. Tagging, publishing, Git writes and deployment require explicit Developer authorization.

Deferred features remain deferred: architectural physics, managed material/catalog bindings, GLB registration, roof joins/hips/overhangs, opening rehosting, stairs, annotation entities and multiple pinned inspectors. Existing snapshot concurrency has no new revision-conflict system.
