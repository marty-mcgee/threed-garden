## Inspection and implementation boundaries

ProjectAssetsPanel previously enumerated runtime markers only. Existing DesignDocument version 5 already contains walls, floors, roofs, hosted door/window openings and hosted roof cutouts/skylights. Dashboard owns Project-keyed drafts and selection; DesignEditor/DesignPlan and DesignSceneObjects already share those IDs, generated geometry and editable properties. Leaflet already shows wall/floor/roof lines and forwards architecture selection.

- Derived inventory: src/libraries/services/threed/design/asset-inventory.ts reads the current authoritative document, with stable IDs, type/level labels and Imperial dimensions. No duplicate records or new schema.
- ProjectAssetsPanel and ArchitectureAssetsSection use the existing search, PersistentDetails, panel CSS, selected-row styles and accessible icon tooltips. Existing Models, Characters and Sensors remain unchanged.
- Dashboard scene/page.tsx passes the active Project document and existing selected ID. Asset selection reveals the selected-properties section. Invalid selection is rejected; edit/delete/Undo reconciliation clears missing IDs. Selecting a Model through Assets clears architectural selection.
- Locate frames the actual DesignPlan using framePlan, waits for its active level and consumes a request once. In 3d/combined it uses the established Scene coordinate focus channel, converting metres with metersPerSceneUnit. In geographic 2d it uses existing geographic conversion and Leaflet fitBounds. View Mode is never changed. The geographic map's existing wall/floor/roof rendering is preserved; hosted openings can be located by footprint without adding map rendering types.
- Transient Locate requests are Project-keyed and cleared on Project switch. Plan framing changes the existing saved workspace pan/zoom; no separate state store or save system.

## Persistence

Architecture remains in project.config.threeDArchitecture through the existing Dashboard handleSaveThreeDProject snapshot, /api/project/threed-markers validation/transaction, /api/map/threed response, session loader and hydrateArchitectureDraft. Workspace preferences retain their established threeDViewState storage. Assets reconstruct from the loaded document; they are never independently saved. Unrelated Models and configuration remain within the existing transaction. No database/schema, physics, material, GLB export, new drawing tools or pinned DetailsCard work is included.

## Acceptance checklist

1. Existing Model remains present while drawing a wall/floor/opening in Design.
2. Every supported entity appears once in the collapsible Architecture section.
3. Clicking a wall selects its shared ID and reveals editable Design Properties.
4. Length/height edits update geometry and inventory dimensions immediately.
5. Canvas selection highlights the matching Assets row.
6. Locate frames the visible Design plan, geographic map or targets the 3D Scene without changing modes.
7. Existing Assets search matches architecture type, ID, level and dimension information.
8. Delete/cascading delete removes entries and clears invalid selection; Undo restores content.
9. Save/reopen reconstructs inventory from saved architecture and retains the original Model.
10. Switching Projects isolates inventories, selection and Locate requests.
