# v0.20.0 Alpha — App Structure, Multimedia + Scene

Status: **released to production; deployment User-confirmed September 21, 2026**. Released package `0.20.0`.

## Release outcome

This alpha establishes the next top-level application structure and removes the split identity between Music and Multimedia. Application libraries now live under `src/libraries`, Multimedia owns media and Speech under one module namespace, and `/dashboard/scene` is the canonical ThreeD Project workspace.

The release intentionally changes infrastructure and naming without changing established ThreeD runtime ownership. Runtime Marker identity, Project Save/Restore, the persistent Canvas/Rapier world, Garden/Ecctrl routing, Character animation behavior, Ground Maps, collision modes, and Project Toolbar behavior retain their existing contracts.

## Included changes

### Source structure

- Renamed `src/lib` to `src/libraries` and updated aliases, imports, executable scripts, Drizzle configuration, editor configuration, and current documentation.
- The primary source structure is now `src/app`, `src/components`, and `src/libraries`.
- Removed the old source directory rather than retaining a compatibility barrel or split ownership boundary.

### Multimedia namespace

- Consolidated the former Music pages, APIs, components, services, data, and schema into Multimedia.
- Canonical routes are `/admin/multimedia`, `/dashboard/multimedia`, and `/api/multimedia`.
- Preserved Album, Track, Media, Link, playback, upload, and Speech concepts within the unified module.
- Updated Workspace Settings and Project templates to use the `multimedia` module key.
- Advanced persisted Workspace Settings to the v2 contract so stale Music-key overrides are ignored safely.
- Removed legacy Music route aliases as part of the approved clean namespace cutover.

### Dashboard Scene route

- Made `/dashboard/scene` the canonical Project Scene route.
- Updated current navigation and generated links to use the Scene route.
- Retained `/dashboard/map` only as a server redirect that preserves the complete query string, including `projectId`.
- Kept `/api/map`, `components/map`, and internal UnifiedMap names where they continue to describe the shared 2D/3D adapter.

### Database cutover

- Replaced disposable `music`, `music_*`, and `project_music` objects with `multimedia`, `multimedia_*`, and `project_multimedia`.
- Replaced the four legacy Project asset enum values with `multimedia_albums`, `multimedia_tracks`, `multimedia_links`, and `multimedia_media`.
- Preserved `multimedia_speech` and `multimedia_speech_versions` data.
- Cleared exactly two orphaned Speech-version Track references after the approved legacy Music deletion, then restored the foreign key to `multimedia_tracks` with `ON DELETE SET NULL`.
- Verified the live schema contains the replacement Multimedia objects, no legacy Music tables, no orphaned Speech Track references, and the retained ThreeD and Traffic asset enum values.
- Changed `db:push` from forced execution to `drizzle-kit push --strict` so future live proposals require explicit confirmation.

The reviewed Neon cutover is complete. **Do not run `bun db:generate` or `bun db:push` again for this alpha candidate unless the source schema changes.**

## Compatibility and boundaries

- Old `/dashboard/map?...` bookmarks redirect to `/dashboard/scene?...` with their query parameters intact.
- Old Music application routes and module keys are deliberately unsupported after the clean cutover.
- Existing disposable Music records were not migrated; the User explicitly approved dropping and recreating that data under Multimedia.
- Existing Speech records and generated Speech metadata remain retained.
- No `.env` file, credential, static animation asset, FarmBot command authority, MQTT publish behavior, or physical-device behavior changed.
- Production deployment is User-confirmed. The production build was completed through the User-owned release workflow; the agent did not run it locally.

## Alpha browser acceptance checklist

1. Sign in and open Dashboard and Admin; confirm shared navigation, Settings visibility, and authenticated Project discovery.
2. Open `/dashboard/scene?projectId=<owned-project>` and confirm the Project reaches 100% presentation with expected Assets, Environment, DetailsCards, Ground Map, and saved view state.
3. Open the same Project through `/dashboard/map?projectId=<owned-project>` and confirm it redirects to `/dashboard/scene` without losing `projectId` or other query values.
4. Open `/admin/multimedia`; create or edit disposable Album, Track, Media, and Link records, then confirm owner-scoped list counts and deletion behavior.
5. Open `/dashboard/multimedia`; confirm album/track discovery, playback, streaming, and private media behavior.
6. Create or revise a Speech record, generate/preview its audio, optionally publish it as a Track, and confirm version history survives refresh.
7. Open Admin Settings; toggle Multimedia visibility, save, reload, and confirm the v2 preference persists without a legacy Music entry.
8. Create a disposable Complete App Project and confirm it receives one ThreeD, Traffic, and Multimedia module foundation with correct Project counts.
9. Recheck one Character Take/Release Control flow, one animation action, one movable-object collision, and explicit Project Save/Restore.
10. Confirm no live application link generates `/admin/music`, `/dashboard/music`, `/api/music`, or a new `/dashboard/map` URL.
