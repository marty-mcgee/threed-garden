Developer requested Character introduction into the ThreeD Scene using React Three Fiber, Drei, Rapier, Ecctrl, lazy loading, simple CSS and post-processing. Scope clarification explicitly includes **placement plus ongoing physics and motion**. Baseline is Developer-reported production v0.22.20. Existing Scene safeguards must be measured before selecting fixes; no particular physics defect is yet reproduced by this inspection. ## Scoped implementation sequence

1. **Measure placement and readiness.** Exercise cold/warm loading, placement on existing supported ground and near Models/Characters, failed rig resources, first pose and Project switching. Record spawn position, supporting surface, capsule clearance and the order of visual/body/control readiness. Use existing diagnostics; keep timing instrumentation temporary or explicitly development-only. A failed resource must show a bounded issue and the established fallback rather than fabricated success.
2. **Repair only reproduced placement/loading failures.** Keep the Project's persistent Canvas/world. Resolve late responses and disposal through their committed owners. Reuse resource caches while preserving fresh animated hierarchies per Character. Add local loading/error presentation where useful; avoid a broad Suspense boundary that removes unrelated physics owners. Preserve explicit Shape rendering and retained rig restoration.
3. **Measure and repair ongoing motion.** Check Ecctrl WASD, jump, slopes, grounding, control transfer, target-relative approach, contact with balls and layer visibility. Check Garden idle/wander and visual/collider alignment separately. Tune or synchronize only the responsible owner when evidence shows a failure; do not globally resize capsules from animated mesh bounds or overwrite saved physics. Ensure a hidden layer disables its matching body's participation without rebuilding the world.
4. **Refine simple presentation.** Reuse Blueprint/shadcn status and controls outside the Canvas. Keep loading messages concise and avoid covering a running Scene when a new Character is added. Provide accessible focus and reduced-motion behavior for CSS transitions. A visual fade must not leave an invisible moving/interacting Character without a deliberate, tested readiness policy.
5. **Evaluate optional post-processing separately.** First prove compatibility with the installed React/R3F/Three stack and examine render cost. Introduce only a small justified effect, with a baseline/off path and no Canvas/world reset. Confirm selection outlines, transparency, shadows and mobile behavior. Do not restore the incompatible wrapper or perform blanket upgrades. Record a decision if the existing renderer meets the introduction requirement without an added effect.

Each step follows Prove → Act → Document and remains independently reviewable. Implementation may touch the evidence-table files and their existing loader/physics helpers; inspect exact call contracts before editing. No schema, persistence expansion, FarmBot operation or repository restructuring is part of this scope.

## Acceptance criteria

- Placement creates exactly one owner-scoped Project Character marker, preserves saved transforms and does not remount unrelated markers, Canvas or Rapier world. Rapid repeat input cannot duplicate placement.
- Cold/warm resource loading has bounded loading/failure outcomes. Current rig first pose, supporting environment and body/control readiness agree with the documented policy. Removal, Project changes and replaced resources cannot publish stale readiness or retain abandoned physics owners.
- Assigned rig, external FBX clips and rigless Shape sources use their established paths. Shape has no fabricated animation completion or contact-point availability. Switching back restores retained configuration.
- Representative rig scales and saved physics values are tested against actual collider clearance, stable rest position, slopes and obstacles. No arbitrary new mass, speed, jump or capsule defaults are introduced.
- Garden idle/wander, Ecctrl idle/walk/run/WASD/jump, Take/Release Control and target-relative navigation remain usable. Layer hide/show preserves ownership and restores only the affected actor. Ground probes continue excluding movable balls.
- Animation assignment precedence and task-to-locomotion crossfade remain intact. World effects remain completion-gated except the existing correlated bounded ball-contact path; no mixer sampling writes physics or persistence.
- Character status/presentation works at narrow widths and with keyboard/reduced-motion settings. Any chosen post-processing has documented compatibility, performance and visual checks with effects enabled and disabled.
- Physics frame-error containment never activates in acceptance runs. Activation, FBX failure, external animation loss, broken control, targeted Water/Pick Fruit or harvest regression is release-blocking.
