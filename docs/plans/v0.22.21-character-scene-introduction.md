### Implementation proof — October 4

Concrete problems: Ecctrl's real rig is visually withheld until `posedModel === model`, but `enable`, the layer body effect and movement frame use Layer visibility alone; a loading actor can therefore fall or accept motion before first pose. The enabled-state cache also ignores replacement body identity. Garden's wander/patrol changes its child Group under a fixed body without moving the body's cuboid, and Garden's Scene load publishes its model without the preview's `mixer.update(0)`. Layer hiding does not stop Garden's movement frame. Finally, movable spawn rejection uses 0.5 horizontal clearance while two installed 0.3-radius capsules need 0.6.

Additional placement proof: Dashboard `handleCharacterPlacement` awaits POST and unconditionally applies the returned marker to current client data. A Project change during that await can insert the previous Project's response into the new Project. Add a Project-session identity guard, including A → B → A and unmount, before client updates or error presentation. Preserve the successful server write to its originally authenticated Project and the existing duplicate-click guard; no retry or compensating deletion is introduced.

Installed Rapier proof: `useChildColliderProps` recomputes automatic colliders only when `options.colliders` changes and uses `traverseVisible`. Garden's async rig publication cannot refresh those mount-time colliders, and an initially hidden Group produces none. Replace only Garden's automatic cuboids with one explicit stable cuboid matching its original cylinder's bounding box (0.4 half extents, center Y 0.4). Keep the cylinder visuals unchanged, avoid deriving physics dimensions from animated meshes, and move selection rings with the Garden Group without making them colliders. This is a stable Character collision proxy, not a claim of precise per-rig mesh collision; scale/obstacle fit remains a manual check.

Explicit-proxy visibility review: gate the Garden owner by both Layer visibility and saved Character visibility, so the newly explicit collider cannot participate for an individually invisible Character. This preserves the original visible-traversal exclusion while allowing an initially hidden Layer to reveal its existing collider later.

Clearance boundary proof: rounded floating subtraction `1.4 - 0.8` is slightly below 0.6, so the touching boundary could disagree with server SQL numeric arithmetic. Compare squared distances in integer millimetres after the same three-decimal rounding; the focused fixture covers a nonzero-origin touching pair.

Controller position proof: installed Ecctrl initializes `currPos` at zero and updates it only in its enabled frame. Because this change pauses Ecctrl until first pose, the control-transfer effect must read the retained body's actual translation rather than the not-yet-updated cache. Apply the same finite position guard to effect/click reporting; the fixture checks a nonzero body with a zero cached position.

## Acceptance criteria

- Placement creates exactly one owner-scoped Project Character marker, preserves saved transforms and does not remount unrelated markers, Canvas or Rapier world. Rapid repeat input cannot duplicate placement.
- Cold/warm resource loading has bounded loading/failure outcomes. Current rig first pose, supporting environment and body/control readiness agree with the documented policy. Removal, Project changes and replaced resources cannot publish stale readiness or retain abandoned physics owners.
- Assigned rig, external FBX clips and rigless Shape sources use their established paths. Shape has no fabricated animation completion or contact-point availability. Switching back restores retained configuration.
- Representative rig scales and saved physics values are tested against actual collider clearance, stable rest position, slopes and obstacles. No arbitrary new mass, speed, jump or capsule defaults are introduced.
- Garden idle/wander, Ecctrl idle/walk/run/WASD/jump, Take/Release Control and target-relative navigation remain usable. Layer hide/show preserves ownership and restores only the affected actor. Ground probes continue excluding movable balls.
- Animation assignment precedence and task-to-locomotion crossfade remain intact. World effects remain completion-gated except the existing correlated bounded ball-contact path; no mixer sampling writes physics or persistence.
- Character status/presentation works at narrow widths and with keyboard/reduced-motion settings. Any chosen post-processing has documented compatibility, performance and visual checks with effects enabled and disabled.
- Physics frame-error containment never activates in acceptance runs. Activation, FBX failure, external animation loss, broken control, targeted Water/Pick Fruit or harvest regression is release-blocking.
