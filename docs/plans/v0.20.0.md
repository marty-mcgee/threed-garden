# v0.20.0 Alpha — Top-Level App Structure + Multimedia Namespace

Status: **released to production; deployment User-confirmed September 21, 2026**. Released package `0.20.0`. The source, route, Multimedia namespace and reviewed Neon cutover stages are complete.

The accepted final v0.20.0 cleanup candidate is documented in [the final release handoff](v0.20.0-release.md). It adds the validation dispatcher, shadcn/ui ownership boundary, unified Radix dependency, and unused-package cleanup without changing the completed infrastructure or database cutover.

## Milestone goal

Establish the next major source, product-module and Dashboard route structure:

1. rename `src/lib` to `src/libraries`, producing the top-level source organization `app`, `components`, and `libraries`;
2. rename the App module **Music** to **Multimedia** across code, routes, settings keys, schema identifiers and physical database objects; and
3. rename the ThreeD Project workspace route from `/dashboard/map` to `/dashboard/scene`.

The v0.19.43 production checkpoint is the rollback and comparison baseline. Each milestone below is a separate approval and validation gate. Directory restructuring, route changes and schema replacement must not be combined into one unreviewable change.

## Proven current state

### Source library directory

- Before Stage 1, `src/lib` contained 329 files across auth, configuration, data, database, Project assets, schema, scripts, services, stores, types and utilities.
- 291 source files imported through the `@/lib` alias.
- Drizzle explicitly read `./src/lib/schema/index.ts`.
- Validation scripts and source-relative fixtures also resolved files beneath `src/lib`; changing only the TypeScript alias would have left executable scripts and tooling behind.

This is a mechanical repository move with a large reference surface. It must not include feature behavior, schema, route or naming changes.

### Music and Multimedia namespaces

The App already presents some Music features as Multimedia, but its implementation is split:

- existing Music routes: `/admin/music`, `/dashboard/music`, `/api/music`;
- existing Multimedia speech routes: `/admin/multimedia/speech`, `/api/multimedia/speech`;
- existing code directories: `components/music`, `components/admin/music`, `services/music`, `data/music`, `schema/music`;
- existing Multimedia code: `services/multimedia` and `schema/multimedia`;
- persisted configuration keys still use `music`, including Workspace Settings module visibility and Project module metadata.

The Music schema currently declares:

- `music`;
- `music_albums`;
- `music_tracks`;
- `music_media`;
- `music_links`;
- `music_polling_logs`;
- `music_playback_history`;
- `project_music`; and
- the `music_link_type`, `music_link_status`, and `music_polling_type` enums.

The Project asset enum also contains `music_albums`, `music_tracks`, `music_links`, and `music_media`. The existing Multimedia schema separately owns speech tables. The target design must merge these under one Multimedia module without deleting or conflating the existing speech feature.

The User has declared Music module data disposable. No data-copy, compatibility-view or legacy migration script is required. This authorizes planning for destructive replacement of the listed Music module objects, but database changes remain a specific execution gate using only `bun db:generate` and `bun db:push` after the generated proposal is reviewed.

### ThreeD Project route

- `src/app/dashboard/map/page.tsx` is the current Project-session composition root.
- 11 source files and validation scripts reference `/dashboard/map`; 23 documentation files mention it.
- `/dashboard/threed` currently redirects to `/dashboard/map`.
- Dashboard cards, global navigation, Admin helpers and validation fixtures generate the Map URL.
- Internal types and components use historical names such as `UnifiedMapView` and `UnifiedMapData`, but those components still legitimately bridge Leaflet 2D and ThreeD presentation.

## Route decision

Use **`/dashboard/scene`** as the canonical route.

“Scene” matches current product language: ThreeD Scene, Scene Layers, Add to Scene, Scene panels and Scene presentation. “World” suggests a broader container for multiple scenes, streaming regions or world simulation that the current Project workspace does not yet implement.

For the Alpha transition, `/dashboard/map` should become a small server redirect that preserves the complete query string, including `projectId`. This protects bookmarks and deployed links without retaining duplicate workspace implementations. New code, navigation and documentation must generate `/dashboard/scene` only.

Renaming `UnifiedMapView`, `UnifiedMapData`, the `/api/map/*` family or the `components/map` directory is outside the route step. Those names describe the still-supported combined 2D/3D adapter and require a separate ownership review.

## Target Multimedia vocabulary

The target module key is `multimedia` everywhere a top-level module identity is represented.

| Current | Target |
| --- | --- |
| `music` module key | `multimedia` |
| `/admin/music/*` | `/admin/multimedia/*` |
| `/dashboard/music/*` | `/dashboard/multimedia/*` |
| `/api/music/*` | `/api/multimedia/*` |
| `schema/music` | merged into `schema/multimedia` |
| `services/music` | `services/multimedia` |
| `components/music` | `components/multimedia` |
| `components/admin/music` | `components/admin/multimedia` |
| `data/music` | `data/multimedia` |
| `music` table | `multimedia` |
| `music_*` tables/enums | `multimedia_*` |
| `project_music` / `projectMusic` | `project_multimedia` / `projectMultimedia` |
| `music_id` / `musicId` | `multimedia_id` / `multimediaId` |
| Project `moduleType: 'music'` | `moduleType: 'multimedia'` |
| Workspace Settings `modules.music` | `modules.multimedia` |

Domain terms such as Album, Track, playback and audio may remain where they describe actual media concepts. The rename concerns the top-level module and ownership namespace, not ordinary English uses of “music” in titles or metadata.

#### Stage 4 generated-proposal review — blocked before push

Reviewed September 21, 2026. The source schema replacement is implemented and passes TypeScript plus the real Drizzle metadata validator. It unifies Albums, Tracks, Media, Links, playback, polling and Speech in `schema/multimedia`; declares `project_multimedia`; and changes the four Project asset enum values to `multimedia_*`.

The first generated proposal was rejected and its generated artifacts were removed. It correctly limited table replacement to the disposable Music family, preserved the two `multimedia_speech*` tables and did not alter ThreeD, Traffic, Auth, Settings or FarmBot tables. Two ordering/data hazards make it unsafe to apply unchanged:

1. `project_assets.asset_type` cannot cast existing `music_*` values into an enum that contains only `multimedia_*` values.
2. `DROP TABLE music_tracks CASCADE` can remove the Speech Track foreign key before the later generated `DROP CONSTRAINT`, causing that later statement to fail.

Required Neon preflight before `bun db:push`:

- stop writes to the old Music/Multimedia endpoints during the cutover;
- remove Project Asset assignments whose asset type is one of `music_albums`, `music_tracks`, `music_links` or `music_media`;
- drop the disposable `project_music`, `music`, `music_albums`, `music_tracks`, `music_media`, `music_links`, `music_polling_logs` and `music_playback_history` tables, allowing the obsolete Speech-to-Track foreign key to be removed with the old Track table;
- drop the disposable `music_link_type`, `music_link_status` and `music_polling_type` enums after their tables are gone;
- retain `project_assets`, every non-Music Project Asset row, `asset_type`, both `multimedia_speech*` tables and all unrelated schema families; and
- inspect the live `db:push` proposal after this cleanup. It must create only the Multimedia replacement objects, update `asset_type`, and restore the Speech-to-Multimedia-Track foreign key.

The package `db:push` command now uses `--strict` instead of `--force`, ensuring future live proposals require explicit confirmation. The rejected generated SQL and snapshot were deleted so they cannot be applied accidentally.
