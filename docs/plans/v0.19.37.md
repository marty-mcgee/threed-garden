# v0.19.37 — ThreeD Projects: Save + Restore State

Status: User accepted this checkpoint for production release; release preparation complete. Broader remaining stages are follow-up scope. Current production is User-confirmed v0.19.36. No implementation or schema changes in this planning step.

## Goal

Explicit Save Project should capture the current Project and its browser workspace in the database. Opening or refreshing that Project should present the saved Scene and workspace as closely as possible across all Projects, with responsive layouts and current asset availability respected.

## Proved starting point

`src/app/dashboard/map/page.tsx` captures marker snapshots and versioned view state through registered providers, then calls `PUT /api/project/threed-markers`. `src/app/api/project/threed-markers/route.ts` saves markers and `project.config.threeDViewState` in one transaction. Project loading restores view mode, panel height and camera mode through the existing Project session path.

`src/lib/services/threed/markers/project-view-state-core.ts` defines and validates camera position/target, map view, layer visibility, environment, sunlight, extra ground and Scene display toggles. `src/components/map/ThreeDScene.tsx` captures and restores these settings after controls become ready. Named camera presets currently use browser localStorage. Selection, open workspace panels and DetailsCard expansion require further inventory before extending the contract.

Root CONTEXT.md is absent after prior User cleanup; archived context is historical reference only. Current implementation and production release records govern this plan.

## State policy

Persist useful durable presentation: marker transforms and supported instance settings, camera/map views, Scene environment and layers, selection and workspace preferences. Keep Project settings separate from reusable source-asset settings. Determine whether accessibility/theme preferences belong to a user profile or the Project before persisting them; do not override a User's current accessibility preferences on load.

Do not serialize browser internals, credentials, loaded meshes, animation mixers, collision caches, requests, loading/error flags, hover, pointer coordinates, in-progress placement/edit drafts or pending world actions. Character control remains explicitly engaged by the User after load. Save must not replay an animation, harvest, physical-device operation or interaction. Velocity and animation-frame continuation are outside this checkpoint; saved physics objects restart at their saved resting transforms with their configured physics options.

## Acceptance criteria and boundaries

A successful save followed by reload reproduces the supported saved transforms, Scene appearance, view and workspace. Capture and restore coverage is documented per field; unsupported/transient state is explicit. Missing optional references fall back locally without losing valid Scene state. Failed saves do not claim success or discard the current workspace. Older Projects remain loadable and state never leaks between Projects or owners.

Preserve persistent Canvas/Rapier, stable marker identity, GardenCharacter/EcctrlCharacter separation, semantic FBX mappings, first-pose readiness and action/world-effect boundaries. No cross-project borrowing, automatic database writes on movement, harvest persistence expansion, MQTT commands or repository restructuring.
