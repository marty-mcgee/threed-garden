# v0.21.0 — ThreeD Tooling: Node.js + npm

## Status and scope

On September 26, 2026, the User approved replacing Bun with npm after Bun runtime failures in Next.js builds, validation and interactive Drizzle tooling. This supersedes the earlier Bun Stability direction. At the User's request, the unreleased v0.20.13 checkpoint was renumbered to v0.21.0 to mark the package-manager transition. v0.21.0 is released to production, User-confirmed on September 26, 2026; repository release commit `b7ae9a8`.

## Proven problem and acceptance criteria

The manifest selected Bun, CI installed Bun, and Multimedia import and the FarmBot worker explicitly invoked Bun. The reported Bun 1.3.9 build failed during Next's CommonJS runtime loading and crashed natively. The same build command invoked through npm passed. The Snap-installed Bun environment also redirected Node subprocesses during validation.

Affected tooling: `package.json`, the dependency lockfile, `.github/workflows/validation.yml`, `.nvmrc`, and active developer documentation. Acceptance: a fresh `npm install`, Node-only entry points, successful TypeScript and offline validation, and a working development startup. Preserve existing app behavior, the User's `npm start` development shortcut, strict Drizzle confirmation, and unrelated working-tree edits. No database push, broker/device operation, deployment configuration change or production build by the agent.

## Implementation

- Node 24.x and npm 11.x are declared in `engines`; `packageManager` records npm 11.6.2 and `.nvmrc` selects Node 24.
- `package-lock.json` replaces `bun.lock`. Fresh installation preserves every existing direct dependency version, including Next 16.3.6 and next-auth 5.0.0-beta.32.
- `tsx` 4.22.4 is an explicit runtime dependency for existing TypeScript utilities, Multimedia import and the FarmBot worker. These commands use `node --import tsx`.
- CI uses Node/npm, `npm install`, a lockfile-change check, TypeScript and the existing offline CI validation group.
- Local workflow: `npm install`, `npm start` (or `npm run dev`), `npm run validate -- ci`, `npm run build`, and `npm run next:start` to serve a production build.
- Drizzle scripts retain explicit Node invocation and `db:push --strict`. Active developer guides now use npm; historical records of Bun commands are retained.
- Earlier checkpoint changes remain: Next's `agentRules: false`, the patched next-auth version, and two corrected offline fixtures for Model read retry and saved Model Library state.

## Verification

Validation ran in an isolated temporary source copy with fresh npm dependencies and no environment files, preserving the User's active server and `.next` directory.

- Fresh `npm install` passed; repeated installation left the completed npm lockfile unchanged.
- `npm run typecheck` passed.
- `npm run validate -- ci farmbot-worker multimedia` passed all 56 selected tasks.
- `npm start` reached Next.js Ready on an isolated local port; only that temporary server was stopped.
- `npm run db:push -- --help` loaded the CLI without applying schema changes.
- Multimedia import completed its dry run without opening a database connection.
- The FarmBot worker entry point loaded and rejected missing configuration before starting a server or broker connection.
- `git diff --check` passed.

The User confirmed `npm run build` passes after the npm migration. The build gate is complete; the subsequent version-only change renumbers this checkpoint to 0.21.0. Production deployment is now User-confirmed. Earlier browser acceptance and the patched Auth.js session HTTP 200 check are recorded in the release note; fresh-install startup does not replace full browser regression acceptance.

## Remaining dependency findings

`npm install` succeeds but reports the existing Three.js 0.185.1 / postprocessing 6.39.1 peer-range mismatch and 25 audit findings (3 low, 10 moderate, 9 high, 3 critical). No forced audit fixes, broad dependency upgrades or peer-check suppression were applied. The targeted next-auth configuration-error advisory is patched by beta.32; other Auth.js dependency copies still require review. These findings are not evidence of credential exposure.

Remote Vercel configuration remains deferred at the User's request. Preserve the independent `next.config.ts` hostname edits and Vercel example files; examples are not active deployment configuration.
