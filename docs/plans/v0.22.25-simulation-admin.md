## Implemented

- `/admin/threed/simulations` supports search, Project filter, pagination, sorting, page-local checkboxes and revision-aware single/bulk deletion. View/Edit/Delete are colored accessible icons. ThreeD Sidebar and overview link to the module; viewport constraints apply only to its workspace routes.
- `/new`, `/[id]` and `/[id]/view` use dedicated pages with transparent rounded Blueprint sections, compact typography/switches, title help, left green enabled/muted disabled Save/Cancel, exact reads, errors and Reload. Read-only View has no save operation. Invalid route IDs return not-found; missing/private records do not open blank editors.
- Structured Actions have stable step IDs, selected saved Character/target marker identities, timeout (1–300 seconds) and Stop/Continue failure policy. Up/Down controls reorder the saved array; add/remove retains the other steps. Actions reuse existing generic and Planting target identifiers. Planting-specific Actions filter to Planting targets. Availability and rig/physics compatibility are not certified by saving.
- Observation choices store unique Project Sensor Groups, including the existing Imported compatibility group. Saving collects no readings and never resets counters. Other metadata observation sources remain future work.
- The optional Scenario picker uses the same owner, Project and ThreeD module. Editing locks Project/module. Changing a new draft's binding asks before clearing its Scenario/Action/observation choices. Inactive empty drafts are valid; Active requires at least one fully specified Action and denotes availability only.

`/api/threed/simulations` provides authenticated GET (list, exact ID and scoped options), POST, PATCH and DELETE. All responses are private/no-store. Lists return summary counts instead of full definitions. Input is limited to 64 KiB, 50 steps, 32 observation sources, unique IDs/groups, existing Action identifiers and explicit allowed fields. Foreign or inactive marker references and incompatible Planting targets are rejected. Scenario references must match owner/Project/module; module assignment and owner checks precede create/update. Edit cannot submit Project/module changes. PATCH locks the owned Simulation row, compares its revision, increments it and updates the timestamp. DELETE requires the captured revision. Duplicate slugs/stale saves return 409; failed saves retain the local draft. Batch deletes are sequential, with honest partial success and refresh.

The schema and previously prepared SQL remain unchanged. There are no run/result tables, live collectors, worker/MQTT/physical operations, cross-Project copy/apply or Scene/runtime changes. Existing Canvas/Rapier ownership, Garden/Ecctrl separation and Action/world mutation gates remain untouched.
