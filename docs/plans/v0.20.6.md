# v0.20.6 — Dashboard: UI/UX Cleanup

Status: release candidate approved; final UI/browser acceptance User-confirmed. Production build and deployment remain pending. Package `0.20.6`. No schema, API, dependency or environment changes. Production build remains User-owned.

## v0.20.6.1 — Project Assets organization

- **Proof:** Long asset lists had static group headings and a horizontally clipped type-filter row.
- **Act:** Added collapsible type groups with visible-result counts, wrapping type filters, and consistent Models/Plantings labels. Searching or changing filters reopens result groups.
- **Validate:** TypeScript and inspector regressions pass. Browser-check collapse/expand, filtering and nested sensor selection.
- **Resolution:** Asset identity, selection and positioning callbacks remain unchanged.

## v0.20.6.2 — DetailsCard hierarchy

- **Proof:** The title, utility icons and editable sections lacked clear separation.
- **Act:** Added spacing and separators below the title and utility actions. Save/Move/Delete remain at the top outside the scrolling content.
- **Validate:** Inspector rendering checks and TypeScript pass; visual acceptance pending.
- **Resolution:** Editor forms and action callbacks are retained.

## v0.20.6.3 — Ground Map inspector

- **Proof:** Ground Map's long form occupied Environment's dropdown, while it had no direct Project Assets entry.
- **Act:** Added **Assets → Ground Map · Settings** and **Environment → Ground Map · Edit settings**. Both open one DetailsCard-style inspector. The Scene-owned form is rendered through a portal; upload, removal, alignment state and existing handlers remain in ThreeDScene. Save Project invokes the existing Project save action. Alternate Scene hosts retain the inline form when the inspector workspace is absent.
- **Validate:** Ground Map validation (including saved-transform round-trip), inspector regression checks, TypeScript and diff checks pass. Browser testing remains required.
- **Resolution:** Presentation-only relocation. No new Ground Map records, API requests or persistence contracts. Opening the inspector does not reposition the camera or remount Canvas/Rapier. Selecting a marker returns to its inspector; closing Ground Map restores the previously selected inspector. Project/view switches close Ground Map.

## v0.20.6.4 — Sensor Tools

- **Proof:** Sensor actions and groups lacked a common heading and crowded the bottom compass area.
- **Act:** Added a Sensor Tools heading and bottom clearance. Existing Add Sensor and group actions remain available; Add Sensor is omitted while editing Ground Map so it cannot accidentally target the prior marker.
- **Validate:** Existing inspector checks pass. Verify bottom controls remain reachable on a short viewport.
- **Resolution:** Sensor data, groups and physics behavior are unchanged.

This supersedes the earlier separate primary-action row and wrapping filter-chip presentation in .1–.2.

## v0.20.6.6 — Action order, darker panels and compass

- **Proof:** Actions were Save/Move/Delete, asset groups and the parent Physics Sensors section initially expanded, and the compass competed with left-side tools.
- **Act:** Reordered primary icons to Delete/Move/Save, preserving their callbacks, colors and accessible labels. Parent Physics Sensors defaults closed; a remembered user preference still takes precedence. Dedicated Sensor Settings remains initially open. Asset groups now default closed. The compass moves bottom-right with clearance above a visible gizmo and gains Environment → Show/Hide Compass.
- **Validate:** TypeScript, inspector regressions and diff checks pass. Browser-check icon actions, fresh/remembered section states, panel readability and compass visibility with/without the gizmo.
- **Resolution:** UI-only. Compass visibility is local Scene state and resets to shown on remount; no saved-view schema or API changes.

This supersedes the earlier asset-group default-open behavior, action order and opacity values.

## v0.20.6.7 — Neutral actions, workspace preferences and compass initialization

- **Proof:** Primary icons retained colored idle backgrounds; asset group disclosures had no stored preference. Compass projection could run before the camera's world matrix reflected its restored pose.
- **Act:** Primary icons now have neutral idle styles with existing hover colors retained. All shared inspector/panel surfaces use 80% default opacity and 98% hover/focus. Asset groups and Sensor Groups use browser-local, Project-scoped disclosure preferences. Assets panel visibility remains part of the existing Save Project workspace payload. Compass projection synchronizes the camera world matrix and runs again on the first animation frame after controls become ready.
- **Validate:** TypeScript, inspector regressions and diff checks pass. Browser-check compass North immediately after cold load/refresh without interacting, then orbit to confirm continuity. Verify action hover colors and group state restoration for two Projects.
- **Resolution:** No schema/API changes. Clarification: DetailsCard and asset-group disclosure states are browser-local preferences scoped to a Project, not server-saved Project fields. Save Project already persists the overall Assets panel visibility. Sharing individual disclosure preferences across devices would require a separately scoped saved-workspace contract change.

## v0.20.6.8 — Panel Appearance settings and compass axes

- **Proof:** Opacity required CSS edits; the compass showed true North without Scene coordinate directions. User confirmed initial North and required visibility persistence work.
- **Act:** Added Admin → Settings → ThreeD Panel Appearance, with default/hover-focus sliders, live preview and Reset panel opacity. Values apply through CSS variables, persist in this browser and synchronize across tabs. Defaults remain 80%/98%; hover opacity cannot be lower than idle. This control is explicitly separate from account Save Changes. Added camera-projected +X and +Z arrows to the compass alongside heading-aware true North; directions with no meaningful screen projection are hidden.
- **Validate:** TypeScript, inspector, Workspace Settings, Dashboard discovery, Project session and diff checks pass. Updated the existing Settings test loader for the new UI component. Browser validation remains required for sliders, refresh, tab synchronization, focus preview and axis orientation during orbit.
- **Resolution:** No schema/API/dependency changes. Appearance is browser-local, not shared Admin policy. Axis indicators do not modify the Scene camera, models or physics.
