## Proved boundary and smallest milestone

An existing non-primary Texture File may retain a saved URL whose Blob is missing. [Attachment POST](../../src/app/api/threed/models/files/route.ts) intentionally supports same-relative-path recovery after `BlobNotFoundError`: it uploads a fresh key and updates the existing File, including classification/settings, without a locked stale-state recheck. [Scoped File PATCH](../../src/app/api/threed/models/[id]/files/[fileId]/route.ts) locks the owned parent and File but edits settings only.

Shared Texture linking also permits an idempotent existing same-URL attachment. Diagnostics change neither path: **all existing writers, uploads, recovery, linking, settings, primary selection and deletion behavior remain unchanged**.

The smallest milestone is an explicit Check restoration eligibility action on the selected File page. Report target eligibility, storage availability, dependency/reference blockers and observed changes. Every response has `restoreAllowed: false`. No Restore Save action, candidate payload, upload, mutation or cleanup is included.

No table-wide or owner-wide exclusion is permitted. Model/File `FOR UPDATE` protects current target rows and conflicts with child inserts through the immediate File→Model FK. It cannot lock absent global references, prevent URL references under other parents, or forbid future stale writes. Locking existing reference rows misses phantoms. Restore-only SERIALIZABLE or advisory locking does not make uncoordinated writers validate current sources. The schema has no unique Model-relative-path constraint, restore ledger or tombstone.

## Conditional prerequisite for future repair

Future repair needs a separately approved participating-writer policy. Every introducing writer must resolve managed supporting-image references to current authoritative sources and validate URL/access under lock. Reject obsolete, ambiguous or unmapped managed URLs. Copied old URLs cannot bypass this policy through new-source registration; fresh registration needs independently validated server-issued upload authority. Existing arbitrary URL/JSON acceptance makes this broader than one File operation.

A conditional row-lock protocol acquires source and destination Models in ascending ID order, Files ascending, Textures ascending, then applicable Project advisory/row and marker locks. Select each row's strongest required mode before acquisition; never upgrade. Sources/reference rows use `FOR SHARE NOWAIT`; binding mutators use `FOR UPDATE NOWAIT`. `FOR KEY SHARE` is insufficient against implicit non-key URL updates unless every binding mutator explicitly takes `FOR UPDATE`. Validate ownership or the existing allowed access policy, current URL, parent, classification and revision after locking; write within the same transaction. Hold locks only for final validation/reference DML, released at commit/rollback, with a two-second statement/application budget and no network, decoding or upload under locks. Busy acquisition refuses immediately, releases already acquired locks through rollback and never retries automatically. Existing Project advisory locks would also need a nonwaiting, consistently ordered participant path. A Model lock cannot substitute for its source File lock.

This requires complete participation and current-source registration rules. Per-Blob shared/exclusive transaction advisory locks are an alternative, but still need canonical identity, ordered keys, every writer and post-lock validation. They are **not selected**. Neither approach prevents future references from bypassing writers. Do not block unrelated owners to compensate.

## Implemented GET-only diagnostic contract

`GET /api/threed/models/[id]/files/[fileId]/restoration-eligibility` authenticates exact Model owner, File owner and membership before storage work. Reject malformed IDs/extra parameters; accept no browser URL, candidate or settings. Inspection is explicit, never a render loop; private `Cache-Control: no-store`.

Return scoped IDs, opaque owned-source revision, observation time, safe reason codes, availability `missing | present | unknown`, state `observed_candidate | blocked | unknown | stale`, `candidateValidation: "not_performed"`, and **`restoreAllowed: false`**. `observed_candidate` means bounded observations found no supported-target blocker; it never means repair-safe or write permission. Do not expose foreign IDs/URLs, credentials, provider messages or global fingerprints. Use 401/404 for authentication/exact ownership, 400 for malformed input, safe 503/504 for unavailable inspection; other findings are diagnostic results. All GET-handler JSON responses, including errors, explicitly carry `restoreAllowed: false`; network/framework failures cannot grant permission either.

Report individual findings separately. Authentication/context errors take priority. A known capture change produces `stale`; incomplete required proof produces `unknown`; a completed unchanged assessment with a known blocker produces `blocked`. Only complete, unchanged, confirmed-missing observations with no blocker can produce `observed_candidate`. An immediately excluded target may return `blocked`, with unperformed checks explicitly marked `not_checked`; never label them clear. Retain known blocker details even when the overall result is stale/unknown.

1. Capture source records and complete declared-reference inputs in short **REPEATABLE READ, READ ONLY snapshot A**. Include canonical full records/ordered attachments and internal global fingerprints, not timestamps alone: legacy recovery omits `updatedAt`. Select timestamps directly with microsecond-preserving PostgreSQL `to_char(..., 'YYYY-MM-DD"T"HH24:MI:SS.US')`, preserving nulls; never hash JavaScript Date round trips.
2. Release A before authenticated storage calls and bounded primary/MTL reads. Inspect A’s immutable URLs.
3. Capture the same complete inputs in short **REPEATABLE READ, READ ONLY snapshot B** after external reads. Compare source revisions and internal global fingerprints. Any difference is stale; incomplete B is unknown. Recheck ownership/target eligibility. Never return earlier favorable findings after timeout/failure.

No explicit row/advisory/table locks. Automatic `ACCESS SHARE` permits ordinary DML but can encounter exclusive DDL. Each read phase uses two-second statement timeout, 100 ms lock timeout and two-second application deadline. A queued checkout may stop waiting at the deadline; its eventual callback performs no SELECTs. A started transaction must finish or roll back before a timeout response. The existing Pool/Drizzle adapter cannot cancel checkout, a running driver operation or rollback transport, so physical release may exceed the application cutoff; late captures never yield favorable proof. Failures mean unavailable proof, never skipped rows, `SKIP LOCKED` or automatic retry. Equal captures cannot detect every intervening ABA change, changes after B or external object recreation. These limits appear as informational uncertainty after diagnostic state selection. [PostgreSQL locks](https://www.postgresql.org/docs/current/explicit-locking.html) and [isolation](https://www.postgresql.org/docs/current/transaction-iso.html) define the semantics; deployed behavior was not tested.

## Full checks retained

Target: an expected PNG/JPEG/WebP `texture` attachment, not any assigned primary. Expected format is inferred from the saved filename/classification; missing bytes cannot be decoded or established as static/valid. Any eventual replacement candidate still needs full independent validation. Diagnostics preserve every field, including legacy empty relative paths. Geometry/buffers/MTL/animations/previews, reusable/shared Texture sources and uncertain legacy ownership are outside restoration candidacy. No schema/runtime/Character/Project hydration/environment/package/version changes.

Storage: the general owned-Blob predicate accepts broad primary/preview/legacy paths. Require exact configured public store host, HTTPS without credentials/port/query/fragment, owner-bound immutable attachment UUID/key, and current primary root or exact `model-<id>/attachments/` fallback. Unknown/historical roots and deterministic legacy keys block candidacy. Derive store identity only in server memory from the existing validated read-write credential using installed SDK format; no internal helper import/new secret. OIDC-only identity needs a separately reviewed branch.

Authenticated SDK `head()` success means present; only `instanceof BlobNotFoundError` for the proven saved object establishes observed missing. Token/store absence, forbidden, transport/abort/ambiguous response is unknown. Browser failure/public CDN 404/message text proves nothing. Use a five-second per-call wall-clock race plus AbortController, within one fifteen-second monotonic external-inspection deadline shared by HEAD and every primary/MTL read. Each call uses the smaller remaining budget; do not restart the overall deadline for another resource. Late results cannot replace timeout. This is observed absence, not permanent absence.

Global checks include all owners/inactive rows internally. Canonical HTTPS host+decoded path must detect query/hash/equivalent URL aliases. Inspect raw recursive JSON, not version-filtered material helpers; unknown representations cannot pass.

## Future failure policy retained, not implemented

Diagnostics create no objects/SQL mutations. Future approved repair must preserve:

| Future event | Required policy |
| --- | --- |
| Upload failure/lost response | Object may exist; no automatic retry/delete. |
| Confirmed rollback/refusal | This attempt commits no mutation; others may change/remove the row. Refresh authority; retain fresh objects for separately authorized cleanup. |
| Lost commit/HTTP acknowledgement | Outcome unknown; never claim rollback/delete candidate. Scoped Refresh precedes manual retry. |
| Confirmed commit | Report current authority; never undo another successful writer. |

For future repair, communicate uncertain acknowledgement as "Restore outcome unknown. Refresh this File before any retry." Disable automatic and repeat Save while unknown. Refresh shows current authority, not proof of which attempt committed; if the outcome remains unresolved, keep retry disabled rather than resubmitting. Known rollback means this attempt did not commit, not that no competing writer acted. Correlation IDs alone do not provide idempotency. The existing schema cannot promise exactly-once uploads or identify all orphan objects after acknowledgement loss; any durable attempt/idempotency ledger needs separate approval. This diagnostic milestone reports failed inspection as unknown and can be refreshed manually without duplicating mutations because none occur.

Old-key overwrite, fresh/old deletion, sweeps, staged cleanup and destructive retry stay excluded.
