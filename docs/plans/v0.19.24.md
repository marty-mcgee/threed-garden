## Proposed additions (not yet schema changes)

### multimedia_speech

| Field | Proposed type / behavior |
| --- | --- |
| id | serial primary key |
| user_id | non-null text FK to existing auth user |
| title | non-null varchar(255) |
| text | non-null text, draft may be empty |
| voice_id | nullable varchar(128), draft may lack voice |
| provider | non-null text, initially fish-audio |
| model | non-null text, initially s2.1-pro-free |
| settings | non-null JSONB, empty object default; server-validated allowlist |
| revision | positive integer, default 1; optimistic edit conflict detection |
| accepted_version_number | nullable positive integer; composite FK described below |
| archived_at | nullable timestamp; archive rather than destroy history |
| created_at / updated_at | non-null timestamps |

Owner/list index on user_id, updated_at, id. No Album requirement: a Speech draft is autonomous.

### multimedia_speech_versions

| Field | Proposed type / behavior |
| --- | --- |
| id | serial primary key |
| speech_id | non-null integer FK to Speech, delete restrict |
| version_number | positive integer, unique with speech_id |
| request_id | non-null UUID, unique with speech_id; durable request deduplication |
| draft_revision | non-null integer identifying saved draft captured for this attempt |
| text / voice_id / provider / model / settings | immutable generation-input snapshot |
| status | text check: pending, generating, ready, failed, interrupted |
| storage_key | nullable text; non-null for ready versions, never an expiring signed URL |
| file_name / mime_type / file_size | nullable output metadata; positive size for ready versions |
| track_id | nullable integer FK to existing music_tracks, ON DELETE SET NULL |
| error_code / provider_status | nullable bounded diagnostic code/integer; no raw provider bodies or secrets |
| created_at / completed_at | timestamps |

Composite FK from Speech (id, accepted_version_number) to Versions (speech_id, version_number) keeps accepted selection inside its own Speech. Nullable pointer permits initial insert; define using Drizzle's deferred column typing for the circular relation. Only ready versions can be accepted, enforced by the owner-scoped service transaction. One in-flight attempt per Speech via partial unique index on speech_id for pending/generating statuses. No FK to Album unless/until publishing a Track.

Snapshot/output fields freeze when ready; lifecycle/error/link fields have narrowly scoped transitions. Preserve failed attempts as history, without describing them as playable audio. Increment version numbers under a row lock, not a race-prone max+1 outside a transaction. Never keep a database transaction open while calling Fish Audio or S3.

## User workflow

1. Multimedia → Speech list: search, pagination, status, title, accepted version, modified date, Edit/Archive actions.
2. New/Edit Speech: title, text, voice, model/settings; Save Draft is separate from Generate.
3. Generate requires a saved draft, reserves an idempotent version, snapshots inputs and calls the existing Fish adapter. Store and verify MP3 in S3 before marking ready. A refresh must not trigger generation.
4. Version history: version number, time, status, preview, Accept, Save as Track. Generating creates another version; it never changes accepted_version_number automatically.
5. Explicit Accept selects an existing ready version. Later draft edits label the accepted output as belonging to an earlier draft; they do not invalidate/delete it.
6. Save as Track references that version's existing audio. Repeated saves return the existing linked Track rather than creating duplicates. Track deletion clears track_id but preserves audio while Speech history references it.
7. Archive hides Speech from the default list and retains all accepted/history files. Permanent record/file purge is deferred until reference-aware cleanup is implemented.

## Failure and deletion boundaries

Provider calls are not exactly-once transactions. If a process dies after provider submission, preserve an interrupted/unknown attempt; do not automatically regenerate it under the same request. Explicit retry creates a new attempt after resolving stale state. If S3 succeeds and registration fails, retain enough version identity for recovery; do not silently discard evidence. Add a storage-reference check for Versions to current Track deletion before shipping version-to-Track linkage. Existing database/S3 atomicity limitations are not solved by this proposal alone.

No automatic backfill from old Track metadata: it may be incomplete. Existing Tracks and files stay intact. No paid-model fallback, credentials, live generation or AWS changes are part of planning.
