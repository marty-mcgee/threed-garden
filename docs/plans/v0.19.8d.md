# plans: docs: v0.19.8d — ThreeD Model Library Import and Scene Presentation

Status: completed and released successfully to production September 7, 2026.

This plan produced **v0.19.8d — ThreeD Model Library Import and Scene Presentation**. The implemented and verified stages below record the progression that produced that checkpoint.

## Objective

Complete the handoff from reusable Models configured in the Admin surface to discovery, placement, and presentation in the Dashboard Model Library and ThreeD Scene.

## Stage 1 — Library data and readiness

Status: implemented and manually verified September 7, 2026.

Extend the existing Dashboard Model Library contract to expose the information needed to make a safe placement decision:

- preview image and Model type;
- active and public Library eligibility;
- primary Model file availability;
- saved Texture-assignment count;
- missing dependency status; and
- explicit **Ready**, **Needs Configuration**, and **Unavailable** states.

This stage changes Library visibility and diagnostics only. It must not change Project placement behavior.

Implementation notes:

- the shared Library response now provides a bounded `libraryReadiness` summary derived from stored Model, file, and relational assignment records;
- Model cards and selected-Model metadata display **Ready**, **Needs configuration**, or **Unavailable**;
- FBX and OBJ records with a primary runtime file but no saved Base Color assignment or attached Texture are conservatively identified as needing configuration;
- dependency coverage is reported as **Available** or **Not yet verified** because deep completeness requires explicitly downloading and inspecting the primary file in Model Files; and
- placement remains unchanged during Stage 1, allowing the new diagnostics to be manually evaluated before they become a placement gate in Stage 2.

## Stage 2 — Model Library discovery UX

Status: implemented and manually verified September 7, 2026.

Improve browsing for a Library that may contain hundreds of Models:

- search by Model name;
- category filtering;
- readiness filtering;
- consistent compact Model cards;
- preview images with a clear fallback presentation; and
- an owner-only Admin configuration link for incomplete Models.

Only ready Models may begin Scene placement. Incomplete Models remain visible and diagnosable without producing a broken placement.

Implementation notes:

- the existing name search and category filter now compose with an explicit readiness filter;
- active non-Character Models remain discoverable to their owner even before public publication, while Models owned by another User still require both Public and Model Library Item eligibility;
- new manual Model imports default to Model Library Item classification, while Public sharing remains an explicit opt-in;
- compact cards show format and readiness without opening the inspection surface;
- ready Models retain the established click and drag placement paths;
- Models marked **Needs configuration** or **Unavailable** can be inspected but cannot start placement;
- incomplete Models owned by the signed-in User provide a direct **Configure Model** link to their Model Files workspace; and
- the Library response exposes only a bounded `canManage` boolean rather than another User's ownership identity.

Initial manual verification exposed and corrected a pre-existing runtime identity mismatch: a Project Model marker uses `data.id` for its Project marker record and `data.modelId` for its reusable Model. Attachment loading now requests the reusable `modelId`, preventing Project marker IDs from producing false `/api/threed/models?id=<projectMarkerId>` 404 responses. Project marker identity and placement authority remain unchanged.

## Stage 3 — Configured Model preview

Status: implemented and manually verified September 7, 2026.

Ensure the Dashboard Library preview uses the same saved Model configuration as the Admin importer and Model Files workspace:

- authoritative primary Model file;
- Model-owned dependency attachments;
- reusable Model Texture assignments;
- saved scale, Y rotation, and offsets; and
- bounded loading and failure presentation.

Admin preview, Library preview, and Scene runtime should render the same configured asset through the established Model runtime adapter.

Implementation notes:

- selecting a Model card mounts a compact interactive Three.js preview inside the Library inspection surface;
- the preview receives the authoritative primary file, Model-owned attachments, relational material assignments, saved scale, Y rotation, and offsets already returned by the Library contract;
- it reuses `ModelMarker3D`, matching the Admin preview and Dashboard Scene loading path rather than introducing another Model parser;
- fitted bounds, orbit controls, and camera reset provide bounded inspection without changing persisted transforms;
- loading and runtime failures remain contained within the preview; and
- the preview creates no Project Marker, placement transaction, or Rapier physics world.

## Stage 4 — Project placement and runtime verification

Status: checkpoint behavior implemented and manually verified September 7, 2026.

Connect ready Library Models to the existing one-shot placement transaction:

- do not duplicate reusable Model or Texture records;
- preserve `project_threed_markers` as Project-instance authority;
- apply saved transforms and Texture assignments immediately;
- preserve the persistent React Three Fiber Canvas and Rapier world;
- do not remount unrelated Scene assets; and
- verify refresh, Project switching, movement, editing, and deletion.

An owner inspecting an incomplete Model should receive a direct route to Model Files or Model Textures instead of a black or untextured Scene placement.

Implementation notes:

- the selected-Model inspection surface exposes a per-Project-instance placement scale before placement begins;
- the effective scale is previewed as reusable Model base scale multiplied by the placement scale;
- selecting a different Model resets the placement scale to `1`; and
- placement-scale changes do not mutate the reusable Admin Model record.

## Stage 5 — Release hardening and documentation

Status: completed and production deployment confirmed September 7, 2026.

Complete the following manual regression coverage before preparing the release:

- large-Library search, category, and readiness filtering;
- ready and incomplete Model behavior;
- textured placement and refresh persistence;
- Project switching;
- Model DetailsCard selection, editing, movement, and deletion;
- Model collision and Physics Debug presentation; and
- Character selection, Take/Release Control, WASD, and animations in a Scene containing newly placed Models.

Then run the repository validation ladder, prepare the v0.19.8d release documentation, and use the established manual production build and deployment gates.

## Preserved authority boundaries

- `threed_models` remains reusable Model authority.
- `threed_model_textures` remains reusable master Texture authority.
- `threed_model_material_assignments` remains Model/material-slot/channel mapping authority.
- `threed_model_files` remains Model-owned primary-file and dependency-attachment authority.
- `project_threed_markers` remains Project-instance authority.
- The Runtime Marker registry remains the current-position mirror.
- The Dashboard retains one persistent Canvas and Rapier world.
- GardenCharacter and EcctrlCharacter remain separate runtime paths.
- No bulk import, MQTT publishing, FarmBot command, or physical-device behavior is authorized by this plan.
