# v0.20.1 — ThreeD Physics

Status: **release candidate accepted by the User; production deployment not yet confirmed**. Package `0.20.1`.

The User confirmed functional readiness and accepted the final optional Sensors panel/DetailsCard layout. This records User acceptance, not an agent-run browser test. The User has confirmed a successful build. Production deployment remains pending.

## Release boundary

The candidate includes checkpoints `v0.20.1.0` through `v0.20.1.4`, the DetailsCard/loading portion of `v0.20.1.6`, the `v0.20.1.7` dependency decision, sensor TransformControls at `v0.20.1.12`, generic sensors/groups at `v0.20.1.14–16`, and optional panel/layout refinements at `v0.20.1.17`. It does not claim the proposed `v0.20.1.5` Farming-zone system because current ThreeD Layer records do not assign Runtime Markers. That feature requires a separate reviewed marker/layer identity stage.

Checkpoint `v0.20.1.8` remains outside this release. Physical commands, MQTT publishing, and automatic equipment actions remain disabled.

Soccer Physics is the current acceptance priority. Owner-local Physics Sensor Cuboids now attach to Models, Beds, Plantings and FarmBots. Generic named sensors, user-defined groups and entry counts replace fixed sports behaviors; Soccer is a browser test scenario. FarmBot browser coverage remains brief and read-only. The planned category-driven Add to Scene Model collections are recorded as checkpoint `v0.20.1.9` and remain deferred until after this production checkpoint.

6. Select each sensor owner and confirm its focused sensor wireframes are readable without the full Environment collider mesh. Enable Physics Debug and confirm the owner-specific diagnostic guides follow position and rotation while retaining their configured Scene-unit dimensions.

8. Open a Project FarmBot DetailsCard and confirm unavailable telemetry does not delay or hang Project loading.
9. Save alignment with live presentation disabled and confirm the FarmBot remains at its saved Project position.
10. Enable alignment using verified device bounds/orientation; confirm an in-bounds live position moves the FarmBot representation and its attached sensor smoothly.
11. Stop or disconnect the worker and confirm the presentation freezes at its last confirmed position while the DetailsCard reports stale/disconnected state.
12. Switch Projects and confirm the prior Project's live observation is not reused.
13. Recheck Project Save/Restore, movable-ball loading, fixed and triangle-surface Models, Character Take/Release Control, DetailsCards, and Scene Layer toggles.

## TransformControls pilot acceptance — v0.20.1.12

1. Open a sensor owner, use **Zoom to Sensor** if needed, then **Transform Sensor · Mouse Handles**.
2. Drag the red X, green Y and blue Z handles separately. Confirm the preview and disabled numeric fields update, the owner stays selected, and the camera does not orbit during dragging.
3. Select **Rotate Y**, drag the ring past 90° in both directions and verify a continuous turn.
4. Press **Cancel** or Escape, including while dragging: the saved cuboid is unchanged, the handles disappear, physics resumes and camera orbit works again.
5. Repeat and **Save Transform**. Verify the success toast, correct collider/guide alignment and persistence after refresh. Repeat with a rotated owner.
6. Simulate a failed save: retain the preview for retry/cancel without claiming success. Switch owner/Project or close the editor and verify no stale handles remain. Hide the owner layer and verify cleanup.
7. Recheck the existing click-to-place, Move Sensor and Zoom actions, Character control and scoring. Check the separate Garden Scene route still renders without an editing workspace.

This checkpoint exposes handles on sensors. Whole-Model TransformControls adapters are recorded as v0.20.1.13 and are not part of this pilot's completed behavior.
