## Baseline and boundaries

Stable production is **v0.19.32 — ThreeD Animations: Custom Action Slots + Preview Workspace**, including its documentation release, both User-confirmed. See [release evidence](../releases/v0.19.32.md).

Preserve owner-scoped Slot identity, immutable action keys, saved mappings, protected deletion and enabled state. Animation Categories organize clips and Slots; Model Categories classify Models. Their relationships remain separate. Previewing a clip does not save an assignment or certify rig compatibility. Character override → Model default → existing runtime behavior remains the assignment precedence, with disabled custom Slots unavailable.

Accessibility comes first: keyboard focus, dialog dismissal/focus return, labels, touch targets, responsive scrolling and readable transparent panels.

## Development sequence

1. **Prove the current workflows.** Inspect Slots, Category management, Character/Model assignment windows and Model Category controls. Record concrete friction and affected files; incorporate User notes before choosing the first behavior change. Start with shared Category management and assignment discovery as review candidates.
2. **Refine Slots and Animation Categories.** Improve creation/editing, Category selection, quick creation, Uncategorized handling, enabled-state clarity and protected-delete feedback within existing CRUD conventions. Preserve Slot keys and references.
3. **Refine Model assignments.** Make selected Slot, assigned clip, inherited source and saved/unsaved state clear. Keep independent preview separate from saving; preserve drafts when filtering and keep preview mounted. Apply the same interface consistently to Character overrides and Model defaults.
4. **Refine Model Categories.** Review assignment/discovery alongside Animation workflows, preserving the distinct classification system and existing Model Library eligibility. Category changes must not silently change placement roles or physics.
5. **Validate shared UI/UX and prepare release.** Check Admin and Dashboard behavior across Projects, keyboard/touch/narrow layouts, messages and overlay coordination. Finalize the release title around implemented scope and record verified outcomes.

Each stage follows **Prove → Act → Document**: identify the problem and acceptance criteria before editing, make the smallest scoped change, then validate and document the final implementation. Do not combine repository restructuring with feature behavior changes. The sequence is a plan, not a claim that all listed areas require changes.

## Implemented stages

### Slots and Animation Categories

Added `/admin/threed/animation-categories` with AdminWorkspaceHeader, Category icons, counts, name search, sortable columns, client pagination, page-local bulk selection, reference counts and shared Add/Edit dialogs. Existing owner-scoped Category API now returns clip/Slot counts. Slots referencing a Category exclude it from deletion selection; the composite FK remains the authoritative protection if references change after loading. API conflict feedback explains reassignment to another Category or Uncategorized. Bulk failures remain red beside green deletion totals. Renaming preserves identifiers and references; deleting removes clip taxonomy labels via existing cascade, with confirmation, without deleting clips/mappings. Library, Sidebar, Slots and Model Categories link to the workspace. Clip Category assignment now uses a shared modal dialog instead of inline controls.

Existing API maximum of 500 Categories remains; this workspace pages/searches the loaded owner list rather than claiming unlimited server pagination. Model Categories retain their existing server pagination and separate taxonomy. Category dialogs retain failed drafts and block dismissal while saving.

### Assignment and Model Category UX

Character and Model assignment windows share visible saved source/state/clip information, total unsaved count and per-row Discard change. Refresh confirms before discarding dirty work. Clip/Slot filtering retains drafts and the existing preview iframe; independent preview remains unsaved. Assignment errors are red alerts; successful saves are green status messages. Category naming replaces leftover Group filter state nomenclature. Model Categories now separate green bulk summaries from red failures and show failed-save errors inside the retained dialog. Navigation connects both Category workspaces without merging classification or changing placement/physics eligibility.
