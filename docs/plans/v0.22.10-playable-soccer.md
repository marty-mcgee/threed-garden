# v0.22.10 — ThreeD Playable Soccer

**Released to production, User-confirmed September 30, 2026.** Release commit `b952b885`, package `0.22.10`. The User selected Character actions and ball interaction as the priority after v0.22.9. The implementation history below records candidate decisions and validation; individual browser checks remain distinct from deployment confirmation.

## Outcome and recommended scope

In Project 15, take control of an eligible Character, select a particular movable ball as the Action Target, approach it with WASD, and trigger one supported mapped kick. After the one-shot animation completes, that ball receives one bounded physical impulse through its existing Rapier owner. Moving it into an existing goal sensor increments the existing session counter once per entry.

Start with Farmer Kate and one verified foot-kick mapping. Use the same capability for other eligible Characters, but do not make Joey, Scarecrow, headers, passes, penalties, teams, or match rules prerequisites for this release. Their asset preparation and rig compatibility are separate follow-ups. No automatic Character placement or live catalog edits are included.

## Implementation status

The current candidate adds **Kick selected ball** to a controlled movable Character's Animations section when the built-in **Use as Action Target** selection points to an active movable-ball Model instance and a loaded, active foot-kick slot is available. The button uses the existing Model target choice; it does not make a second ball selection. The Scene checks the exact Project marker, current Character and ball positions, control, visibility, Layers, and 4.5-unit planar/2-unit height range before starting. It carries a request UUID and actor marker ID through Ecctrl's existing one-shot path. On the matching completion, the ball's existing Rapier body rechecks control, target, live actor position, body availability, and range before applying a horizontal impulse. A kick adds at most 10 scene units/second of speed while the ball is below an 18-unit/second planar cap. Those values are candidate tuning choices, not browser-accepted physics measurements.

The request rejects overlapping clicks, mismatched and repeated completions, target/control/Layer changes, removed markers, and missing completion after 30 seconds. The ball body is the sole impulse owner; the existing generic goal Sensors remain the sole count owner. Character playback is scoped to the selected Project Character marker while ordinary action events retain their historical source-character behavior. The on-screen Scenario instruction and help guide describe this flow. The kick itself does not write to an API or create a new Scene world or FarmBot operation. The later User-authorized sensor snapshot below adds explicit Project Save persistence without a schema change.
