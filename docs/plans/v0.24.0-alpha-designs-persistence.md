# ThreeD Designs: integration with the existing Project Scene

Release handoff: **[v0.24.0-alpha — ThreeD Designs: Project Scene integration](../releases/v0.24.0-alpha-project-design.md)**. Developer confirmed production release October 9, 2026. Package version remains unchanged; detailed authenticated App and post-deployment acceptance remain pending.

## Requirement and proven divergence

The October 9 clarification supersedes the independent Designs persistence candidate. Design View edits the active Project Scene. The candidate's separate DesignPreview Canvas, record picker and /api/threed/designs writes failed this requirement. Existing project.config JSONB and the snapshot transaction provide the persistence boundary without a new table/column.

The exact source/module/schema mapping is in [THREED_DESIGNS.md](../developers/THREED_DESIGNS.md). threeDArchitecture is a new JSON contract in existing project.config, not a pre-existing column. Package/root lockfile remain 0.24.0-alpha. Production remains the Developer-confirmed alpha; this correction is Developer-confirmed released; this documentation confirmation remains unstaged.

## Focused implementation

1. Lift architecture/history/selection to the active Dashboard Project with per-Project draft retention. Remove separate Save/picker/record identity. Module routes choose an existing Project.
2. Retain persistent 3D/map owners across View Modes; mount architecture alongside Models in the existing Canvas beside the Plan. Preserve existing physics, transforms, materials and resource references.
3. Validate/store {version:1, document} at project.config.threeDArchitecture. Existing map/threed loading returns it; existing project/threed-markers PUT saves it with marker/view snapshots in the same transaction. No new schema activation.
4. Convert metres to Scene units and reuse map coordinate transforms. Stable entity IDs link to generated project/entity object identities. Plan/mesh/map selection shares those IDs.
5. Validate JSON before explicit Merge or architecture-only Replace. Allocate fresh IDs/remap internal references; preserve unrelated Scene content. Export remains portability; import saves through Project Save.
6. Retire separate API writes with 410. Retain possible legacy records/mapping for non-destructive read-only recovery; no automatic migration, adoption or removal. Previous additive SQL is superseded.
