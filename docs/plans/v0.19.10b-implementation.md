# v0.19.10b — GLB/GLTF bulk-import implementation

Implemented September 9, 2026. Release candidate package: **`0.19.10-beta`**. The User manually tested and accepted the final checkpoint and confirmed the local build gate as passed. Release preparation is complete; see the [production handoff](v0.19.10b-release.md). This work has not been committed or deployed. Production remains [v0.19.10a](../releases/v0.19.10a.md), commit `16a92ae`, as confirmed by the User.

## Problem proved before editing

The released bulk picker, preparation and runner accepted only FBX. Primary verification assumed `fbx`, and all companions were textures. Existing upload and Model Files APIs already accepted GLB/GLTF and binary attachments, but upload analysis returned material-target keys only for FBX. The current GLTF scanners did not prove complete buffer/image decoding or the runtime's default-scene traversal keys.

Acceptance was defined in the [beta plan](v0.19.10b.md): mixed formats retain their exact type, required binary buffers cannot be deferred, supported embedded/external resources are decoded before upload, existing Texture assignments use proved runtime keys, saved files and assignments are verified before activation, and FBX recovery behavior remains intact.

## Implemented behavior

**Admin → ThreeD → Models → Bulk Import Models** now accepts FBX, GLB and GLTF in one queue. **Add textures / .bin files** fills the shared companion pool. Each row shows its external image/buffer requirements, texture summary and independent readiness. Exact paths and unambiguous filenames retain the existing matching rules; explicit choices resolve ambiguity. Destination filenames must match their selected source files. Bare buffer names use `buffers/`; bare image names use `textures/`.

GLB/GLTF preparation parses and bounds the declared bundle. On explicit import, before any upload, the runner captures the exact Files/settings and loads that local bundle with the installed `GLTFLoader`, local DRACO decoder and the shared material inventory used by the preview/runtime. PNG/JPEG/WebP decoding and actual geometry are checked. Only temporary owned blob URLs and the existing local decoder paths are available to that inspection. Temporary URI substitutions never change uploaded primary bytes; decoded objects, image bitmaps, decoder workers and object URLs are released after inspection.

The existing owner-scoped sequence then uploads the primary, creates and verifies an inactive Model with its primary file, saves images as `texture` and `.bin` files as `binary` with `isBinaryBuffer`, assigns an optional existing Base Color Texture, verifies saved assignments, audits dependencies, and activates only when requested and complete. A GLTF audit that is unavailable or reports missing geometry cannot count as success. Failures retain the established known-Model review or uncertain-create handling without an automatic duplicate create.

**Assign Existing Texture File** retains batch inheritance, per-Model overrides and None. GLB/GLTF assignment keys come from the loaded default scene, including repeated and skinned meshes, rather than JSON material IDs. None preserves authored materials/maps. Only Base Color is assigned; other authored PBR channels remain loader-owned. Texture selection does not satisfy an external image or binary requirement.

Missing geometry always blocks its row. Missing images can be explicitly deferred using **Resolve missing texture files later (keep inactive)**. Local inspection substitutes a temporary one-pixel image only for a genuinely absent image; it is never uploaded. Corrupt or ambiguous supplied resources still block. The saved Model retains its missing-image audit and remains inactive.

## Supported subset and limits

| Case | Beta behavior |
|---|---|
| Primary formats | Existing FBX plus glTF 2.0 JSON (`.gltf`) and GLB version 2 (`.glb`), case-insensitive. GLB accepts one JSON chunk and an optional BIN chunk with exact container bounds. |
| Embedded resources | GLB BIN geometry, bufferView images, canonical base64 buffer/image data URIs. No artificial attachments are created. |
| External resources | Local relative `.bin`, PNG, JPEG and static WebP. GLB external dependencies are handled like GLTF dependencies. |
| Compression/materials | Local DRACO and `EXT_texture_webp` browser checks pass. The explicit required-extension allowlist covers the installed loader's supported PBR extensions, quantization, texture transforms and punctual lights. |
| Unsupported resources | KTX2/BasisU, Meshopt, AVIF, GPU instancing, animated WebP and unknown required extensions block. FBX retains its existing image support. |
| Dependency URIs | Relative paths with one decoding pass; safe `./` segments normalize. Remote URLs, persisted blob URLs, absolute/workstation paths, backslashes, parent traversal, queries/fragments and repeated/unsafe percent encoding block. Custom `extras` metadata stays inert. |
| Selected files | 4 MiB per primary, companion or preview; 100 queued Models; 500 shared companions/resources; one attachment per request. |
| Bundle/geometry | 32 MiB selected/embedded resource budget and 32 MiB decoded-geometry ceiling; declared buffers, accessors, ranges, sparse indices and actual geometry values are validated. These ceilings are separate from browser overhead. |
| Scene/inventory | At most 4096 records per collection and bounded combined scene/primitive expansion, depth 128, no node cycles or multiple parents. A scene must be declared. Existing Texture assignment requires a complete inventory of 1–500 canonical slots. |
| Image/inspection work | At most 16,777,216 pixels per image and 33,554,432 pixels in total; actual image decoding must agree with dimensions. Local inspection times out after 30 seconds and uses at most two DRACO workers. |

This is a tested initial bulk-import subset, not complete glTF conformance or a guarantee for every exporter. Single-Model importing and the saved Model renderer remain available through their existing paths. There are no API, schema, Project, Character, Canvas/Rapier, dependency-package or decoder-asset changes. OBJ, ZIP/folder traversal, larger-file transport and durable batch queues remain deferred.

## Embedded-texture presentation follow-up

The User's screenshot showed a self-contained GLB reporting only **3 embedded resources**, with **Batch (None)** as its Texture choice. The generic resource count combined buffers and images; it did not explain which textures were already included or that None preserves them. Acceptance for this follow-up was an image-specific summary near the filename, accurate treatment of images in external binary files, and wording that follows the effective inherited or overridden Texture selection.

`summarizeBulkGltfResources` in the preparation core now retains lightweight counts for images embedded in the primary, images stored in external `.bin` files, and unique separate image paths. The component displays these in **Model textures**, explicitly reports when no additional files are needed, and explains either original-material preservation or the selected all-slot Base Color replacement. For example, one embedded geometry buffer plus two embedded images now displays **2 embedded texture images**, rather than three generic resources. The None options explain **keep original materials and textures**. Images in external `.bin` files remain visibly dependent on those files.

Validation: all 32 preparation groups and TypeScript pass. The actual component passed isolated Chromium checks for the prominent two-image GLB summary, external binary/image distinctions, a material-color-only Model, batch inheritance, row override/None, no preparation writes and mobile horizontal fit. The existing Texture-assignment browser suite also passed, including catalog failures, assignment failure recovery and activation. This follow-up changes presentation and preparation metadata only; import sequencing, saved files, decoder behavior and the existing worktree changes are preserved.

## Expanded form and local preview follow-up

The User found the form too complicated and requested all fields visible by default, prepared preferences/scales, a highlighted requirements section, and an on-demand separate-window Model preview. Inspection confirmed collapsed Batch defaults/shared files, competing scroll areas, no local 3D preview entry point, and a result branch that replaced the preparation fields. Acceptance was an expanded, scrollable form with visible requirements and defaults, plus a real pre-upload preview using the selected files and effective visual settings.

The dialog now has one scrolling configuration area with a fixed header/footer, expanded batch/shared-file sections, and a prominent File requirements block before Model configuration. Import results preserve a disabled copy of submitted settings and companion choices. Defaults retain scale 1.0, Library Item on, other flags off and no categories/Texture on first use. Versioned, bounded browser preferences remember only validated batch values per authenticated User; Reset defaults restores the starting values. Invalid numeric edits do not overwrite a valid stored preference, stale references remain visible, and no Files or drafts are persisted. Both scale fields offer 1%, 2% and 100% shortcuts with custom values and per-Model inheritance.

**Preview Model** opens `/threed/model-import-preview` only on request. The server requires the existing authenticated session. The opener and receiver validate origin, window identity, a fresh token and payload; the URL carries no file names or Model settings. Structured-cloned Files and copied visual settings form a stable local snapshot. Reopening refreshes the named window; handshake listeners have acknowledgement, timeout and close cleanup. Popup denial is reported in the importer.

The preview owns a local Three.js scene, uses the shared canonical material inventory and grounding calculation, and fits its camera without changing Model scale. It provides orbit/zoom/pan, reset, dimensions and a one-unit grid. Original materials are preserved unless an existing Base Color Texture is selected; that Texture is read through the existing owner-scoped catalog and applied locally. Missing geometry errors and incomplete-texture placeholders remain explicit. The optional saved thumbnail is labeled separately. There are no upload, Model-write or Scene-runtime operations in this window.

The GLTF browser inspector now offers a retained scene lease; the existing pre-import inspection wrapper still releases it immediately after validation. The FBX preview uses the installed FBXLoader, selected-file resolution, browser image decoding, finite geometry bounds and bounded resource allocation. FBX preview supports PNG/JPEG/WebP/BMP; no TGA decoder was added. Both paths release geometry, materials, textures, decoder resources and owned object URLs after errors or window cleanup, including late completions. Preview loading is bounded to 30 seconds. A saved Texture override is separately owned and disposed by the renderer.

All seven native import validators pass (116 groups total). Browser checks verified original and selected texture rendering, representative tracked FBX geometry, no mutation requests, preferences, four form viewport sizes and full-size camera framing with nonzero offsets. Four additional completed-row browser groups verified immutable submitted settings despite later batch/catalog/companion changes, clearing and safe retry. These checks use mocked APIs; real authenticated asset appearance and persistence remain manual release checks.
