## Goal Milestone

Developer designated this finding as the next iteration's Goal Milestone on October 7, 2026. Make Animation Action Maps, default Actions and available clips understandable and consistent across Character configuration, Simulation forms and Preview Canvas. Production is Developer-reported v0.23.1. This document records planned work; it does not claim v0.23.2 implementation, acceptance or release. Package/root lockfile remain 0.23.1.

## Proven findings

- Preview initially combined logical Action keys with raw rig clip names, producing duplicate or unexpected choices. Current uncommitted changes project saved map titles plus the established default Action catalog, retaining per-Character selection and per-step local overrides.
- A saved Action Map and a loaded playable clip are separate requirements. Character overrides, inherited Model assignments, disabled mappings and rig compatibility affect availability.
- `kickBall` is a Simulation operation that resolves a loaded foot-kick Action Map. The current contact recognizer accepts left/right foot titles or Soccer kick names, but plain `Kick` does not qualify.
- Header clips can animate when assigned, but the contact contract currently supports feet only. Header ball response is a separate execution capability and must not be inferred from clip availability.
- The Developer's Simulation #4 screenshot shows an unresolved Farmer Joey kick. Its exact saved assignment/load failure has not been inspected live.

## Planned behavior and acceptance

1. Define and present two explicit sets: **Strict Animation Set** for configured active mappings with compatible playable clips, and **Broad Animation Set** for default Actions plus custom mappings, with unavailable entries and their reasons visible. Treat these definitions as the proposed implementation contract for this iteration.
2. Preserve configured titles and immutable Action keys. Default Idle, Walk, Run and jump phases remain discoverable. Explicitly disabled mappings never become playable through default or raw-name fallback.
3. Resolve plain Kick and sided Kick mappings consistently. Display which mapping and clip a `kickBall` step will use, or the precise missing/inactive/incompatible requirement. Preserve actual animated foot-contact gating and honest missed-contact results.
4. Explain Header's animation availability separately from ball-contact support. Any head-contact implementation requires a separately reviewed scope and regression checks before being enabled.
5. Keep participant choices independent per Action. Preview selections remain local unless an explicit assignment save is requested; a local preview override must not imply Scene execution uses that override.
6. Enable Play Timeline only when every step meets its preview requirements. Show actionable blockers beside the affected step, including source loading, missing assignment, disabled map, incompatible rig and unsupported contact.
