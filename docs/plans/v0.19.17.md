# v0.19.17 — ThreeD UI Refinement + Scene Overlays

User-designated next milestone after production v0.19.16. Current scope: presentation only in the ThreeD Module, including its front-end and Admin pages; other modules are deferred. Package remains at the released version until production preparation. No build is run by the agent.

## Strict boundary

Allowed: JSX/HTML structure, CSS/Tailwind classes, spacing, typography, sizing, alignment, responsive grids, borders/backgrounds, overflow and focus presentation. Preserve field visibility, labels/meaning, IDs, values, validation, handlers, links, sorting, pagination and disabled states. Preserve accessible reading/tab order and usable touch controls.

Not included: new functionality; data fetching/filtering; assignment or selection logic; API/schema/auth changes; dependency updates; runtime, animation, camera, physics or world-action behavior. Do not hide fields or add collapsed sections to make forms shorter. Do not move components in ways that reset their state or remount Canvas/physics. Shared component changes require reviewing their consumers first; use scoped classes until the pattern is proven.

The Character behavior and world-action UX plan is paused for this milestone. Its unresolved functionality is not silently included in visual work. Settings and registration functionality remain deferred. Existing screens can receive visual adjustments; unused Tasks/Analytics are not revived.

## Accepted visual references

- Admin Models: compact header, stationary controls, scrolling records, readable table headings and pagination.
- Character Create/Edit: wide dialog, compact controls, related fields in responsive columns, full-width Model relationship, all fields visible. Narrow screens retain one column.
- Specialized Model Files and Animation Preview workspaces retain their distinct purpose and layout.
- Dark overlays use a very dark gray surface distinguishable from the App, with opaque readable content. Preserve light-theme readability as well.
