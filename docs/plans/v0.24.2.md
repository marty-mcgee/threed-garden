# v0.24.2 — Workspace Feedback + Responsive Reliability

October 10, 2026: Developer confirmed **v0.24.2 — Workspace Feedback + Responsive Reliability** released to production. Package/root lockfile remain 0.24.2. The implementation and verification below record pre-release evidence; release confirmation does not establish additional authenticated or post-deployment checks. Exact deployed SHA remains unconfirmed. No schema or dependency changes. Manual Release Gate applies.

## Proven problems and focused acceptance

- Project Save already captures workspace preferences, but the toolbar did not distinguish changed preferences from the loaded/saved snapshot.
- The narrow-screen `.threed-inspector` rule forced `left: 0.5rem !important`, overriding saved normalized DetailsCard positions.
- Overlay bounds observed the panel and parent but not toolbar height changes caused by wrapping.

Acceptance: indicate changed workspace/architecture beside the existing Save action; explain saving/failure through accessible feedback; acknowledge only captured preferences; avoid hydration/runtime Sensor false positives; preserve Project isolation. Keep saved cards within narrow viewports, default inset for unpositioned cards, and toolbar-aware bounds. Retain accepted Design layout and existing persistence.

## Implemented

- `captureProjectWorkspace` in `src/app/dashboard/scene/page.tsx` is shared by feedback and the existing PUT Save. No second persistence mechanism.
- `useWorkspaceSaveFeedback.ts` samples retained view providers every 750ms after hydration. Timestamp and Sensor readings are excluded; numeric differences below four decimal places are ignored. Cameras, view mode, panel/inspector state, overlay positions and Design workspace preferences are included.
- Amber Save outline/dot, hover/focus tooltip, accessible live status and existing bottom unsaved message now reflect architecture/workspace changes. Save errors retain actionable feedback. Acknowledgment compares the captured snapshot with the latest callback, preserving edits during Save. Unchanged means workspace unchanged, not certification that all Model/runtime content is saved.
- DetailsCards with custom positions bypass the forced narrow default inset. Default cards retain that inset. The shared overlay hook observes toolbar resize as well as panel/parent resize.
- No expanded architecture, Builder, autosave or conflict-management stage.

## Limitations and manual acceptance

Feedback samples at 750ms; moving follow/auto-rotating cameras can legitimately change the saved view. This is workspace feedback, not a universal Scene-content dirty tracker. Existing architecture navigation guards are unchanged. Workspace-only preferences now show unsaved feedback but do not add a new navigation confirmation flow.

v0.24.0 authenticated Save/Reload remains Developer-accepted 100%; historical pending entries remain superseded. This increment still needs an authenticated smoke check of new feedback with real Project Save, slow/failed Save and Project switching. Physical phones/tablets, comprehensive touch drawing and Builder-specific upload/PBR/placement verification remain separate. No live database writes, migrations, seeds, push or deployment were performed.

Manual: open a saved Project; wait for restoration; move a camera/card or toggle Simulations; wait up to 750ms for amber Save feedback. Save and confirm it clears. Change another preference while Save is pending and confirm it remains unsaved afterward. Reload and confirm the saved preferences; switch Projects and check isolation. At narrow width, drag a saved card, resize, then Reset Overlay Positions. In Design, resize the divider and check Properties scrolling, rulers and pointer alignment.
