Prepared September 12, 2026. **Production deployment User-confirmed**, package `0.19.16`, released commit `e8cccf3`. User accepted the Assignment + Preview checkpoint. A separate local manual build result was not reported. The handoff below is retained for reference; individual production smoke checks are not inferred from deployment confirmation.

## Included outcome

Users can assign reusable library animations to Character actions or optional Model defaults. Character overrides retain precedence. The Characters row’s **Animations & Preview** opens a wide workspace with a scrolling action list and persistent preview Canvas.

- Textured Character resting pose loads automatically. T-Pose restores the authored bind pose; A-pose assets remain A-pose.
- Preview starts/restarts the selected animation without saving assignments or reloading the Character/camera. Replacements retain the last working animation on error; superseded loads cannot take over.
- Active inherited Model defaults can be previewed without creating a Character override. Disabled and unavailable choices explain their state.
- Front/Three-quarter presets, orbit/zoom and explicit Save view/Reset view. Camera preferences are per Character in this browser, not database or cross-device settings.
- Per-action Save persists assignment IDs, with readback, unsaved-state feedback and failed-draft retention.
- Owner-scoped single-animation metadata GET supports preview. Scene assignment failures name the action, animation ID and Character/actual Model source through existing error handling.

The title encompasses Model assignment; **live preview is currently Character-specific**. Generic Model preview/playback is not implemented. Preview loops a clip on the linked reusable Character Model; it does not simulate one-shot world effects, retarget incompatible rigs or preview a Project-specific replacement Model. Assignment edits take effect in the Scene after reload.
