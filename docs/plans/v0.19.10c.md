Released to production as package `0.19.10-centaur`, commit `a618a66`, confirmed by the User September 9, 2026. See the [completed production handoff](v0.19.10c-release.md) and [release record](../releases/v0.19.10c.md). The build gate remains manual; do not run `npm run build` in this chat.

## Proved gaps and acceptance before implementation

The clean production worktree accepts OBJ primaries in the single-Model API and `.mtl` supportive files in Model Files, but the bulk picker/preparation/runner allow only FBX/GLB/GLTF. The shared companion scanner has a limited OBJ/MTL parser (one mtllib name per line, last whitespace token for images). ModelMarker3D uses OBJLoader without MTLLoader, so saved material files do not affect appearance. Bulk snapshots classify companions only as images or binary buffers.

Affected areas: bounded OBJ/MTL parsing and browser loading helpers, the shared companion scanner, bulk preparation/UI/runner/local preview, ModelMarker3D's OBJ branch, relevant validators and version/documentation. Existing files APIs can persist MTL as `other`; no schema/API extension is required. Single-Model importing retains its staged-primary/create/Model Files lifecycle, with saved OBJ materials rendered through the same loader used by local previews.

Acceptance:

- Mixed FBX/GLB/GLTF/OBJ batches retain exact primary and attachment classifications; MTL is a material library, not an image or thumbnail.
- Discover declared MTL libraries and their texture maps, with quoted/spaced names and bounded relative paths, including parent-relative image paths that remain inside the Model bundle.
- Required missing/ambiguous MTL blocks import. Missing images may be deferred inactive; supplied invalid files cannot be silently deferred. Geometry-only OBJ remains valid.
- Local preview and saved single/bulk OBJ rendering use the same OBJLoader/MTLLoader material contract and canonical slot inventory. Existing Texture assignments replace Base Color only.
- Preview/preflight makes no upload requests; no arbitrary dependency URLs are fetched. Bound file bytes, references, geometry and image work, and release owned preview resources.
- Preserve production FBX/GLB/GLTF behavior, guarded recovery, submitted snapshots and expanded UI. No Character, Physics, MQTT, schema or environment changes.
- Run native importer checks, focused real browser OBJ/MTL rendering and TypeScript. The User owns the build and production verification gates.

OBJ curves/free-form surfaces, unsupported material extensions/maps, ZIP extraction and larger-file bulk transport are outside the initial tested subset. Record the final supported options and validation after implementation.

## Implemented candidate

- Package version is `0.19.10-centaur`. The existing bulk dialog accepts mixed FBX/GLB/GLTF/OBJ primaries and shared MTL/image/binary companions. Expanded fields, saved defaults, highlighted requirements, submitted snapshots, guarded retry and on-demand previews remain intact.
- `model-obj-core.ts` supplies fetch-free OBJ geometry and MTL parsing shared by preparation and dependency auditing. Declared MTL files reveal their image requirements after local reading. Quoted/spaced names, multiple libraries, negative indices and parent-relative images are supported; attachment paths must remain inside the bundle.
- `model-obj-loader.ts` combines OBJLoader and MTLLoader with selected-resource resolution, actual image decoding, bounded work and explicit resource disposal. Local preview and pre-upload inspection share this loader with saved Model rendering. MTL material names and canonical mesh-slot identities survive import; an existing Texture changes Base Color only.
- MTL attachments retain `fileType: 'other'` through upload/readback, while only the explicitly selected thumbnail updates the thumbnail URL. A missing MTL blocks preparation, preflight and saved completion even when missing-image deferral is selected. Known-created Models remain inactive after an incomplete saved audit.
- `ModelMarker3D` changes only its OBJ asset-loading branch and the staged OBJ cache distinction. The single-Model form keeps its geometry preview before creation and explains how to attach MTL/images in Model Files. Model Files now exposes OBJ material inspection and existing Texture assignments. A complete local bundle can also be prepared as a one-row bulk import.
- The shared image-dimension reader was extracted from the existing GLTF inspector without changing GLTF/FBX decoding behavior. No dependencies, API routes, schema, Character ownership or Physics lifecycle changed.

### Supported OBJ/MTL subset and limits

Ordinary vertices, UVs, normals, polygon triangulation, lines/points, groups, smoothing, material assignments and negative primitive indices are supported. Lines/points have no assignable mesh material slots in the existing Texture assignment system. Geometry-only OBJ uses vertex colors/default materials; a declared material library is never silently ignored in saved or bulk loading.

MTL supports material colors, opacity and shininess through Three.js, plus `map_Kd`, `map_Ks`, `map_Ke`, `map_d`, `map_bump`/`bump`, `norm` and `disp`. Supported map options are `-s`, `-o`, `-bm`, `-mm` and `-clamp`. This is the Three.js material interpretation, not a promise of every exporter-specific MTL extension or offline renderer effect. Image files support PNG, JPEG, static WebP and BMP. Unsupported maps/options, TGA references, external dependency URLs and escaping paths fail explicitly.

The existing 100-Model/500-companion selection and 4 MiB-per-file bulk limits remain. Selected material text across the pool is limited to 32 MiB. The shared OBJ loader permits 32 MiB of source bundle bytes and 32 MiB of decoded geometry, up to 500 material names/maps, 4,096 object/group declarations, 16 Mi pixels per image and 32 Mi pixels in total, with a 30-second load deadline. These loader limits also apply to saved single Models. Curves/free-form surfaces, ZIP extraction and larger-file bulk transport remain outside this candidate.

## Retained live regression checklist

1. Import a representative OBJ with multiple materials, MTL libraries and texture images. Confirm discovery, appearance, UVs, scale/rotation/offsets and both preview placements. Repeat with a mixed FBX/GLB/GLTF/OBJ batch.
2. Leave existing Texture at None to preserve MTL appearance, then assign an existing Texture and confirm only Base Color changes, both before and after reopening the saved Model.
3. Remove a required MTL and confirm import is blocked. Defer a missing image and confirm the saved Model stays inactive; attach the image later in Model Files and recheck appearance/dependencies.
4. Use Add Model for one OBJ: confirm geometry preview before creation, then attach MTL/images in Model Files and verify material slots and Texture assignment. Confirm a geometry-only OBJ needs no invented material dependency.
5. Place the saved OBJ in a Project; verify appearance, grounding, transforms and fixed collisions alongside existing Models and Characters. Confirm ordinary Character movement/actions and Canvas/Physics persistence remain unaffected.
6. Complete the User-owned build/Vercel gate and report the deployed commit before updating the production boundary.
