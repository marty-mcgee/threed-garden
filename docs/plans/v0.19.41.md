# v0.19.41 — ThreeD Models: Collision Modes + DetailsCard Blueprint

Status: Released to production; deployment User-confirmed on September 20, 2026. Package `0.19.41`. No schema change was required.

## Goal

Allow a User to select an appropriate collision mode for each Model placed in a ThreeD Project. Ordinary Models retain fast box collision by default. A User may explicitly request accurate surface collision for a fixed Model such as a Farm House, allowing Characters and movable objects to interact with its exterior, entrances and other supported geometry more accurately.

The setting belongs to the Project Model instance rather than the reusable Model source. Two placements of the same reusable Model may therefore use different collision modes without changing one another or every Project that uses the source asset.

## Prove — current behavior

- `ProjectModelMarkerBody` in `src/components/map/ThreeDScene.tsx` gives every ordinary fixed Model one measured `CuboidCollider`. Movable balls receive `BallCollider` instead.
- Environment Models are the only current path that asks `ModelMarker3D` for a geometry audit. Eligible small static assets receive `TrimeshCollider`; large eligible assets use the released proximity-based triangle-region system; rejected or incomplete surface coverage retains bounded box fallback.
- `ModelInstancePlacementEditor` already saves instance name, transform, Environment role and ball physics from the Model DetailsCard. It does not expose collision mode.
- `parseUpdateProjectModelInstance` validates Model-instance updates. The PATCH route merges accepted metadata into the owner-scoped `project_threed_markers` row and returns the updated marker for a local client transaction; a Project reload is not required.
- `project_threed_markers.metadata` can store the instance preference, so this feature does not require a new column or migration. Collision selection should still receive its own strict parser instead of relying on arbitrary metadata input.
- Existing surface extraction rejects skinned, empty, malformed, degenerate and over-budget geometry. A requested mode is therefore not proof of the effective runtime collider.

## Collision contract

Persist an allowlisted Project-instance preference with two User-facing choices:

| DetailsCard choice | Persisted request | Runtime behavior |
| --- | --- | --- |
| Box (default) | `box` | One measured fixed cuboid for an ordinary Model. Lowest preparation and memory cost. |
| Triangle Surface | `triangle-surface` | Attempt bounded static triangle extraction. Use the exact supported mesh surface when ready; otherwise keep the box fallback and report why. |

Compatibility rules:

- Existing ordinary Models with no saved value resolve to `box`, preserving current behavior.
- Existing Environment Models with no saved value retain the v0.19.29 automatic surface/region/fallback behavior. Their released proximity collision must not silently revert to one enclosing box.
- Environment Models may use the same DetailsCard control, but `Triangle Surface` means the established surface policy: full trimesh when within the full-surface budget and proximity regions when a supported large asset requires them. The effective runtime label may therefore be `triangle-surface`, `triangle-regions`, or `box-fallback`.
- Movable Ball physics owns a sphere collider. The collision selector is disabled while Movable Ball is enabled, and the saved surface request must not create a trimesh on a dynamic body.
- Triangle collision remains fixed/static. This version does not add concave dynamic trimeshes, convex decomposition, mesh editing or automatic collision-shape generation.

The UI must distinguish **Requested collision** from **Effective collision**. Saving Triangle Surface promises an attempt under supported limits; it must not display success when runtime geometry fell back to a box.

## Development stages

### 1. Contract and persistence

Add a shared `ProjectModelCollisionMode` resolver/parser to the existing Model-instance contract. Accept only `box` and `triangle-surface`; reject unknown values at the API boundary. Save the preference into the existing marker metadata while preserving placement role, ball physics and unrelated metadata. Include the requested mode in local marker reconciliation and Project Save/restore.

Acceptance:

- Existing ordinary instances resolve to Box without a data migration.
- Existing Environment instances preserve automatic surface behavior when the field is absent.
- Owner scoping and current PATCH transaction behavior remain unchanged.
- Invalid modes return a bounded 400 response and never mutate the marker.

### 2. Runtime collider selection

Generalize the existing geometry-audit request so a fixed ordinary Model can request bounded surface extraction without being classified as an Environment Map. Keep Environment collision preview/region preparation separate from ordinary Model collision; an ordinary Farm House within the full-surface budget needs a fixed `TrimeshCollider`, not the full Environment box-planning pipeline.

Mount exactly one effective collision strategy per phase:

- Box request: measured `CuboidCollider`.
- Triangle request, eligible and ready: `TrimeshCollider`.
- Triangle request, loading or rejected: measured box fallback.
- Environment surface request above the full-surface budget: existing proximity regions plus their guarded fallback.
- Movable Ball: existing `BallCollider` only.

Recompute safely when Model source, scale, rotation, Layer state, placement role or requested mode changes. Preserve the persistent Canvas/Rapier world, stable marker identity, fixed-body synchronization, Layer suspension, Model placement and unrelated runtime state.

### 3. DetailsCard UI/UX

Add a compact **Collision Mode** selector inside the existing Project Model Instance editor. Place it near Environment/Movable Ball physics because those choices affect eligibility. Use plain options and short supporting text:

- **Box** — faster; broad rectangular contact.
- **Triangle Surface** — more accurate; higher preparation and memory cost; static Models only.

The field participates in existing dirty state, Save Placement, failure retention and saved-state reconciliation. Disable it with a clear accessible reason for Movable Ball. Do not add always-visible diagnostic paragraphs; put detailed eligibility/fallback guidance in a disclosure or tooltip.

Expose the effective mode when runtime evidence is available, ideally in the existing Physics Debug/DetailsCard diagnostic path. At minimum, Physics Debug must report marker ID, requested mode, effective mode, triangle count and rejection reason. The UI must not claim that triangle collision is active merely because it was requested.

### 4. Validation and live acceptance

Extend the existing Runtime Marker/Model placement validation and add a focused collider-selection fixture using native Rapier where practical. Verify:

- default/legacy Box behavior;
- valid static house surface contact, including an opening or concavity that a bounding box would incorrectly block;
- rejected/skinned/over-budget fallback with a reason;
- Box ↔ Triangle save, immediate local update and reload persistence;
- transform/scale correctness;
- one active strategy without duplicate box and triangle contact after readiness;
- Movable Ball incompatibility;
- Environment full-surface, proximity-region and fallback regression paths;
- Layer hide/show and Physics Debug accuracy;
- Character Take/Release Control, walking, Project Save/restore and movable-ball behavior remain intact.

Run targeted collision fixtures, Runtime Marker, hidden-collision-mount, Project session, Character orchestration, TypeScript and diff checks. The User retains the build and deployment gates.

## Performance and safety boundaries

- Box remains the ordinary Model default and the failure fallback.
- Reuse the established surface triangle/vertex limits; do not raise memory budgets as part of this UI feature.
- Do not build triangle buffers for Box Models.
- Do not attach concave trimeshes to dynamic balls or merge GardenCharacter and EcctrlCharacter collision ownership.
- Changing a Project instance must not mutate the reusable Model record or other placements.
- Surface preparation must not remount the Canvas, physics world or unrelated markers.
- No schema, environment configuration, MQTT, FarmBot command or physical-device change is included.

## Release criteria

The version is ready only after the Farm House demonstrates a useful collision improvement over Box in the browser, the effective/fallback mode is truthful, resource use remains bounded, saved selection survives reload, and the existing Demo Farm/Soccer collision regressions remain acceptable.

## Implementation record

Completed September 20, 2026:

- Project Model instances now persist an allowlisted `collisionMode` in existing marker metadata through the owner-scoped PATCH route. Invalid top-level or nested metadata values fail validation.
- The Model DetailsCard provides **Box** and **Triangle Surface** choices through the existing Save Model workflow. The selector participates in dirty state and is disabled while Movable Ball physics owns the collider.
- Ordinary Models retain Box by default. Older Environment records retain the released surface/region policy when no explicit value exists.
- Fixed ordinary Models may now request the existing bounded triangle extraction path. Unsupported or over-budget geometry uses a measured box fallback; Environment Models retain their proximity-region fallback path.
- Runtime strategy resolution keeps movable balls, measured boxes, full triangle surfaces and Environment triangle regions mutually exclusive. Physics Debug reports requested and effective modes, fallback state and active surface triangle count.
- Surface preparation resets when its eligibility changes without remounting the Canvas, Rapier world or unrelated Runtime Markers.
- Project-load readiness now distinguishes a loaded Model file from a ready stationary collider. Characters and movable balls remain outside the Rapier world until Box bounds, a Triangle Surface, or an Environment fallback/region strategy is available, preventing gravity from moving actors through a still-preparing deck or structure.
- DetailsCards now share one compact, stateful foldable-section primitive across common metadata and the Character, Model, Bed, FarmBot and Planting instance workspaces. Primary Save/Move/Delete actions remain visible while secondary forms and diagnostics can be collapsed consistently.
- The Model editor now presents **Scene Role** separately from one consolidated **Physics Mode** selector: Fixed Box, Fixed Triangle Surface, or Movable Ball. The UI maps those choices back to the compatible `placementRole`, `physicsMode`, `collisionMode`, and `ballPhysics` metadata fields, so existing Projects require no migration.
- DetailsCard primary actions use concise module names such as **Save Model**, **Save Bed**, **Save FarmBot** and **Save Planting**. The shared surface uses `#121B2A` as its base tint while retaining the established 50% resting and 82% hover/focus opacity behavior.
- A pre-release Planting deletion regression was corrected: deleting a Project Planting now removes its Runtime Marker and Project assignment while archiving the source row. Historical watering records remain intact and can no longer block the Project deletion after its assigned Bed has been removed.
