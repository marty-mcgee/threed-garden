### Generator coverage and dimensions

At defaults, the TypeScript Cottage has **253 meshes, 10,990 triangles, 11 materials and 18 unique PBR images**. The source reference had 10,942 triangles. The port splits affected decorative rafters around real skylight openings, adding 48 triangles while retaining the 253 named mesh groups.

All physical parameters remain inches; door defaults are 80 × 36. The generator multiplies positions by `0.0254 * overall_scale` once, emits metres with +Y up/front −Z and retains independent overall scale. Validation rejects nonfinite/out-of-range/unknown input, invalid wall/door/window/roof/hall fits, overlapping rear window/door frames and side passages outside enclosed wings before allocations.

Every generation owns its mesh arrays, geometries, materials and textures. Stable named parts/materials, finite flat normals/UV/color attributes, bounds and statistics are returned through `GeneratedModelBundle`; `dispose()` releases owned resources idempotently. No React, DOM, auth, storage, database or process-global mutable mesh list enters geometry/pixel generation.

The provisional interior includes main/wing finished floors, lining with matching openings, vaulted ceilings with skylight apertures, rear hallway/two room zones, open internal doorways and baseboards/trim. It is an editable draft shell without cellar, stairs, furnishings, movable doors or construction certification. Transparent glazed doors/windows remain geometry; transparency does not certify physical passability. Default Model box collision blocks interior access; opt-in stationary triangle-surface collision and actual capsule clearance require Project acceptance.

## 4. Materials, export and presentation

Pixels use fixed `mulberry32-v1` with seed 1117 by default. Texture resolution is 64/128/256, default 128. Slate, fieldstone, siding, timber, paving and oak-floor images reproduce the reference style with bounded TS algorithms rather than NumPy/Pillow byte identity. Height-derived tangent normals and packed ORM share raw RGBA artifacts. Base color/emissive use sRGB; normal/ORM use linear data; ORM packs R occlusion, G roughness, B metallic. Bounded non-directional vertex shading adds contact darkening without baking Project sunlight.

ThreeD Model Textures owns reusable generated images. The existing subsystem now supports `baseColor`, `normalMap`, `roughness`, `metallic`, `occlusion`, `emissive`; Cottage uses five of these. Relational assignments win over legacy overrides only for the same target and channel. Runtime clones preserve authored material factors, normal scale/AO strength, transparency, glass side flags and vertex colors. Replacement textures inherit UV channel, repeat/offset/rotation, wrapping/filtering/orientation and the appropriate color/data space. Shared ORM bytes are reused across three role bindings.

The Builder encodes its generated images for explicit Texture creation when saving. Duplicate image hashes are deduplicated **within the current generation/registration**. Owner-wide byte deduplication across generated Models remains future work; owner + URL uniqueness is not content deduplication. Arbitrary embedded-image extraction from imported GLBs and a reusable Material entity were not implemented. Embedded images are never represented as invented standalone Texture URLs.

The browser exports complete geometry with `onlyVisible:false`, regardless of preview visibility, embeds PNG images and performs structural bundle inspection before existing GLTFLoader/material inventory checking. No external dependencies, lights or cameras are intentionally added. Three's tangentless normal convention uses `normalScale=(0.7,-0.7)`, matching GLTFLoader and preventing exporter-side raw normal-image conversion. Material snapshots include scalar factors, texture IDs and sampling/color-space metadata.

## 5. Upload budgets and provider lifecycle

The old inspection reported a 4 MiB bulk primary gate, exceeded by the 4,400,840-byte Python GLB. That was a historical transport constraint, not the intended product-wide Model policy. The implemented shared direct-primary policy now permits 32 MiB; bulk GLB/glTF primary inspection uses 32 MiB with retained combined/decoded/image/resource/time bounds. Bulk FBX/OBJ and companion files retain separate 4 MiB gates. The direct primary helper supports its format allowlist independently of those bulk decoders.

Current direct flow: select/preflight → authorize new owned key → direct browser-to-Blob transfer with progress/Stop → verify provider key/type/size and bounded actual downloaded bytes/structure → use existing Model/File registration. Binary transfer bypasses the Function request body; completion still downloads up to 32 MiB from Blob and allocates bounded byte buffers for server inspection. This is not zero server byte processing or a measured production capacity claim. Registration and activation remain separate. Failed verification uses existing guarded staged-file cleanup and preserves previous draft/candidate state; unconfirmed cleanup remains visible.

The signed upload authorization binds owner, destination, filename/type/size and expiry; it contains no storage credential. Completion reads only the provider-verified URL and rejects redirects, wrong key/type/size, truncation/oversize and structurally invalid GLB/glTF bytes. Browser-supplied URLs/inventory do not establish valid provider bytes. Synthetic tier timings are inspection measurements, not production transfer/download or complex-model benchmarks.

S3 remains later work. Existing Multimedia signed-PUT/HEAD patterns are references; ThreeD's file reads, requirements/recovery, ownership, stable URLs, CORS and deletion/cleanup must become provider-aware together. Do not persist expiring signed GET URLs as primary authority or route GLBs through the private Multimedia endpoint. Larger tiers, durable jobs/server export and headless capture require their own measured design and authorization. No live Blob/S3 settings, credentials or resources were inspected or changed.

## 6. Manifest, registration and Project behavior

`ModelGenerationManifest` in `src/libraries/services/threed/model-builder/types.ts` is the implemented local v1 contract. It is not a database table or the strict Model import manifest v1. Its fields are:

- `generator`: ID `threed-cottage-ts`, version `0.24.0-alpha.1`, RNG/seed, inch/metre units and draft flag.
- `parameters`: complete validated snake_case inputs; canonical serialization supplies input SHA-256.
- `geometry` and `bounds`: named mesh/vertex/triangle/image-pixel statistics and metre min/max/size.
- `artifacts`: encoded GLB/PNG paths, MIME, byte size and actual SHA-256.
- `materials`: IDs/names, base-color/roughness/metalness/opacity/double-sided/normal-scale/AO factors, image-role bindings and UV/repeat/offset/rotation/wrap/orientation/color-space sampling snapshots.

The downloaded manifest adds input hash and confirmed registration `modelId`, `primaryModelFileId`, Texture digest-to-ID mappings and completion. It does not fabricate assignment row IDs, revision pins or signed generation certification. Safe `metadata.modelBuilder` persists generator/parameters/input-output hashes/material recipes; local reference/source paths and private URLs are excluded. Blob objects are public, and arbitrary Model metadata is not a private source archive.

Builder registration explicitly creates `modelType='glb'`, `metadata.activeSource='model'`, source scale 1/zero rotation-offsets, `isPublic=false`, `isActive=false`, `status='pending'`. The existing API creates and assigns the primary File in the same owner transaction; confirmed Model and `mainModelFileId` are required before Texture work. It then materializes image bytes through Model Textures and applies bounded target/channel batches. An optional captured thumbnail URL is included in new Model creation; the existing capture action stages that image separately and retains the returned URL in the local draft until save.

Registration retains confirmed upload/Model/primary/Texture/assignment progress. Resume retries only incomplete work, preserves one ORM record across role bindings and rejects changed generation hashes or concurrent saves. Stop does not erase confirmed rows. An unknown create POST result blocks replay and directs Model/Texture review; an interrupted assignment can be retried through the existing idempotent assignment path. This is sequential recoverable registration, not an atomic multi-artifact transaction or durable job journal. Reloading/closing the Builder loses its local Resume state; partial saved records remain available for review.

Before replacing a local generation, known unregistered primary bytes are discarded through the guarded existing DELETE endpoint. Unconfirmed cleanup retains the preview, blocks Save and allows cleanup retry; potentially deleted URLs are never reused. Idle unmount attempts keepalive cleanup, while pending/associated/uncertain writes retain their bytes. Unload cleanup and provider multipart-abort cleanup remain best-effort. Optional staged thumbnails lack an existing guarded discard endpoint and can remain orphaned when abandoned; thumbnail lifecycle cleanup is a follow-up. Completed registration reflects acknowledged writes, not an additional database readback or automatic activation.

Each regenerated saved asset gets a new Model identity and immutable upload key. Existing Models, primary pointers and Project markers remain untouched. After review, activation and new Project adoption/placement are explicit. Current Project reads overlay current authorized primary/assignments; changing an existing primary can affect future reads, without realtime invalidation or a historical asset pin. Current marker PATCH cannot retarget source Model identity. Same-Model candidates, conflict-safe promotion/rollback, source retargeting and revision pinning remain separate future work requiring API/schema review where applicable. The legacy deterministic-path/upsert CLI was not run or changed into a revision store.

## 7. Admin workspace and offline CLI

Route `/admin/threed/models/builder` is linked from Admin Models. It retains Blueprint/shadcn conventions and the existing Model preview/material inspector/capture paths. Parameters and draft names are guarded while generation/save/capture is busy; changed parameters gate download/save until regenerated. Failed/stopped generation retains the previous valid preview, and replacement disposes old owned resources/object URLs. Rebuilt output resets capture state. Before-unload/link/Back guards preserve local drafts and block busy navigation; confirmed navigation releases the guard. No Preview operation registers Scene mixers/positions, changes physics/world state or writes Project data.

```powershell
node --import tsx src/libraries/scripts/build-threed-cottage.ts --input dimensions.json --output ./cottage-output
```

The local CLI accepts optional input JSON (defaults if omitted) and a required new/empty output directory. It writes `geometry.json`, unencoded `textures/*.rgba` and a deterministic `generation-report.json` with SHA-256 and material/image descriptions. It refuses artifact replacement. These are offline inspection outputs, not a GLB/PNG export adapter. The browser creates portable textured GLB and captured PNGs. Shared modules are `types.ts`, `parameters.ts`, `cottage.ts`, `materials.ts`, `export.ts`, `registration.ts` under `src/libraries/services/threed/model-builder/`.
