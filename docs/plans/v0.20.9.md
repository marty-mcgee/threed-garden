# v0.20.9 — ThreeD Front-End: Scene UX + Model Reliability

Production-ready checkpoint, package `0.20.9`. On September 24, 2026, the User confirmed all remaining manual gates, including browser acceptance, Barn placement, panel/view restoration and the manual production build. Commit and production deployment remain pending. See the [release handoff](v0.20.9-release.md).

## Proven problems and acceptance criteria

- `BedMarker3D.tsx` preferred soil-type colors over the explicit Bed color. An explicit color must win; soil-type and default colors remain fallbacks.
- `ThreeDScene.tsx` limited OrbitControls to 200 units, below the distance needed for large Ground Maps. Zoom must extend far enough to view the map, with a matching far clipping plane and saved-distance acceptance.
- `dashboard/scene/page.tsx` hid and disabled all Library panels while the Project title menu was open. Assets already had independent visibility and save capture. Library panels must remain visible beneath the menu; saving must retain the open Assets or Model Library workspace.
- `AppHeader.tsx` rendered its account menu only for Admin, with initials rather than a Gravatar. Both surfaces must expose the account avatar, login status and appropriate sign-in/sign-out action.

## Implementation

Bed rendering now gives `bed.color` precedence. Geometry, frame materials and physics are unchanged.

Scene orbit distance is at least 5,000 units and scales to four times the Ground Map diagonal for larger maps. The far plane is four times that limit, and saved camera distance acceptance uses the same orbit limit. Existing marker bounds, target compatibility and Character camera modes remain in place.

Library wrappers no longer hide or become inert when the title menu opens. The existing saved workspace JSON contract now accepts `panel: 'models'`; Model Library restoration uses its existing loader. Legacy `none`, `summary` and `assets` values remain supported. The workspace retains the existing mutually exclusive Assets/Library opening behavior. Model filters, placement operations, and Character/FarmBot Library visibility are not newly persisted.

The shared Dashboard/Admin account menu shows a Gravatar, initials fallback, login status indicator and status text inside the menu. Gravatar uses the authenticated session email with [Gravatar's documented normalized SHA-256 identifier](https://docs.gravatar.com/rest/hash/). Failed image requests or unavailable browser hashing retain initials; stale asynchronous results are discarded. No new dependencies or database schema changes.

## Follow-up — Model Library database disconnect

The User reported Model 61 (`SM Bld Barn 03`) failing to load material assignments with a nested `Connection terminated unexpectedly`, followed by a generic placement POST failure. The exact POST failure stage is unknown. The database connection implementation predates v0.20.9; the log does not establish when the intermittent failure began.

A SELECT-only connection probe failed once with IPv4 timeouts/IPv6 unreachable errors, then succeeded twice. A subsequent SELECT-only check found Model 61 and all seven joined material assignments. This confirms current record availability, not full placement success or the cause of every failed request. No database writes or schema changes were performed during diagnosis.

The existing `retryDisconnectedRead` helper was unused by the Models API and Model placement prechecks. Acceptance: a recognized transient disconnect during Model reads recovers once, texture assignments remain intact, repeated failures and schema errors still fail, and the placement transaction is never automatically replayed.

Changes:

- `src/app/api/threed/models/route.ts`: bounded retry around Model GET reads after authentication; replace raw query/error logging with safe error metadata.
- `src/app/api/project/threed-markers/route.ts`: bounded retries for Model placement's Project ownership, active assignment and eligibility reads. Creation transaction remains single-attempt. Include nested safe connection diagnostics on failure.
- `src/libraries/db/connection-diagnostics.ts`: identify wrapped disconnects even when pg supplies no error code; continue omitting messages, SQL and connection details.
- `src/libraries/scripts/validate-threed-database-failures.cjs`: execute the real Model GET against a material-assignment disconnect, successful retry, repeated disconnect, missing relation and missing Model. Verify code-less disconnect diagnostics.

Validation: TypeScript, `threed-database-failures`, `threed-library-placement`, and diff checks passed. The regression confirms recovered texture assignments and bounded failures. The User subsequently confirmed successful Barn placement as part of the remaining manual gates. Network interruptions during the write transaction can still fail; no automatic write retries were added.
