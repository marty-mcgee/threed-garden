# v0.19.13 — ThreeD Admin Sub-Module Workspace UI/UX Updates

Status: **released to production** as commit `c976c77`; deployment and manual build are User-confirmed. See [release record](../releases/v0.19.13.md). The implementation notes below retain their original local validation context. Remaining work is tracked in the [continuation record](admin-threed-workspace-continuation.md).

## Objective

Apply the released [Admin ThreeD Models workspace blueprint](admin-threed-workspace-blueprint.md) to other Admin ThreeD sub-module pages, preserving each module's fields, relationships, access rules and behavior.

The common experience is a compact workspace header with actions and search, total/range counts, pagination and page-local bulk selection where supported. Records scroll independently beneath stationary controls and column headings. Use consistent status colors, Active check/X indicators, compact buttons, accessible icon labels and responsive wrapping. Server-side search/sort must precede pagination for paginated datasets; do not merely sort the loaded page.

## Implementation sequence

| Stage | Pages | Required review before edits |
|---|---|---|
| 1 | Model Categories, Model Textures, Model Files; assess Model Animations | Hierarchies versus flat records, shared-file ownership/deletion, file requirements and previews, animation-specific controls |
| 2 | Plants, Beds, Plantings | Reusable definitions versus Project instances, references, quantity/units and deletion constraints |
| 3 | Characters, Layers, FarmBots | Character runtime separation, persistent Scene/Layer ownership and integration safety |
| 4 | Waterings, Harvests | Authenticated Project scope, history and scheduling semantics |

Start with Model Categories as the first bounded implementation. For each page, inspect the route, CRUD component, API, schema and any embedded Project-admin consumers; record the current problem, appropriate columns/actions and acceptance criteria. Implement and validate that page before broadening the change. Reuse existing workspace components where their contracts fit. Extract additional shared components only after a second implementation demonstrates the need; keep restructuring separate from behavior changes.

Do not force Model-specific upload, file-management or deletion controls onto unrelated modules. Enable viewport constraints only for reviewed standalone pages; preserve embedded hosts. Existing module functionality must remain available.

## Acceptance per page

- Headers, pagination and navigation remain usable while long records panels scroll; verify narrow/short windows, horizontal scrolling, sidebar collapse and dialogs.
- Search and sorting cover the authorized dataset, with deterministic ties and correct totals; test older records beyond page one, page sizes, nulls and empty results.
- Rapid request changes cannot restore stale rows. Mutations refresh counts and recover an empty final page.
- Bulk selection is explicitly page-local, resets on query changes and preserves existing deletion confirmations/restrictions. Do not introduce unsupported destructive operations.
- Keyboard focus, icon labels, status text and active indicators remain understandable without relying only on color.
- No regressions to Model importing, shared Texture reuse, primary-file authority, Character animation/control, DetailsCard or persistent Scene physics.

## Boundaries

No schema changes, old-data migration, storage relocation, new physical-device behavior or MQTT capability is included. Character animation tasks are separate from the unused Tasks sub-module and must remain intact. Tasks/Analytics are excluded; Registration and Settings remain deferred. This version does not silently expand their scope.

## Model list timeout — query batching and selector projection

**Proved:** the User reported `ETIMEDOUT` during a Model Files query inside a paginated Model GET. The list handler executed one file query and one material-assignment query per Model, in addition to count, list and category queries: 103 database calls for 50 Models, or 403 for 200. The new header selector traversed catalog pages using this full response. The log establishes a connection timeout; it does not independently prove query volume was its sole cause.

**Implemented:** list enrichment now loads all files and material assignments for the authorized page IDs in batches, grouping by Model ID and preserving the response shape, category associations, shared Texture URLs and primary-file authority. Nonempty pages use five sequential database calls regardless of page size; empty pages use two. `view=selector` returns only ID, Model name and format with the existing filters/authorization and pagination, using two calls and alphabetical ordering. Model Files uses that projection and aborts superseded catalog fetches or remaining pages when unmounted. Its original customization layout remains unchanged.

**Validation:** TypeScript, `validate:threed-model-list` and the new `validate:threed-model-list-api` passed; the new gate is registered in package scripts and CI. The API fixture transpiles the actual GET handler and supplies a database double, proving constant query counts for 1/50/200 rows, per-Model grouping, single-detail assignment compatibility, selector pagination/projection, owner predicates, and empty/invalid/unauthenticated responses without a live connection. It does not prove live SQL execution or network availability. Diff checks passed. No schema changes, pool configuration, database writes or build ran; earlier workspace changes are preserved.

**Manual follow-up:** navigate repeatedly between paginated Models and Model Files, choose Models beyond the first catalog page and verify attachments/materials. If timeouts continue, collect the underlying connection error separately; this change reduces query load but cannot repair an unavailable database/network.

## Project map connection timeout and incomplete responses

**Proved:** the User reported a batched Plantings read failing with `ETIMEDOUT` while the Project map GET returned 200. Both `fetchItems` and `processAssets` swallowed query failures into empty collections. Separately, the shared database module created a fresh pool on each module evaluation with no development reload cache. These are concrete resilience problems; the underlying network timeout has not been reproduced against the live database.

**Implemented:** `src/lib/db/client.ts` caches its pool on `globalThis` only in development, attaches Vercel lifecycle handling once at creation, and handles idle-client errors with code-only logging. Production keeps module-level pooling and existing driver/configuration. The map route propagates failed asset reads to its existing 500 error response instead of publishing an incomplete successful snapshot. Genuine empty reads still succeed. No retry of database writes, connection-string changes, schema changes or Scene runtime changes were introduced.

**Validation:** TypeScript, the existing Project session validator and new `validate:threed-database-failures` passed. The new offline validator executes the real modules with controlled doubles: development re-evaluations share one attached pool, production does not reuse that development pool, failed Plantings reads return 500, and valid empty results return 200. Registered in package scripts and CI. No live connection or build ran.

**Manual follow-up:** restart the development server once to discard pools created by the previous module, then reload Project #5 and repeat navigation. Verify Plantings appear and connection errors stop. If timeouts persist, investigate connectivity separately; pool reuse and accurate error responses do not establish live network availability. Pool lifecycle guidance: [node-postgres pooling](https://node-postgres.com/features/pooling) and [Vercel pooling](https://vercel.com/kb/guide/connection-pooling-with-functions).

## Rollout paused — Character position persistence

The User reported Character Save Position not working and requested that Project Save include Character position automatically. Inspection found that the editor compared inputs to its live display position and disabled Save when unchanged, incorrectly labeling that state Saved. The runtime registry also intentionally preserves live overrides across asset refreshes, but the successful Character PATCH handler did not replace its old movement override. A subsequent Project snapshot could therefore use pre-edit coordinates. These paths predate the current Admin rollout; no evidence establishes that the recent Admin changes introduced them.

The editor now permits explicit saving of valid displayed coordinates after Release Control and uses Ready to save instead of claiming persistence. Successful Character position PATCH responses update only that Character's registry entry with the server-returned XYZ, alongside the existing targeted client transaction. Failed requests leave live authority untouched. Project Save already captures current registry positions; its existing automatic Character capture was verified without adding separate PATCH calls or writes during movement. Runtime routing, animations, controls and physics remain unchanged.

Validation: TypeScript, the Runtime Marker suite (49 groups plus existing response regressions), and `validate:threed-character-position-save` passed. The new offline fixture executes the actual position-save callback, snapshot provider and Project-save callback with controlled dependencies; it covers failed edits, successful edits and new movement captured directly by Project PUT. Registered in CI. No build or live writes ran. Manual gate: Take Control, walk, Release Control, Save Position, then refresh; edit XYZ and Save Position then Save Project and refresh; walk and Save Project directly while controlled, then refresh. ## Character idle restart after save/reset

**Proved:** a real-Three.js regression fixture executing the actual Ecctrl `playAnimation` callback failed when a replacement mixer had a new idle action with the same clip name as the old action. The name-only early return left the replacement model in its bind/T-pose. Model replacement can occur on a Character save because the loader responds to Character data changes.

**Implemented:** skip only the identical, currently running action unless a forced restart is requested. Crossfade only between different actions belonging to the current mixer. The existing model-ready idle effect now starts the replacement model's animation; no task/world action is automatically replayed. Semantic task locks, locomotion mapping, saved transform handling and separate Garden runtime are preserved.

**Validation:** new `validate:threed-character-animation-restart` failed before the fix and passed afterward using real Three.js mixers. It checks replacement idle startup, stopped-action restart, stable running idle, force and task-lock behavior. TypeScript, Character position/orientation saving checks and diff checks passed; the new gate is registered in CI. No build or live writes ran. Manual gate: save/reset/reload the Character, confirm immediate idle instead of T-pose, then exercise WALK/RUN and one-shot actions returning to locomotion. Screenshot Blob 404s were not diagnosed by this animation fix; full failing paths are needed to trace those separately.
