# v0.20.1 FarmBotJS dependency decision

Decision: **keep the existing server-side MQTT.js adapter**. Do not add FarmBotJS in v0.20.1.

## Proof

FarmBot documents MQTT as its preferred connection for server applications. Its status topic carries the current state tree, including X/Y/Z coordinates. The repository already uses that server pattern and already owns authentication, bounded subscriptions, reconnect behavior, normalized persistence, Project assignment checks, and secret isolation.

FarmBotJS wraps authentication, MQTT, CeleryScript RPC correlation, and browser-oriented events. FarmBot’s documentation says Node use is community-reported but is not tested or used by FarmBot in production. The capability that v0.20.1 needs is read-only server observation, which the current adapter already supplies.

| Capability | Existing MQTT.js worker | FarmBotJS impact |
| --- | --- | --- |
| Server MQTT status subscription | Implemented and validated | Duplicates current ownership |
| Owner/Project authorization | Implemented in App routes | Still required outside the library |
| State normalization and persistence | Implemented and validated | Still application-specific |
| Reconnect and worker lifecycle | Implemented | Would require replacement and regression work |
| RPC correlation | Existing dormant command pipeline | Useful only for a separately approved command stage |
| Node production support | Current dependency is used server-side | FarmBot does not claim production Node support |
| Browser credentials | Excluded by current design | Browser use would conflict with the server-only credential boundary |

## Resolution

- Keep `mqtt` as the provider-neutral transport dependency.
- Keep FarmBot parsing beneath the integration boundary; the generic MQTT service must not import it.
- Add no second connection manager, token owner, or client-side FarmBot session.
- Reconsider FarmBotJS only through a separate dependency proposal tied to a capability the current server adapter cannot provide.
- Physical commands remain disabled and outside the v0.20.1 release boundary.
